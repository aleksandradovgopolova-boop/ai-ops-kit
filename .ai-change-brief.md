# Change Brief — Review Fixes 2026-08-06

Источник: внешнее ревью v3.28.0 (живой прогон кита на чистом репозитории + аудит кода).

## Результат

Пользователь, поставивший кит в свой репозиторий, с первого прогона получает **реальные правки
кода**, а не `провайдер: mock · правок 0`. Отчёт прогона не врёт про распознанный стек.
Инсталлятор покрыт тестами. Слой валидаторов проверяется внешними тестами, а не только
самоаттестацией.

## Затрагиваемые пути

1. `run --execute` → резолв провайдера → orchestrator → tool-loop → правки (P0-1)
2. `run` → сборка отчёта → печать `стек:` (P1-3)
3. `onboard` → `repository-profile.yaml` → потребители профиля (P1-4)
4. `project_detector.detect` → вывод команд → `not_applicable` гейтов (P1-5)
5. `installer init` → состав поставки в child-репозиторий (P0-2, P2-7)
6. pre-commit чеклист (206 команд) → CI → `validate_release_claims.checks_count` (P2-9)
7. `make_provider` → имена провайдеров из `registry/providers.yaml` (qwen/deepseek/kimi)

## Инварианты

- **Fail-closed сохраняется.** Ни одна правка не превращает незакрытый гейт в зелёный результат.
  `run` с незакрытым гейтом обязан возвращать exit≠0 (сейчас 2).
- **Честность деклараций.** Резолв провайдера, если скатился в `mock`, говорит об этом прямо
  до прогона, а не постфактум нулём правок.
- **Registry — источник истины.** Имена провайдеров в коде не расходятся с `registry/providers.yaml`.
- **Секреты только из env.** Ни ключей, ни base_url с секретами в репозитории и логах.
- **Никаких новых зависимостей** — stdlib + pyyaml.
- **`mock` остаётся дефолтом для CI/selftest** — офлайн-детерминизм не ломается.

## Failure modes (≤5)

1. Автовыбор провайдера уводит CI/selftest с `mock` на живой вызов → недетерминизм и трата денег.
2. Резолв провайдера маскирует отсутствие ключа и падает уже внутри tool-loop невнятной ошибкой.
3. Кеш профиля протухает → `run` работает по устаревшему стеку после изменения манифестов.
4. Усиленный вывод команд выдумывает несуществующую команду → гейт «проходит» вхолостую.
5. Разделение поставки выкидывает файл, который нужен движку в child-репозитории → `doctor` красный.

## Доказательство

Три обязательных теста на каждую capability:

- **positive** — с `claude` в PATH `run --execute` выбирает claude-cli и производит непустой diff;
  `onboard` в python-репо → `run` печатает `стек: python`.
- **fail-closed** — без ключей и без CLI резолв даёт `mock` + явное предупреждение, exit≠0
  при незакрытом гейте; выдуманная команда не засчитывается как пройденный гейт.
- **side-effect proof** — доказать, что файл РЕАЛЬНО изменён (diff непуст, HEAD сменился),
  ПРЕЖДЕ чем проверять реакцию гейта; для инсталлятора — файл реально записан на диск.

Плюс: `python3 -m pytest tests/ -q` зелёный (baseline 732), полный pre-commit чеклист PASS,
живой прогон в чистом репозитории повторно.

## Не входит

- Смена архитектуры гейтов/агентов/registry.
- Новые продуктовые возможности.
- Перенос файлов между пакетами (3.0-срез 0 не трогаем).
- Публикация/пуш — только локальная ветка `engops/review-fixes-2026-08-06`.
