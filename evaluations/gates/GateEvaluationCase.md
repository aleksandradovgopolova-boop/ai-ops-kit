# Gate Evaluation Case

Шаблон закреплённого случая «вход → ожидаемый вердикт гейта». Кейсы лежат в
`evaluations/gates/cases/<id>.yaml`; прогон — `python3 -m ai_ops_kit.devtools.gate_evals`.

```yaml
schema_version: 1
kind: gate-evaluation-case
id: <kebab-case, совпадает с именем файла>
gate: <id гейта из quality/gates.yaml>
case_kind: no_judge | judge_output
summary: <одна строка: что именно утверждает кейс>

origin:
  source: <откуда взят: путь к отчёту прогона / sha коммита>
  provenance: verbatim_run_report | verbatim_commit | class_repro | contract_invariant

# Сигналы задачи — влияют на применимость гейта (required_when) и на условный human_approval.
signals: {}

expected:
  status: pass | warn | fail
  reason_matches: [<подстроки, которые ОБЯЗАНЫ найтись в blockers/warnings>]

# Только для case_kind: judge_output — что подаётся судье в режиме live.
input:
  task: |
    <текст задачи для роли-судьи>
  diff_file: <id>.patch      # диф лежит соседним файлом, а не строкой в YAML

# Записанные ответы судьи. Заполняются живым прогоном:
#   python3 -m ai_ops_kit.devtools.gate_eval_live --record --case <id>
recorded:
  - recorded_at: <ISO-дата>
    provider: <claude-cli | anthropic | ...>
    model: <модель или пусто>
    derived_status: <вердикт цепочки НА МОМЕНТ ЗАПИСИ — заморожен>
    transcript: <id>-<n>.md   # файл в qualification/evidence/gate-evals/

# Замеренная устойчивость судьи (заполняет live-прогон). Ратчет: согласие не должно падать.
stability:
  measured_at: <ISO-дата>
  runs: <N>
  agreement: <k/N>
  verdicts: [<вердикт каждого повтора>]
```

## Правила

1. **Провенанс называется, а не подразумевается.** `verbatim_*` — вход взят дословно из
   случившегося прогона или коммита; `class_repro` — минимальное воспроизведение класса дефекта,
   замеренного в поле; `contract_invariant` — кейс закрепляет объявленный инвариант реестра.
   Смешивать нельзя: «настоящий» и «похожий на настоящий» — разные утверждения.
2. **`fail` обязан назвать причину** (`reason_matches`). Красное без основания неотличимо от
   красного по другому поводу, и следующая регрессия проедет незамеченной.
3. **`pass` без судьи тоже обязан назвать основание.** «Зелёное» без причины — ровно то, против
   чего заведён корпус.
4. **Кейс без записанного ответа судьи — `unavailable`, не `ok`.** Третье состояние не
   сворачивается во второе. Так же ведёт себя кейс, чья стенограмма не найдена: в поставке дочки
   улик нет по построению, и прогон обязан сказать «не измерено», а не упасть и не позеленеть.
5. **Диф — соседний `.patch`, стенограмма — файл в `qualification/evidence/gate-evals/`.** Первое
   механически: в unified diff пустая строка контекста — это строка из одного пробела, и PyYAML на
   таком тексте отказывается от блочного скаляра, превращая кейс в нечитаемую кашу. Второе — того
   же рода: стенограмма это улика прогона, её место рядом с остальными уликами, а 85 КБ судейской
   прозы внутри кейса делают из набора случаев дамп.
