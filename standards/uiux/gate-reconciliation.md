# Реконсиляция гейтов дизайна с UI/UX-Конституцией

> Работа `design-gates-cite-constitution-ids` (UI/UX, волна 2). **Это НАБЛЮДЕНИЕ.**
> Сила гейтов (`blocking`, `severity_policy` в `quality/gates.yaml`) НЕ меняется — усиление
> покрытия отдельная более поздняя работа. Тест
> `tests/unit/test_design_gates_cite_constitution.py` держит и привязку ID, и неизменность силы.

Три тонких блокирующих гейта дизайна (`ux_review`, `accessibility_review`,
`design_system_usage`) работают по чек-листам `rules/design/*`. Каждый пункт теперь несёт
`constitution_id` — стабильный ID правила Конституции (`standards/uiux/`), к которому он
привязан по смыслу; находка ревью цитирует этот ID, как code-review цитирует rule id.
Источник ID — `standards/uiux/rules.yaml` (генерируется из `UI_CONSTITUTION.md`).

## Расхождения (не скрываются)

### A. Пункты чек-листов без правила Конституции (`constitution_id: none`)

Всего: **4**. Это пункты гейтов, у которых нет прямого правила-двойника
в Конституции. ID не выдуман (запрет работы). Кандидаты на будущее правило Конституции
либо на осознанное оставление вне неё.

| Пункт | Гейт | Почему нет двойника |
|---|---|---|
| `h7-efficiency` | `ux_review` | ускорители для опытных (шорткаты/дефолты) — эвристика Nielsen №7; Конституция её как отдельную норму не вводит |
| `h10-help` | `ux_review` | контекстная помощь — эвристика Nielsen №10; отдельного правила в Конституции нет |
| `alt-media` | `accessibility_review` | текстовая альтернатива нетекстовому контенту (WCAG 1.1.1) — Конституция держит a11y на уровне принципов POUR (UI-025), отдельного правила про alt нет |
| `icons-standard` | `design_system_usage` | иконки из библиотеки системы, единый стиль/сетка — Конституция не вводит правило именно про иконки (UI-FORBIDDEN-018 — про форму icon-кнопки и aria, не про источник иконок) |

### B. Правила Конституции без пункта чек-листа

Всего: **43** из 65 правил Конституции не покрыты ни одним пунктом
трёх тонких гейтов. Это ОЖИДАЕМО: три гейта — узкий срез (UX-эвристики, WCAG-подмножество,
дизайн-система), а Конституция шире (ИА, взаимодействие, формы, данные, контент, анимация,
правила для ИИ, запреты тёмных паттернов). Список — карта того, что три гейта пока НЕ ловят;
расширение покрытия — отдельные будущие работы, не эта.

**Принципы мировой практики (world_standard)** — 19:

- `UI-001` — Назначение важнее оформления
- `UI-038` — Прозрачность поведения системы
- `UI-008` — У каждого экрана — понятная иерархия
- `UI-009` — Одна доминирующая задача
- `UI-011` — Предсказуемая навигация
- `UI-013` — Разделение оснований, компонентов и паттернов
- `UI-016` — Предсказуемость взаимодействий
- `UI-017` — Обратная связь следует за значимым действием
- `UI-018` — Деструктивные действия защищены
- `UI-039` — Риск определяет трение
- `UI-019` — Форма сообщает структуру
- `UI-021` — Не запрашивать лишнее
- `UI-031` — Оптимизация под сканирование
- `UI-032` — Состояния данных — первого класса
- `UI-036` — Пустое состояние объясняет и направляет
- `UI-037` — Загрузка сохраняет контекст
- `UI-025` — Доступность — базовый уровень, а не улучшение
- `UI-023` — Действия названы действиями
- `UI-024` — Без языка реализации

**Правила для ИИ (ai_ops)** — 9:

- `AI-001` — ИИ обязан изучить контекст до генерации
- `AI-002` — ИИ не изобретает компонент без нужды
- `AI-003` — ИИ генерирует полные состояния
- `AI-004` — ИИ сохраняет консистентность дизайн-системы
- `AI-005` — ИИ объясняет отклонения
- `AI-006` — UI от ИИ проходит независимую проверку
- `UI-FORBIDDEN-010` — Молчаливое отклонение ИИ от Конституции.
- `UI-FORBIDDEN-012` — Выдавать ИИ-контент или ИИ-действие за человеческое либо скрывать, что работает ИИ (Часть V).
- `UI-FORBIDDEN-013` — AI-функция без пути коррекции ошибки и без обозначения неопределённости (Часть V).

**Запреты (forbidden)** — 18:

- `UI-FORBIDDEN-001` — Создание нового компонента при наличии подходящего существующего.
- `UI-FORBIDDEN-002` — Произвольные цвета, отступы, радиусы, типографика при наличии эквивалентных токенов.
- `UI-FORBIDDEN-003` — Цвет как единственный индикатор состояния.
- `UI-FORBIDDEN-004` — Плейсхолдер как единственная метка поля.
- `UI-FORBIDDEN-005` — Технические сообщения об ошибке напрямую пользователю.
- `UI-FORBIDDEN-006` — Проектирование только happy path.
- `UI-FORBIDDEN-007` — Существенная функциональность спрятана только за hover.
- `UI-FORBIDDEN-008` — Недоступные кастомные контролы при наличии доступного нативного/устоявшегося.
- `UI-FORBIDDEN-009` — Новый паттерн взаимодействия без продуктовой причины.
- `UI-FORBIDDEN-010` — Молчаливое отклонение ИИ от Конституции.
- `UI-FORBIDDEN-011` — Манипулятивный (тёмный) паттерн: асимметрия выбора, pre-checked согласие, затруднённая отмена, confirmshaming, фейковая срочность (Часть VI).
- `UI-FORBIDDEN-012` — Выдавать ИИ-контент или ИИ-действие за человеческое либо скрывать, что работает ИИ (Часть V).
- `UI-FORBIDDEN-013` — AI-функция без пути коррекции ошибки и без обозначения неопределённости (Часть V).
- `UI-FORBIDDEN-014` — Форсированная регистрация до того, как показана ценность продукта (registration wall).
- `UI-FORBIDDEN-015` — Ложный или обманный индикатор загрузки, имитирующий работу, которой нет.
- `UI-FORBIDDEN-016` — Навязчивые прерывания: автозапуск видео/аудио; всплывающее окно поверх активной задачи или сразу после входа; автообновление, сбивающее позицию или ввод.
- `UI-FORBIDDEN-017` — Мисдирекшн: «крестик» закрытия, запускающий действие вместо отмены; кнопка отказа, замаскированная под согласие.
- `UI-FORBIDDEN-018` — Icon-only кнопка неквадратной/«плавающей» формы (высота ≠ ширина, размер вне шкалы) или иконка-действие без aria-label и тултипа (§28.1).
