# standards/uiux — UI/UX-стандарт кита (источник)

Единый **источник** правил дизайна для кита. Задаёт «как надо» для генерации и проверки
пользовательского интерфейса — машиночитаемо и проверяемо, а не текстом-подсказкой.

## Один источник, два генерируемых представления

| Файл | Что это | Правится руками? |
|---|---|---|
| `UI_CONSTITUTION.md` | **Источник истины**: 65 правил (8 частей), стабильные ID `UI-`/`AI-`/`UI-FORBIDDEN-` | да — правило меняют здесь |
| `ui-ux.rules.md` | Оперативный слой: одна строка на правило, для контекста агента | **нет — генерируется** |
| `rules.yaml` | Машинный реестр для гейтов и валидаторов | **нет — генерируется** |
| `scripts/build-rules.py` | Генератор обоих представлений из Конституции | — |

`ui-ux.rules.md` и `rules.yaml` **собираются** из `UI_CONSTITUTION.md`. Ручная правка
генерируемого файла затирается пересборкой, а расхождение генерата с источником краснит контур
(тест-зеркало `tests/unit/test_uiux_constitution_source.py`) — по образцу прочих «зеркал» кита
(check-fast↔CI, layering, счёт валидаторов).

## Изменить правило

1. Правишь `UI_CONSTITUTION.md` (ID стабильны — на них ссылаются гейты и код-ревью; новое
   правило получает следующий свободный ID, старые не перенумеровываются).
2. Пересобираешь:

   ```bash
   python standards/uiux/scripts/build-rules.py
   ```

3. Коммитишь источник вместе с пересобранными `ui-ux.rules.md` и `rules.yaml`. Тест-зеркало не
   даст закоммитить рассинхрон.

`level` (MUST/SHOULD/MUST_NOT/MAY) выводится из нормативных глаголов Конституции; `severity` и
`validation` — эвристика генератора, уточняется под риск-профиль вручную в исходнике генератора.

## Границы (это волна 1)

Здесь пока только **источник + генератор + сверка**. Стандарт внедряется в кит волнами
(цель `uiux-standard-as-product` в `ROADMAP.md`):

- **волна 1 (эта):** Конституция — источник; следующая работа свяжет её ID с существующими
  гейтами `ux_review` / `accessibility_review` / `design_system_usage` (в режиме наблюдения);
- **волна 2:** токены-контракт (`design/tokens/*.json`) и реестры компонентов/паттернов/шаблонов;
- **волна 3:** углубление агентов-ревьюеров и UI-health;
- **волна 4:** MCP-доступ к UI-системе.

Источник материала — пакет владельца `ai-ops-uiux` (решение A, 2026-08-27).
