## 2026-08-05 (окно — 2026-07-30…08-05)

**Топ-находка недели: жанр перестал быть пустым.** За семь дней вышло три содержательных проекта, повторяющих части тезиса кита, и все под permissive-лицензией. [QiQi14/multi-agents-control-plane](https://github.com/QiQi14/multi-agents-control-plane) (Apache-2.0, создан 2026-07-30, 5★) описывает себя дословно как «a task state machine with contracts, receipts, risk gates, and evidence, so that planning, execution, and review are separate roles with separate authority» — это одновременно gates, delivery-receipt, evidence-артефакты и writer≠judge в одном продукте; схемы объявлены нестабильными, v0.2.2. [disler/super-simple-software-factory](https://github.com/disler/super-simple-software-factory) (MIT, создан 2026-07-31, **371★**) — «moving the control plane out of the prompt and into Python», «Gates become the definition of done», типизированные envelope на стыках фаз, трейс в SQLite; в отличие от прочих соседей имеет реальный канал распространения (один Claude Code skill + YouTube-разбор). [0xwilliamortiz/ratchet](https://github.com/0xwilliamortiz/ratchet) (MIT, создан 2026-07-31, **430★**) — не конкурент, а **механизм, которого у кита нет**: хук PostToolUse измеряет каждую правку и возвращает вердикт в живую сессию; их формулировка проблемы («every minimalism ruleset for coding agents is an open loop») — прямой аргумент против гейтов, срабатывающих только на ревью.

**Харнесс под китом (Claude Code 2.1.221→2.1.222).** Две починки классов **обхода разрешений**, а не косметика: (1) zsh мог исполнить скрытые команды внутри regex-условия `[[ ]]`, минуя проверку Bash-инструмента; (2) PreToolUse-хуки с auto-allow обходили ограничения инструментов в фоновых агентных задачах (summaries, compaction, renames). Плюс: worktree-изолированные сессии и их субагенты могли запускать деструктивные git-команды по основному чекауту — изоляция теперь распространяется на правки файлов и Bash во всех типах сессий; `/fork` создаёт собственный worktree; появился `mode: "mask"` для sandbox-credential-файлов (Linux/WSL); удалена фича ultraplan ([CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)). **Вывод для кита:** если гейты кита опираются на хуки и permission-слой харнесса, то на версиях до 2.1.221/222 у них были документированные обходы — это довод в пользу минимальной поддерживаемой версии харнесса в capability-декларациях, а не только «хуки настроены».

**Пополнение охвата (не новинки окна, пропуски прошлых сканов).** [fluidbox](https://github.com/hrishikeshdkakkad/fluidbox) (MIT, создан 2026-07-10, 11★) — Rust control plane с policy-gated tools, human approvals и append-only audit ledger. **Постскриптум (тот же день) — обе рекомендации выполнены.**

1. **RR заведён:** RR-013 «Соседи по жанру, август 2026: жив ли ещё вывод EV-660 о ненайденной связной цепочке» (status draft, deadline 2026-08-21, required_confidence medium). Скоуп — читать код и артефакты трёх новых соседей, а не README; отдельный вопрос про ratchet как заимствуемый механизм и отдельный про то, как честно переформулировать EV-660.

2. **Инженерная проверка «опирались ли гейты кита на обойдённые механизмы харнесса» — выполнена, ответ отрицательный, с одной оговоркой.** Гейты кита харнесс-хуками не реализованы вообще: `find -iname "*hook*"` по репозиторию (кроме `.research/`) не даёт ни файла, гейты в `quality/gates.yaml` — это runnable-валидаторы (`validation/*.py`, `tools/*.py`), вызываемые воркфлоу; ограничение инструментов — свой `tools/tool_broker.py`, а не permission-слой харнесса; изоляция — свои контейнеры с одноразовым клоном (`containers/run-sandboxed.sh`, EV-910) и свои git worktree (`tools/worktree.py`). Поэтому починка PreToolUse-обхода в фоновых задачах (2.1.222) кита не задевает, а worktree-фикс относится к собственным изолированным сессиям харнесса, не к нашим git-worktree.
   Класс «скрытая команда внутри условного выражения» (zsh, починен в 2.1.221) на брокер **не транслируется** — проверено вызовом `Policy.decide` на векторах: `[[ -n *(e:cmd:) ]]` → deny (`['[[']` не в allowlist), `if cmd; then` → deny, `c=touch; $c …` → deny, `op=git` со вторым сегментом → deny. Плюс брокер исполняет через `subprocess(shell=True)`, то есть `/bin/sh`, где zsh-квалификаторов glob нет.
   **Оговорка (реальный, но небольшой дефект).** В `SANDBOX_SHELL_ALLOWLIST` три бинаря отнесены к группе с комментарием «безопасное чтение/навигация (модель исследует репо)» — `awk`, `sed`, `find` — но у всех трёх есть штатное исполнение команд: `awk 'BEGIN{system("…")}'` → ALLOW, `sed '1e …'` → ALLOW, `find . -exec … \;` → ALLOW (проверено на дефолтном `sandbox_policy()`, то есть при `allow_network=True`). Честная декларация кита про «инструменты, исполняющие код репо по своей природе» покрывает `python3/node/make/npm/pytest`, но эти три лежат не в той группе и описаны неверно. Гарантия при этом не пробита: настоящая граница — контейнер (read-only rootfs, смонтирован только одноразовый клон), и кит это прямо заявляет. То есть дефект — в **классификации и комментарии**, а не в границе; правка на один комментарий и перенос трёх строк в соседнюю группу.
   Побочно: первая проба дала ложное «всё deny», потому что `NETWORK_RE` ловит слово `curl` в любом месте строки — вердикты приходили за payload, а не за разбор конструкта. Урок для будущих проб брокера: adversarial-вектор не должен содержать сетевого слова, иначе проверяешь денайлист вместо allowlist.
