# Механизм: десять вопросов жизни фичи из связанной истории (T2)

Дата: 2026-09-28. Направление: `product-memory-org-intelligence` (цель №1 «Сейчас»).
Работа: `ten-questions-answered-on-a-real-ii-sreda-feature` (issue #1139).
Продолжает замер T1 (`PRODUCT-MEMORY-THREAD-MEASURE-2026-09-21.md`), где на ии-среде из улик
отвечался лишь 1 вопрос из 10: данные были узлами графа, но не сшивались в нить на уровне фич.

## Что построено

Один сценарий поверх уже собранного графа знаний — `intelligence/feature_life_history.
answer_ten_questions(graph, feature)` и команда `./ai-ops graph questions <feature>`. Он отвечает на
ДОСЛОВНЫЕ десять вопросов приёмки направления:

1. зачем возникла — из решения (`decision -motivates-> feature`);
2. какую проблему решает — из цели (цепочка `contains` до цели);
3. для кого — аудитория из связанного паспорта функции (`feature.audience`);
4. какая гипотеза — из связанного урока (`FL-*.hypothesis`);
5. почему такое решение — выбранный вариант и причина (`FL-*.solution_options.chosen`);
6. что построили и где — из работы/PR (`work -builds-> feature`);
7. что доказано и кто проверял — из персистентного вердикта ревью (`review -reviewed-> feature`);
8. что произошло после релиза — реальный сдвиг метрики (`outcome-readout`) либо объявленный исход;
9. чему научились — выводы из связанного урока (`FL-*.learnings`);
10. что дальше — следующий шаг по уроку (петля outcome→insight→next) либо `FL-*.follow_up`.

## Граница честности (важно)

Связь между функцией и её историей доказывает ГРАФ (рёбра). Конкретный ответ на вопросы 3/4/5/9/10
читается из ПЕРВОИСТОЧНИКА, на который ссылается связанный узел (`ref`/`blueprint`), — граф намеренно
НЕ расширяли вширь (ревью прямо просило «не расти вширь, а сделать один связный сценарий»). Это
по-прежнему ответ «из связанных улик», а не генерация: у каждого ответа в поле `evidence` — id
узлов/рёбер и путь к артефакту, которым он подтверждён. Чего в связанной истории нет — называется
честным `unknown_reason` с указанием недостающего звена, а не заменяется догадкой. «Неизвестно» ≠
выдуманный ответ.

## Что ДОКАЗАНО (тестами, на фикстуре)

`tests/unit/test_feature_life_history.py` (поведенческий, модуль грузится по пути):

* на фиче с полной историей отвечены ВСЕ ДЕСЯТЬ, у каждого ответа есть улика, ссылающаяся на реальные
  узлы графа;
* на фиче с пробелами недостающие вопросы — честное «неизвестно» с причиной (какого ребра/поля нет),
  БЕЗ выдуманного ответа;
* без корня репозитория вопросы, чей ответ живёт в первоисточнике, честно «неизвестно» (граф один их
  не несёт) — а не тихо выдуманы;
* функции нет в графе → все десять «неизвестно» по одной причине;
* собранный граф проходит `validate_knowledge_graph` (граф не изменён — новых узлов/атрибутов нет).

## Что ОСТАЁТСЯ за владельцем (полевая приёмка)

Зачётная планка направления — «на ОДНОЙ РЕАЛЬНОЙ фиче ии-среды кит отвечает на все десять вопросов
из связанной истории». Это ПОЛЕВОЕ доказательство: его берёт ВЛАДЕЛЕЦ на репозитории
`Proektnyy-ofis/ii-sreda`, прогнав `./ai-ops graph build .` и `./ai-ops graph questions <feature> .`
на реальной фиче с населённой историей (решение, работа/PR, ревью, FL, аудитория). Здесь доказан
только МЕХАНИЗМ на фикстуре — фикстура за поле НЕ выдаётся.

Что для поля требуется населить на стороне ии-среды (следует из замера T1 и из причин `unknown`
механизма): у выбранной фичи — объявленные `links.decision` и `links.built_by`, `feature.audience` в
паспорте, `FL-*.yaml` с `hypothesis`/`learnings`/`solution_options`/`follow_up`, привязанный к фиче,
и запись `features/<id>/review/verdict.yaml`. Когда на такой фиче `graph questions` вернёт 10/10 из
улик, планка направления считается взятой; повторный этот прогон на реальной фиче — критерий.
