## Находки

### 1. Быстрый путь есть только у документации

docs-правка (правка `.md`): продуктовые тесты пропускаются как prose-exempt, остаётся ruff + impact.

| | Холодный (1-й) | Тёплые (медиана) | Тёплые (макс) |
|---|---:|---:|---:|
| Цикл docs-правки, с | **1,35** | **0,79** | 0,96 |

Для документации обратная связь приходит за ~секунду. Это ожидаемо и работает.

### 2. Любая правка кода запускает полный набор — сужения нет

На правку **любого** `.py` (включая сам тест) селектор отдаёт `tier=full`,
`affected_tests=0`, `impact_status=targeted_tests_not_found`. Проверено на пяти файлах разного
веса — лист (`checks/lint_baseline.py`), ядро (`shared/budget.py`, `engine/acceptance_verify.py`),
и даже сам тест (`tests/unit/test_budget.py`) — **во всех случаях полный откат**.

Причина названа самим китом:

> Full fallback: dependency graph incomplete: dynamic pytest fixtures have implicit consumers

То есть граф зависимостей объявлен неполным (динамические pytest-фикстуры с неявными
потребителями), и из осторожности кит гоняет весь корпус. **Тормозит не объём тестов сам по себе,
а то, что targeted-выбор локально фактически выключен для кода.**

### 3. Полный откат = `check-full.sh --pr` (весь корпус, включая `slow`)

`tier=full` исполняет `bash scripts/check-full.sh --pr` = ruff +
`pytest tests/ -q -n auto --dist loadfile -m "not nightly and not release_gate"`.
Набор `не nightly и не release_gate` **включает `slow`-тесты**. Одна только сборка «не slow»
подмножества — **9 251 тест за 6,67 с**; `slow`-тесты сверху.

«Не slow» подмножество под реальной нагрузкой машины дошло до **80 % за 220 с на 10 ядрах**
(≈275 с целиком) — совпадает с задокументированным в скрипте ожиданием «~283 с». `slow`-тесты
добавляются поверх этого.

### 4. Полный цикл часто вообще не стартует — сторож host-slot

`check-full.sh` берёт общий host-slot и **отказывается стартовать**, если `ps` видит другой
тяжёлый процесс. Матчер (по строке команды, **без учёта CPU**):

```
pytest | vitest | playwright test | check-full.sh | (npm|pnpm|yarn) (run) build|test|typecheck | tsc
```

На машине владельца постоянно крутятся self-hosted actions-runners (`prechecker`,
наблюдались PID 28644 / 63377 / 96703) — они матчатся **всегда, даже при 0 % CPU**. В этой сессии
попытка чистого замера полного `--pr` цикла **была заблокирована все 480 с** и не стартовала;
отдельное более раннее наблюдение дало ~3606 с с прерыванием (rc=2, контаминация). То есть на
реальной машине полный локальный цикл — это не «медленно», а часто **«не запускается»**, пока
рядом есть совпавший процесс. (Тот же эффект зафиксирован 20.10: отказ допуска при чужом vitest
PID 28644 даже при CPU=0.)

### 5. Дрейф версий Python — скрытая причина повторов

Локально цикл идёт на Python **3.14**, а CI — на **3.12** (`check-full.sh` исторически ждал 3.11).
Локальный зелёный не гарантирует зелёный CI → лишний круг. Это причина повторов первого класса,
а не сноска. Принцип владельца: разница версий **не должна мешать процессам разработки**.

## Причины повторов, наблюдавшиеся в этой сессии

- **Блокировка host-slot** постоянными раннерами — цикл приходится откладывать/повторять.
- **Полный откат на каждую итерацию** — каждая правка кода повторно гоняет весь корпус, нет
  промежуточного узкого цикла.
- **Дрейф версий local↔CI** — потенциальный лишний круг local-green → CI-red.

Неизвестные повторы не выдаются за ноль; сэкономленные секунды не вычисляются.

## Осталось unknown (не изменилось этим срезом)

Сквозной wall с очередью и dispatch CI; CPU/оплаченные минуты; денежная цена; cold OS-кэш;
p95 (n слишком мал — честно недоступно). Чистый wall полного `--pr` цикла не получен из-за
блокировки host-slot; его замер требует свободного слота (без остановки чужих рабочих процессов).

## Что это значит для #1321 (рычаги, не объявление готовности)

1. **Вернуть сужение для кода:** пока граф зависимостей объявлен неполным, targeted-выбор для
   `.py` не работает и всё уходит в полный откат. Это главный рычаг «быстрого feedback».
2. **Отделить `slow` от быстрого пути:** `slow`-тесты сейчас внутри локального `--pr`-набора.
3. **host-slot не должен постоянно блокировать локальную разработку** из-за несвязанных
   фоновых раннеров (матч по имени без учёта CPU).
4. **Выровнять Python local↔CI**, чтобы версия не рождала лишние круги.

Ни один исход #1321 этим baseline не закрывается — это измерение, с которого считается «после».
