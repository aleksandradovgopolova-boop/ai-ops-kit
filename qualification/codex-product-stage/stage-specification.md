# Solution Design

## Контекст и constraints

Черновик заметки должен сохраняться локально после ввода, чтобы текст можно было восстановить после случайного закрытия вкладки и её повторного открытия. Вне scope: синхронизация, аккаунты и публикация.

## Варианты

Локальное хранилище браузера для текста черновика.

## Сравнение

Локальное хранение соответствует требованию восстановления в том же браузере без серверной инфраструктуры. Оно не обеспечивает перенос между устройствами или браузерами, что находится вне scope.

## Рекомендуемое решение

Сохранять введённый текст заметки локально. При повторном открытии вкладки восстанавливать сохранённый черновик. Предоставить пользователю действие для удаления черновика; после удаления текст не должен восстанавливаться.

## Компоненты и взаимодействия

- Редактор заметки принимает ввод пользователя.
- Локальное хранилище сохраняет текущий текст после ввода.
- При открытии заметки редактор читает локально сохранённый текст и восстанавливает его.
- Действие «удалить черновик» очищает локально сохранённый текст.

## NFR

Сохранение и восстановление происходят локально, без требований к сети или серверу.

## Security and privacy

Текст хранится локально в используемом браузере. Передача текста внешним сервисам в рамках задачи не предусмотрена.

## Migration / rollback

Миграция не требуется. Удаление черновика является пользовательским действием.

## Architectural compromises

Явного двустороннего архитектурного компромисса в подтверждённых требованиях нет; применение ТРИЗ не требуется.

## ADR required

Нет.

Открытый вопрос владельцу: каков требуемый срок хранения локального черновика?
