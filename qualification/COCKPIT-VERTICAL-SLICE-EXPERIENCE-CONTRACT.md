## Пользовательский сценарий

**Владелец** открывает Cockpit утром. На экране 3 плитки: одна с терминалом, одна с браузером,
одна пустая. Он не помнит, на каком этапе остановилась вчерашняя задача.

**Без панели:** владелец кликает на плитку терминала, читает последние строки вывода,
пытается понять контекст, открывает транскрипт, ищет последнюю рекомендацию кита.
Время: 2-5 минут.

**С панелью:** владелец нажимает ⌘A (или кликает на иконку панели). Справа выезжает
панель с заголовком «Задача: добавить hello-world endpoint». Ниже:
- Этап: `run` (выполняется)
- Статус: ждёт ввода
- Требование: «Выберите: применить правку или откатить?»
- Кнопки: [Применить] [Откатить] [Подробнее]

Владелец нажимает «Применить». Панель закрывается. Время: 5 секунд.

## Контракт взаимодействия

### Видимость
- Панель скрыта по умолчанию (не занимает место, когда не нужна)
- Открывается по ⌘A или клику на иконку в статус-баре
- Закрывается по ⌘A, Escape, или клику вне панели

### Содержимое
- **Заголовок:** название работы из workitem.yaml (или "Нет активной работы")
- **Этап:** один из specify/plan/run/review/done
- **Статус:** работает / ждёт ввода / заблокирована / готова / ошибка
- **Требование:** текст рекомендации из session_guardrails (если есть)
- **Действия:** кнопки из рекомендации (если есть)

### Обновление
- Polling каждые 5 секунд через Electron IPC
- При смене сессии — мгновенное обновление
- При отсутствии активной сессии — панель показывает «Нет активной работы»

### Доступность
- Keyboard navigation: Tab между кнопками, Enter для действия
- Контраст: текст 4.5:1 минимум на фоне панели
- Screen reader: aria-label на каждом элементе

## Stories (требования)

### Story 1: Панель открывается по горячей клавише
**Как** владелец, **я хочу** открывать панель активной работы по ⌘A,
**чтобы** не искать её мышью.

**Acceptance:**
- ⌘A открывает панель, если закрыта
- ⌘A закрывает панель, если открыта
- Работает из любого состояния приложения

### Story 2: Панель показывает контекст сессии
**Как** владелец, **я хочу** видеть название работы, этап и статус,
**чтобы** понять, что происходит, без чтения транскрипта.

**Acceptance:**
- Название работы берётся из workitem.yaml
- Этап и статус обновляются каждые 5 сек
- При отсутствии сессии показано «Нет активной работы»

### Story 3: Панель показывает требование и действия
**Как** владелец, **я хочу** видеть, что от меня требуется, и иметь кнопки для действия,
**чтобы** ответить киту без открытия терминала.

**Acceptance:**
- Текст требования из session_guardrails.recommend()
- Кнопки из рекомендации (если есть)
- Нажатие кнопки отправляет действие в сессию

### Story 4: Панель закрывается по Escape
**Как** владелец, **я хочу** закрывать панель по Escape,
**чтобы** не тянуться к мыши.

**Acceptance:**
- Escape закрывает панель, если открыта
- Не влияет на другие элементы (если панель закрыта)

## Измерение успеха

- **Время до действия:** от открытия панели до нажатия кнопки < 10 сек
- **Частота использования:** владелец открывает панель ≥1 раз в день
- **Отказ:** если панель не используется за неделю — удаляем

## Технический контракт

### Данные (Electron IPC)

```typescript
interface ActiveWorkInfo {
  workTitle: string | null;      // из workitem.yaml
  featureId: string | null;      // из workitem id
  stage: 'specify' | 'plan' | 'run' | 'review' | 'done' | null;
  status: 'working' | 'waiting' | 'blocked' | 'ready' | 'error' | null;
  requirement: string | null;    // из session_guardrails
  actions: Array<{label: string; command: string}> | null;
}
```

### API

```typescript
// electron/preload.cjs
electronAPI.getActiveWork(): Promise<ActiveWorkInfo>
electronAPI.sendAction(command: string): Promise<void>
```

### Источники

- `session_telemetry.snapshot()` → stage, status
- `session_guardrails.recommend()` → requirement, actions
- `workitem.yaml` → workTitle, featureId
