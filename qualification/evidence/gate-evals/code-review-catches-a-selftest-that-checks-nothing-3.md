# Code Review

## Вердикт

**FAIL.** Модуль объявляет три проверки, реализует полторы, и ни одна из реализованных не даёт истинного сигнала: ветка проверки флагов не может сработать никогда (конструктивно), ветка проверки traceback срабатывает всегда и ложно — на самом себе. Плюс прямое нарушение правила репозитория: selftest живёт в продакшн-модуле и при этом ничего не исполняет — печатает «SELFTEST PASSED» константой.

Ирония, которая здесь не украшение, а суть дефекта: модуль написан под тезис «совет, который нельзя выполнить, хуже отсутствия совета», и сам утверждает пройденной проверку, которой не делал.

## Blockers

**B1. Selftest не исполняет ничего из того, о чём отчитывается** (`ai_ops_kit/engops/refusal_paths.py`, ветка `if args.selftest:`)

```python
print("  - check_refusal_paths: OK")
print("  - format_report: OK")
print("SELFTEST PASSED")
return 0
```

Ни `check_refusal_paths`, ни `format_report` не вызываются. Строки — литералы. Это не слабый тест, это отчёт о невыполненной проверке; ровно тот класс дефекта, который правило репозитория запрещает явно («модуль не вправе утверждать пройденной проверку, которой не делал»). Возвращает 0 безусловно — то есть в любом CI-гейте это вечно-зелёная строка.

**B2. Проверка флагов не может обнаружить дефект ни при каких входных данных** (`defined_flags` / цикл по `error_patterns`)

Два независимых убийцы:

- `defined_flags = set(re.findall(r'--([a-z0-9-]+)', content))` собирает **все** токены `--flag` во всём файле, включая те, что встречаются внутри сообщений об ошибках. Множество «определённых» флагов по построению является надмножеством «упомянутых». Условие `if flag not in defined_flags` невыполнимо в принципе.
- `error_patterns` ищут в **исходном коде** строки, которые argparse генерирует в **рантайме** (`unrecognized arguments: --x`, `invalid choice: 'x'`). В исходнике этих литералов нет, `finditer` не даст ни одного совпадения.

То есть заявленная главная проверка модуля — мёртвый код, гарантированно возвращающий «всё хорошо».

**B3. Проверка traceback ложно срабатывает на самом модуле — инструмент всегда падает на своём же репозитории**

`engops_path.glob("*.py")` включает `refusal_paths.py`. Файл содержит литерал `"Traceback (most recent call last)"` (строка сравнения), первое условие истинно. Второе условие — `re.search(r'["\'].*Traceback.*["\']', content, re.DOTALL)` — с `DOTALL` точка матчит переводы строк, поэтому «любая кавычка где угодно выше + Traceback + любая кавычка где угодно ниже» матчится всегда. Комментарий «Check if it's in a string literal» описывает проверку, которой регексп не делает.

Итог: `check_refusal_paths` на реальном дереве вернёт `status: "fail"`, `exit 1` с issue о самом себе. Единственная ветка, способная сработать, срабатывает неверно.

**B4. Selftest размещён в продакшн-модуле** — прямое нарушение AGENTS.md. Требуется `tests/unit/test_refusal_paths_selftest.py`; в диффе его нет, флаг `--selftest` в модуле есть.

## Major

**M1. Заявленная проверка «Все упомянутые команды существуют» не реализована вовсе.** В docstring объявлена, в `check_refusal_paths` соответствующего кода нет. Docstring — это тоже контракт; расхождение делает отчёт `refusal-paths-check` недостоверным по третьему пункту.

**M2. Отсутствующий файл = молчаливый pass.** `if cli_path.exists():` — если пути нет, проверка пропускается без следа, и отчёт возвращает `status: "pass"`. Отдельно требует верификации сам путь: `root / "ai_ops_kit" / "cli" / "ai_ops_cli.py"` — по документации кита CLI устанавливается как `.ai/managed/tools/ai_ops_cli.py`. Если путь не тот, вся ветка флагов не исполняется ни разу, а отчёт всё равно зелёный. Нужен статус `skipped`/`error` с ненулевым кодом, а не тихое «pass».

**M3. Нет ни одного теста.** В диффе нет ни selftest-теста, ни фикстурного теста на `check_refusal_paths` (дерево с реально несуществующим флагом → `fail`; чистое дерево → `pass`). Любой из этих двух тестов немедленно вскрыл бы B2 и B3 — что и объясняет, почему их отсутствие здесь не формальность.

**M4. Необработанные ошибки чтения.** `read_text(encoding="utf-8")` без `errors=`/`try` — файл в другой кодировке или без прав на чтение уронит модуль с сырым traceback в stdout. Модуль, чья задача — ловить сырые traceback в отказах, сам их производит.

## Minor

- `--json` не действует на `--selftest`: остальной кит отдаёт машиночитаемый `schema_version`-JSON, selftest — свободный текст. Ломает единообразие потребления в гейтах.
- `glob("*.py")` не рекурсивен: подпакеты внутри `engops/` не проверяются. Если это осознанно — нужен комментарий, иначе покрытие тихо неполное.
- Docstring обещает `refusal_paths.py <child_root>`, но `root` имеет `default="."`; запуск без аргумента молча проверит текущую директорию вместо явного отказа.

## Scope violations

Scope creep нет — добавлен ровно один файл по теме задачи. Нарушение обратное: **объявленный scope не покрыт** (см. M1) при формально корректных границах диффа.

## Missing tests

- `tests/unit/test_refusal_paths_selftest.py` — обязателен по AGENTS.md, отсутствует.
- Позитивный кейс: дерево-фикстура, где отказ ссылается на несуществующий флаг → ожидается `status: "fail"` и issue типа `undefined_flag`.
- Негативный кейс: чистое дерево → `status: "pass"`, `total_issues: 0`.
- Кейс «CLI не найден» → явный `skipped`/`error`, не `pass`.
- Кейс на traceback-детектор: файл с `traceback.format_exc()` в ветке отказа → `fail`; файл, лишь упоминающий слово Traceback в комментарии/сравнении → **не** `fail` (регрессия на B3).

## Compatibility risks

- Если модуль подключается к гейту как есть, он будет **валить пайплайн всегда** из-за самосрабатывания (B3) — с сообщением, указывающим на сам чекер. Диагностический шум с нулевой информативностью.
- Если B3 «починить» точечно (исключить себя из glob), останется B2 — и гейт станет вечно-зелёным, что хуже: он будет создавать документированную иллюзию покрытия ветки отказов.
- Ненулевой exit code (`return 1`) как штатный исход для дерева, где нет никаких проблем, ломает ожидания вызывающих скриптов.

## Что сделано хорошо

- Мотивация в docstring сформулирована точно и по делу: «совет, который нельзя выполнить, хуже отсутствия» — правильная постановка проблемы, ради которой стоит писать этот модуль.
- Формат отчёта согласован с китом: `schema_version`, `kind`, `status` — потребитель предсказуем.
- Разделение `check_*` / `format_report` / `main` корректное: чистая функция проверки отделена от представления и от CLI, что делает модуль тестируемым — как только тесты появятся.
- Дифф дисциплинирован: один файл, без попутных правок.
