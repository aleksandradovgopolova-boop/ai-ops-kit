# #1409 — база времени и памяти

Результат: существующий `bench_performance` воспроизводимо исполняет последовательные серии команд CI/runtime, сохраняет все попытки, время и пик RSS; отказ или несовместимые входы не дают зелёное сравнение.
Затрагиваемые пути: CLI devtools → JSON suite → отдельный процесс измерителя → команда → receipt/logs → явный baseline → сравнение времени/памяти. Старый microbenchmark API сохраняется.
Инварианты: stdlib + существующий host_resource_cli; без второго механизма, автоматической перезаписи базы, новых CI-гейтов, shell=True и оптимизаций. SHA и dirty fingerprint обязательны. Локальная реплика CI не объявляется настоящим CI.
Failure modes: ненулевой exit/timeout; отсутствующая или повреждённая база; пропавшая метрика/команда; другая среда/повторы; занятый или потерянный host-slot.
Доказательство: лёгкие subprocess-тесты с фактическим marker-файлом и измерением RSS; контролируемая задержка действительно исполняется до проверки красного сравнения; ошибочные/несопоставимые receipts блокируются; прежние unit-тесты и core smoke.
Не входит: оптимизация, новый обязательный CI, изменение общих реестров/плана/FILE_INDEX/CI, commit/push/PR/merge, запуск тяжёлых серий без отдельного окна. Фактический baseline до такого окна остаётся NOT_RUN.
