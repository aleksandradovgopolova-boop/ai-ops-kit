# Первый час: три человека, три репозитория

Подготовка #1238 завершает описание опыта. Это **не проведённый опыт** и не выполнение #1115 / measure-first-hour-with-a-stranger. Версия протокола 1, 05.10.2026; изменение после начала сессий получает новую версию и отдельную когорту. Форма: [FIRST-HOUR-JOURNAL-TEMPLATE.md](FIRST-HOUR-JOURNAL-TEMPLATE.md).

## Кто и с чем начинает

Три разных человека, прежде не устанавливавших и не использовавших Kit, проходят по одному первому часу. Они могут знать свой продукт и обычный AI-инструмент; заранее записать опыт Git/CLI/AI. Владелец Kit и автор протокола не являются зачётными участниками. Три разных реальных репозитория: небольшой web-продукт, продукт с backend и desktop/monorepo либо три эквивалентных отличающихся стека. Это целевая выборка, не статистическая оценка всех пользователей.

Имена/репозитории и слоты **пока не назначены**. Наблюдатель заполняет три карточки до запуска; приглашение людей — отдельное действие владельца. Репозиторий без Kit — исходное условие, не устное обещание. До часов проверить отсутствие установленной `.ai/` кита, `.ai-ops.yaml`, `ai-ops` launcher и зарегистрированных Kit skills/plugins/hooks. Собственные AGENTS.md, документацию и средства проекта сохранять. Если Kit уже стоял, предпочтителен другой настоящий проект; допускается изолированная копия до установки с известным SHA и журналом происхождения, но не копия со скрытым готовым контекстом. Удаление Kit в оригинальном продукте не требуется.

Среда до T0: Git/поддерживаемый Python и привычный AI runtime доступны, права на отдельную ветку/PR есть, зависимости продукта установлены и исходный smoke проходит. Проверка среды не обучает Kit и не раскрывает сценарий. Иначе явно пометить опыт как `environment-blocked`, сохранить ошибку и полное время; не заменить его успешным четвёртым участником. В дополнительном опыте с чистой машиной все установки входят в часы и результат публикуется отдельно.

Закрепить опубликованный Kit v4.9.3, commit ad16611cec1ca65a659f597f7b3b0436df8e78b8 (сверить полный SHA тега в карточке перед T0), runtime/model/version и ОС. Отключённый доступ Claude к организации делает соответствующую сессию blocked, ручной вызов hook не заменяет её. Участник получает README этой версии и обычный вход своего инструмента; скрытой заранее установленной Kit skill нет. Если README требует доступного плагина/skill, участник устанавливает его после T0, запись времени обязательна. Смена Kit/runtime создаёт другую когорту, прежний неуспех остаётся в отчёте.

## Сценарий и критерии до часов

Наблюдатель с владельцем продукта выбирают **одну настоящую небольшую работу** из ещё не выполненного backlog: видимый дефект или небольшое изменение поведения. Не выбирают придуманную правку ради теста, установку Kit, обновление самого Kit или готовый ответ. Карточка называет исходную проблему, пользователя, путь воспроизведения и наблюдаемую приёмку. Участник получает только запрос обычными словами:

> Подключи Kit к этому проекту. Помоги понять, что здесь происходит, и подготовь работу по этому запросу: [реальный запрос]. Если получится — доведи изменение до проверенного PR.

**Первый полезный результат** — показанный человеку ответ о данном продукте: цель запроса, один подтверждённый факт из исходников/документов со ссылкой и следующий конкретный шаг, который участник понимает и принимает. «Установка завершена», общий план без факта, список ролей/гейтов не засчитываются. Факт сверяет наблюдатель по источнику, не объясняя участнику правильный ответ заранее.

**Готовность первой работы** — участник может начать выбранное изменение: согласована приёмка, указан затрагиваемый путь, есть отдельная рабочая ветка и выполнимый первый шаг с командой проверки/способом наблюдения. Недоступная команда, неполученные права или неопределённый пользовательский результат — не ready. Это не утверждение, что PR уже готов.

**Принятый PR** — реальное изменение по карточке, проверка поведения + применимый CI/review, принятие владельцем продукта и merged PR. Время до PR меряется отдельно, без искусственного обещания «PR за 15 минут». После первого часа PR может быть завершён позже; при отчёте неполученное событие right-censored: «не наступило к [время]», а не ноль и не готово.

## Часы и помощь

T0 — участник получил доступ к репозиторию без Kit, README и запрос и начинает действовать. Все метки — ISO 8601 с часовым поясом, длительность — секунды. Основные часы **не останавливаются**: чтение, ответы на вопросы, загрузки, ожидания инструмента и помощь человека входят. Вторично отметить интервалы human/runtime/environment, но их вычитание не улучшает основной результат. В репетиции niti 29.09 вычитали человеческую паузу; этот опыт не является baseline независимого первого часа.

T_result/T_ready/T_pr — момент первого выполнения определения выше и источник. Наблюдение первого часа заканчивается T0 + 60 минут либо ранним отказом; в обоих случаях сохранить неуспех и причины. Для отказа длительность до отказа не подставлять вместо времени отсутствующего результата.

Наблюдатель молчит, может повторить исходную формулировку без подсказки. На просьбу о помощи записать вопрос и дать минимальный ответ, чтобы человек мог продолжить; каждое объяснение Kit, подсказка команды, выбор workflow/роли или исправление за участника — отдельное вмешательство. Не давать такой помощи заранее. При риске для продукта остановить опасное действие в экспериментальной копии; вмешательство и остановка остаются в журнале. Сессия с помощью даёт assisted time, **не самостоятельный pass**. Поддержка продукта, а не Kit, отмечается отдельно, но тоже входит во время.

## Что считать

| Поле | Правило |
|---|---|
| Вопросы | Каждый новый вопрос участника инструменту/наблюдателю; ответы на onboarding-вопросы инструмента считать отдельно |
| Технические решения | Требуемый выбор runtime/model, роли, workflow, gate, файла конфигурации или команды; отдельно обычное продуктовое решение |
| CLI | Каждая выполненная участником команда, включая повтор; автоматические команды инструмента отдельно |
| Тупики | Нет следующего выполнимого шага, ошибка или отказ; причина, начало/конец и выход фиксируются |
| Переделки | Повтор действия из-за потерянного ответа/ошибки/непонятного результата, со ссылкой на событие |
| Помощь владельца | Каждое содержательное вмешательство и активные минуты человека; авторские исправления отдельно |
| Новые понятия | Участник попросил объяснить либо система потребовала понять новое внутреннее понятие для продолжения; привести точное слово и событие |
| Внутренние YAML / выбор ролей | Число действий участника по редактированию внутренних YAML, выбору роли/workflow/gate; автоматическая работа системы сюда не входит |

Не восстановимое из журнала — unknown; отсутствие записи не означает ноль. Согласие участника на обезличенную фиксацию требуется до записи экрана; при отказе использовать журнал событий, отметить недоступные поля. Секреты и персональные данные не сохранять в qualification.

## Вердикт без усреднения неудач

Для каждого из трёх: первый результат ≤300 секунд; ready ≤900 секунд; **0** внутренних YAML/выбора роли/workflow/gate; 0 содержательной помощи Kit для independent pass. Цель считается доказанной только по трём independent pass, а завершение первой настоящей работы подтверждается отдельно принятым PR каждого участника. Assisted/blocked/fail публикуются наравне с успехами. Не переносить порог первого часа на accepted PR.

Отчёт показывает 3 строки, все времена и пропуски, затем повторяющиеся тупики и продуктовые исправления. При n=3 нет процентов «всех пользователей», прогнозов рынка и статистической значимости. Повтор после исправления — новая сессия с обозначенной повторной знакомостью, не замена исходной.

## Следующее действие

Владелец назначает три новых участника и три проекта; наблюдатель заполняет карточки и подтверждает среду. Затем выполняется #1115; #1239 берёт реальные тупики из журналов. Самостоятельно приглашения и сообщения людям не отправлялись.
