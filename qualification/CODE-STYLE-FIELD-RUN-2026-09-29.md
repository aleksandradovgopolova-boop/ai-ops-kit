# Полевой прогон «стиль кода держит машина» на ии-среде — 2026-09-29

Направление `child-code-style-held-by-machine` (#1183). Кит — выпуск v4.8.0, в конце — `main` со стыком
профиля (PR #1213). Дочка — `Proektnyy-ofis/ii-sreda`.

## Главное

Проблема, ради которой заводилось направление, на ии-среде уже снята — **самой ии-среды, а не китом**.
Утром 29.09 в ней влит ii-sreda#1007 («по внешнему аудиту 29.09»): свои правила ESLint
`local/latin-identifiers` и `local/layer-boundaries`, 1 200 русских имён переведены (≈9 200 мест в
164 файлах), 40 нарушений слоёв исправлены, долг по именам и слоям — 0. Профиль кита на ии-среде
поэтому не применялся: её собственные правила строже, и накладывать поверх них вторую базу нечего.

Вклад кита в ии-среду — то, чего у неё не было: правило срабатывает **в момент правки агента** (хук),
а не только на `npm run lint` и в CI.

## Что НЕ проверено — и почему

- **Живая сессия агента Claude Code в ии-среде.** Консольный режим (`claude -p`) в этом окружении
  отключён политикой организации («subscription access disabled»). Хук проверен его входным событием —
  тем же JSON, — а не живым агентом.
- **Новый workflow `ai-ops-lint` на раннере.** GitHub Actions ии-среды стоят по оплате: джобы не
  стартуют («recent account payments have failed»). В ii-sreda#1013 раннер workflow приведён к правилу
  её остальных workflow (`[self-hosted, Linux]` без `CI_RUNNER_LINUX`), иначе он ушёл бы на платный
  `ubuntu-latest`.
- **Ревьюер по статьям конституции** живым ревью в дочке не наблюдался.
- **Находка «нет линтера»** на реальной дочке без линтера не наблюдалась (у ии-среды линтер есть).
- **Стык профиля (PR #1213)** в дочку ещё не выпущен — едет следующим выпуском кита.

## Урок

- **Параллельная работа снимает задачу быстрее кита.** Пока кит строил механизм, владелец дочки
  закрыл её руками по внешнему аудиту. Ценность механизма от этого не пропадает: профиль нужен
  дочкам, которые этого ещё не сделали, а хук делает правило ии-среды исполняемым в момент правки.
  Но засчитывать «кит исправил ии-среду» было бы неправдой.
- **Шаблон CI кита по умолчанию уходит на `ubuntu-latest`.** В дочке со своими раннерами и без
  `CI_RUNNER_LINUX` новый workflow кита едет на платный раннер. Это общий класс для всех шаблонов
  кита, не только нового.
