# #611: native потребление сохранённой модели работы

Исполнитель AI. Изолированная копия реальной ии-среды9f36ae3b; общий CLI и
сгенерированные адаптеры candidate ветки. Не stable rollout и не выборка #1243.

Первоначальный опыт Qwen→Codex не квалифицирован: Qwen Code0.21.13 с настроенной
qwen3.7-plus получил403 до инструментов. CLI вернул0 и subtype=success, но файл
не создан. Reported tokens0 не доказывают цену USD0. После read-only /model inventory
отдельно зарегистрирован опыт с уже настроенной qwen3.6-plus: тот же403,9.125s,
инструменты не исполнились. Глобальная модель, логин и ключи не менялись; новых попыток нет.

Перед следующей попыткой отдельно зарегистрирован частичный опыт Codex, без
утверждения успешного handoff. Native Codex0.163.0 действительно прочитал
сгенерированные инструкции, исходные WorkItem/RunPlan и общие проекции, затем
apply_patch создал только разрешённый src/shared/lib/kit-runtime-qualification.ts.
В нём записан только реально исполнивший Codex.48.505s; usage в bundle.json,
cached input является частью input. Стоимость USD неизвестна.

Хеши обоих YAML до/после native совпали. Последующий настоящий workitem status
вернул needs_more_evidence: intake_completeness и implementation_verification
остались незакрытыми. Этот вызов сам записывает производный статус WorkItem;
его эффект измеряется отдельно от неизменности YAML во время native сессии.
Ни запись файла, ни planned не названы done/приёмкой владельца.

Предел: status/inbox/next/explain в снимке — общие проекции проекта. В explain
focus=null и посторонний product outcome19/20; это не завершённая квалификация
всего протокола4+1 для одной работы. Нет доказательства live Qwen, полного
native workflow или универсального переключения без потерь. #611 остаётся открытой.

После пробы typecheck, ESLint целевого файла и build прошли; это не полный продуктовый CI.

В bundle.json сохранены регистрация, отказ Qwen, native receipts чтения/правки,
хеши, usage и последующий статус; точные драйверы — harness.source.txt.
