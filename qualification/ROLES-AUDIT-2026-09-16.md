# Аудит 42 ролей — 2026-09-16 (P1 №10 продуктового ревью)

Ревью 16.09 предположило архитектурную инфляцию ролей: «42 объявлено → возможно ~27 используются →
~15 исторических, надо резать». Проверка ДО реза (дисциплина «сначала замерь»): сколько из 42 ролей
реально задействовано и где.

## Метод
Список ролей — `registry/agents.yaml` (42). Для каждой проверено, задействована ли она в:
1. workflow-контрактах / гейтах (`registry/workflows.yaml`, `quality/gates.yaml`) — роль меняет ход
   исполнения;
2. модели контуров (`registry/product-operating-model.yaml`) — роль-владелец типа работы/контура;
3. eval-кейсах (`evaluations/agents/`) и определениях агентов (`agents/**`).

## Результат
- **42 роли — все задействованы. Лишних (исторических/vestigial) НЕ найдено.**
- **32** роли встречаются ПРЯМО в workflow-контрактах / гейтах.
- Оставшиеся **10** (`agent-creator`, `data-engineer`, `fullstack-developer`, `incident-analyst`,
  `observability-engineer`, `performance-reviewer`, `regression-analyst`, `test-engineer`,
  `user-researcher`, `workflow-designer`) не встречаются в стадиях workflow напрямую, но завязаны
  иначе: роль-владелец контура/типа в `product-operating-model` (7 из 10) и/или мета-роли
  (`agent-creator`, `workflow-designer`, `incident-analyst`) — у КАЖДОЙ есть eval-кейс и определение
  агента. То есть «не в workflow» ≠ «не используется».

## Вывод
Опасение ревью данными **не подтверждается**: инфляции ролей нет, резать нечего. Роли оправданы либо
исполнением (workflow/гейты), либо владением контура, либо как мета-инструменты — и каждая покрыта
eval-кейсом (инвариант «новый агент без eval не принимается» держит это и вперёд).

Это честный итог аудита: правок кода не требуется. Если в будущем появится роль без eval и без
единой ссылки — её и надо будет разбирать; сейчас таких нет.
