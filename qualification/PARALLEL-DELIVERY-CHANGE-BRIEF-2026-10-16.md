# Параллельный прогон: политика и настоящая доставка

- Результат: явный `--parallel` сохраняет выбранные provider/model/base/max_steps и ограничения исполнения; готовая интеграция доставляется существующим контроллером Intent/Receipt.
- Пути: `parallel_live_dispatch.py` → изолированные package runners → fan-in → durable report → `_deliver`; CLI передаёт существующие флаги.
- Инварианты: original checkout не изменяется; writer ≠ judge; нет скрытого fallback; base SHA и aggregate относятся к точной интеграции; без durable барьера нет внешних действий.
- Отказы: неподдерживаемый provider/runtime; недоступная база/approval/budget; failed package/merge; потерянный integration clone; неполная/неподтверждённая доставка.
- Доказательство: реальные временные Git-репозитории, настоящие package commits/fan-in, инъектированные модели и внешняя доставка, неизменность исходного checkout; положительные и отрицательные проверки.
- Доказательство политики: выбранные параметры достигают runner; отказ до клонирования/моделей; requested PR без подтверждённого Receipt не возвращает успех.
- Очистка: принадлежащие прогону package clones удаляются; готовый integration source сохраняется до завершённой канонической доставки, не исчезает в `finally`.
- Не входит: автоматическая декомпозиция/выбор параллельности, запуск нативных Codex-сессий, изменение scheduler, новые provider adapters, paid model calls и настоящие GitHub PR в тестах.
- Проверка: целевые тесты → один независимый review (≤5 находок, одна итерация) → целевой/core smoke → все обязательные проверки CI на точном head. Отдельный локальный full не дублируется: состав тестов, гейты и среда исполнения не менялись; реальные Git/FS/Intent риски покрыты целевыми проверками, по нормативу #1306.

## Оставшиеся границы

- Общий/пакетный бюджет пока не обеспечивается этим параллельным путём: явное ограничение отклоняется **до** клонов и моделей. `max_steps` ограничивает цикл реализации, не сумму author/review/fix/retry и не доллары.
- Автоматический запуск нативных Codex-сессий не реализован этой правкой. Профиль runtime и команды не считаются доказательством spawn/join/cancel.
- Сохранён canonical integration source; durable сохранение игнорируемых package receipts/usage перед очисткой package clones ещё не доказано. До отдельной правки сохранения declared artifacts и изоляции usage context реальные параллельные расходы нельзя выдавать за измеренные.
- Контролируемая расписка не заменяет продуктовую приёмку; USD, активное время человека и owner acceptance неизвестны.
