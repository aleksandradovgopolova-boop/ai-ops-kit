# Git-объект пакета сохраняется до cleanup

Технический критерий восстановления: если пакет вернул настоящий commit SHA, этот commit и дерево остаются доступны в Git исходного репозитория после частичного отказа и удаления disposable clones. Receipt содержит точную локальную checkpoint ref; запись SHA без Git-объекта не объявляется сохранённым результатом. Проверка полного восстановления/повторного исполнения не подменяется этим критерием.

Пути: run_live_concurrent → _preserve_package_artifacts (reported package SHA/gate/usage baseline) → local fetch Git-объектов из своего disposable clone → atomic compare-and-set checkpoint ref в исходном Git common store → readback → прежние usage/receipt durable writes → cleanup. Ready integration и обычная доставка остаются прежними. Неуспех retention блокирует cleanup/delivery и сохраняет последние clones.

Инварианты: не checkout/cherry-pick/merge/main rewrite, не remote push; refs/ai-ops/parallel/<run hash>/<package hash> не являются ветками доставки. Ref нельзя перезаписать другим SHA даже при retry/race. Корректный repeat того же checkpoint идемпотентен. Callback может вернуть unready/fail commit — он сохраняется для диагностики, но не превращается в pass/fan-in/ready. Неотслеживаемые файлы/credentials не копируются: fetch переносит только commit graph. Утверждения о Git durability ограничены поддержанным Git/fsync; при непроверяемой/старой версии последняя исходная копия сохраняется.

Durability: Git>=2.36, per-command core.fsync=objects,reference и core.fsyncMethod=fsync (без изменения repository/global config), затем atomic update-ref с ожидаемым old SHA и readback. Local fetch явно отключает tags/FETCH_HEAD/submodules/auto-maintenance/commit-graph/prune; новые фоновые Git workers не запускаются. Правило сверено по установленному git-config manual Git2.55 и [официальному manual Git2.36](https://git-scm.com/docs/git-config/2.36.0): objects включает loose/pack, reference фиксирует refs, macOS default writeout-only недостаточен для этой гарантии. Это не испытание power-loss конкретного hardware.

Failure modes: SHA существует только в удаляемом clone; fetch/atomic ref write/readback failure; несовпадающая существующая ref; неподдержанный Git; receipt fault после сохранения объектов/идемпотентный retry. Все эти случаи не разрешают удалять последнюю непроверенную копию. Receipt отражает только фиксированный checkpoint_failure stage code, не Git stderr/секретные данные.
