# #1278 — контролируемый сбой доставки

Исполнитель AI; код Кита — main `4f74694c2b7211110352318168dfb21c94339950`
с локальным исправлением отзыва из этого PR. Изменённая governance-функция в REST-
сценарии не используется: проверяются существующие delivery API. `source_commit`
в result.json — SHA созданного локального fixture-коммита, не ревизия Кита.

До запуска сохранены preregistration, бюджет и пределы. Оригинальный исполнявшийся
harness сохранён как текст; он поднимает настоящий HTTP-сервер только на loopback,
использует fixture-token только в своём процессе и не обращается к настоящему GitHub.
`push=False`; в корне отдельного fixture настоящий Git-репозиторий.

Наблюдения:
- `_deliver` с незафиксированным RunHandoff: blocked-lifecycle, HTTP-запросов нет.
  Это инъекция отказа durable-барьера, не SIGKILL живого агента.
- POST создал одну заявку в fixture-сервере, но вернул битый JSON. Клиент вернул
  outcome_unknown; ошибка ответа не стала ни успехом, ни утверждением «не создано».
- reconcile нашёл существующую заявку и тот же полный SHA. Повтор open_draft_pr
  вернул updated: всего один POST, одна созданная заявка, delivery_id сохранился.
- Отдельные regression tests этого PR доказывают approve→revoke→повтор дважды:
  внешний эффект отсутствует. Человеческие решения там синтетические, не приёмка.

Воспроизведение из корня checkout: создать собственный пустой `work/`, затем запустить
Python с `PYTHONPATH=.` и этим `harness.source.txt`. Каталог fixture обязан отсутствовать;
скрипт не перезаписывает предыдущий результат. Нужны stdlib, PyYAML и Git; моделей нет.

Ограничения: не проверены настоящий процессный crash/native agent resume, надёжность
GitHub и принятая владельцем продуктовая работа. Уже выполненный внешний эффект
не становится атомарно обратимым. Полномочия не расширялись. #1278 остаётся открытой.

## Настоящее прерывание процесса (отдельный preregistration)

`process-*`: настоящий Kit pipeline с deterministic mock proposer, локальным bare
Git и loopback API. Перед внешним `_deliver_pr` процесс остановлен SIGTERM (exit-15),
после durable DeliveryIntent. На тот момент POST=0. Обычный `resume --reevaluate-only
--open-pr --execute` завершился delivered/opened; повтор — delivered/updated.
Одинаковы delivery_id, worktree, branch и полный SHA; created_count=1.
Прецедент не переносится на живой native agent или настоящую продуктовую работу.
No paid/native model calls; cost/run_cost null не выдаются за общую цену0. Внешнее
действие в этом сценарии — запись в контролируемый локальный API и push в локальный
bare Git. Это проверка восстановления реального lifecycle, не GitHub availability.
Сводка — проекция полей двух stdout, исходные полные журналы сохранены в рабочем
каталоге исполнителя. Воспроизведение process-harness.source.txt аналогично первому
harness, в новом пустом work-каталоге; бюджет до330s, без живых моделей.
