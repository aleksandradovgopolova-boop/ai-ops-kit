# Диагностический прогон — где трубопровод протекает наружу (one-feature-end-to-end #958)

Прогон 2026-09-15 на полигоне `~/ai-ops-cockpit` («Окошко», кит 4.3.2, `communication.audience: product`).
Первая работа направления `one-feature-end-to-end` (эпик #958), под product-freeze: НЕ строить, а
ЗАМЕРИТЬ, где кит показывает человеку внутреннюю кухню вместо продукта. Вёл опсик; «глаза нового
пользователя» применял опсик (оговорка ниже). Образец метода — leak-находки owner-speaks (#863/#864/#865).

## Метод

Провёл крошечную реальную задачу «показывать номер версии приложения в настройках» по естественному
пути нового пользователя (specify → plan → run → …) и снял человеко-обращённый вывод ДОСЛОВНО; плюс
команды, которыми кит должен советовать и показывать готовность (`advise`, `propose`, `inbox`,
`status`, `explain`, `run`-превью). Также использованы дословные выводы сегодняшнего прогона #745.
Важно: аудитория УЖЕ `product` — значит утечки ниже это реальные пробелы, а не забытая настройка.

## Утечки по пяти исходам (дословно)

### Исход 1 — `one_input_hides_the_pipeline` (единый вход скрывает трубопровод)
- **Внутренний feature id в лицо:** `--feature wi-7cf4f63f098d` (в каждом прогоне новый случайный id).
- **CLI-механика:** `./ai-ops specify "…" --feature … --answers "зачем=…; что=…"`, `--signals`,
  `потом запускай: ./ai-ops plan …` — пользователь видит флаги, синтаксис и САМ трубопровод
  (specify → plan → run → review), а не один вход «что изменить?».
- **Намёк на YAML:** «открывать файл не обязательно» — сообщает, что за этим стоит файл.
- **`status` сыплет механикой:** «план расходится с **заявками**», имена веток/рабочих копий
  `ai-ops/real-mac-app; ai-ops/calm-top-bar; ai-ops/quick-open-palette`, «координация команды
  включается **публикацией**».
- **`explain` тоже:** «две **ветки** перепишут одно место», внутренние id работ `calm-top-bar,
  quick-open-palette`.

### Исход 2 — `verified_is_shown_as_trust_not_gate_list` («Verified — вот почему»)
- Готовность подаётся счётом гейтов: «**гейты: проверено машиной 3 из 3; мнением не закрыт ни один**»
  (прогон #745), а не «Verified — вот почему» (продуктовое решение / архитектура / тесты /
  безопасность проверены). `run`-превью «если все проверки пройдут» — нейтрально, но итоговое
  доверие человеку как продуктовый факт не собрано.

### Исход 3 — `risk_selects_the_process_not_the_human` (риск выбирает процесс, не человек)
- Человека просят ЗАЯВИТЬ размер/риск, и это подано через СТАДИИ/УРОВНИ: «тяжесть задачи (**size/risk**)
  не заявлена — при эскалации уровень станет **L1 ENGINEERING** и добавится ещё **9 разделов**»;
  на другом пути — **L0 QUICK**. То есть риск→процесс протекает наружу именно процессом (уровни,
  разделы), а не спрятан за вопросом «насколько это опасно?».

### Исход 4 — `after_merge_kit_shows_what_happened_to_the_product` (outcome после merge)
- Поток заканчивается на «открою черновой запрос на слияние». Нет обещания/шага «после слияния я
  вернусь и покажу, что стало с продуктом». Механизм есть (`readout`/outcome-contract), но в
  естественный путь не вплетён — новый пользователь его не увидит.

### Исход 5 — `kit_recommends_what_the_product_needs` (кит советует, что нужно ПРОДУКТУ)
- `advise`: «Нашла 6 советов **по инженерной части**… Проект не имеет **declared окружений**…
  добавьте local + production в **.ai-ops.yaml**» — совет про инженерию/конфиг, не про продукт.
- `propose`: «предложение **по фундаменту**… контур **'product_strategy'**: нет обязательных
  **источников истины**: **context/product/ProductOverview.md**… **decisions/registry.yaml**…
  **Storybook** не настроен… превью Storybook в PR доставляю отдельным **workflow**» — рекомендации
  про фундамент/механику КИТА, а не «что нужно продукту» (возможности, ценность, следующий шаг).
- Итог: когда кит «советует», он говорит О СЕБЕ (контуры, YAML, источники истины, Storybook,
  workflow), а не о продукте пользователя. Это ровно диагноз ревью («Kit слишком много рассказывает
  о себе»). Исход 5 не выполнен.

## Счёт

**Замерено ~14 конкретных мест утечки** трубопровода наружу, распределены по всем пяти исходам
(1: 5, 2: 1, 3: 1, 4: 1, 5: 3+). Ни один из пяти исходов на естественном пути пока не выполнен —
что и ожидаемо для стартового замера направления.

## Кандидатные точечные работы (из утечек; НЕ заведены все — product-freeze, берём по одной)

1. **(исход 1)** specify не показывает человеку feature id и CLI-механику; вход — одна фраза, id и
   команды скрыты. ← взято первой активной работой направления.
2. (исход 1) `status`/`explain` говорят продуктом, а не заявками/ветками/worktree.
3. (исход 3) размер/риск — вопрос «насколько опасно?», без утечки уровней/разделов (L0/L1, «9 разделов»).
4. (исход 2) готовность как «Verified — вот почему» (свод доверия), а не «гейты N из M».
5. (исход 4) в конце пути — обещание/шаг «после слияния покажу, что стало с продуктом» (вплести `readout`).
6. (исход 5) `advise`/`propose` советуют, ЧТО НУЖНО ПРОДУКТУ (возможности/ценность), а не про фундамент кита.

## Оговорки честности

- «Глаза нового пользователя» применял опсик, не сторонний человек — окончательная планка UX за
  живым внешним пользователем либо записанным сценарием.
- Аудитория была `product` (не debug): утечки реальны при штатной настройке.
- Замер, не стройка: ни одна утечка здесь не чинилась — фиксы идут отдельными работами под исходы.

## Вердикт / дальше

Направление получило измеренную стартовую картину: ~14 утечек, все пять исходов пока false. Первой
активной работой взята утечка исхода 1 (feature id + CLI-механика в specify). Остальные — кандидатами
в бэклоге направления, берём по одной под product-freeze.
