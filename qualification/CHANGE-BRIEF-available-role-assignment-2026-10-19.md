# Назначение допущенной API-модели с локальными предпосылками

Критерий технической приёмки: в существующем openai-compatible runtime без явного model роутер выбирает самую дешёвую допущенную для роли модель среди поддержанных API-провайдеров с настроенным локальным ключом. Недоступный дешёвый кандидат не скрывает доступного допущенного; фильтр применяется также к fallback/escalation и writer≠judge re-resolution. Нет подходящих кандидатов или ошибка назначения — explained blocked-preflight,0model callbacks, без неявного passthrough. Результат назначения виден в отчёте; рекомендация не называется actual spawn.

Пути: model_router.plan_run/resolve (роль, class, qualification, economics, independence) → ai_ops_run_lifecycle._resolve_models (canonical provider_endpoints.key_available/endpoint_for) → прежние JIT trust/rotation gates → make_openai_provider → _build_run_proposers и execution pipeline. Явный model и остальные providers сохраняют прежний путь. Pure/offline plan_run без optional available_providers сохраняет прежнее поведение.

Инварианты: registry qualifications/classes остаются единственным допуском роли; conditional не становится strict qualified, false_green>0 не проходит. Наличие ключа — только локальная предпосылка, не auth/service health: online_health=null. Значения ключей/новые credentials не передаются/не логируются. Trusted-primary отказ не обходит новый кандидат; существующие budgets, isolation, approvals и writer≠judge сохраняются. Новый scheduler не создаётся. CLI complexity-routing остаётся в прежнем поддержанном API пути; самостоятельное CLI-назначение без API-reviewer здесь не обещается.

Failure modes: отсутствующий primary key при доступном qualified fallback; пустой/unknown provider set; independence re-resolution возвращает исключённый provider; filtered fallback/escalation; потеря ключа/ошибка router или trust перед применением. Явный override не заменяется автоматикой.

Доказательство: RED на прежнем runtime (положительный сценарий не получает доступную qwen вместо недоступной deepseek; пустой набор не блокирует passthrough); pure planner tests — qualification/strict judge/independence/fallback/empty set без изменения registry; actual selected provider callable вызывается через настоящий proposer boundary с offline marker, без native/paid calls.
