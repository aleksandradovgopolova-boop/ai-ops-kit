# Decision Plane #1246 — завершение Jev R&D и следующий шаг

По решению владельца тесты Jev на этом этапе завершены. Рассматривался только бесплатный
classifier.dev. Production-интеграции нет; результаты отрицательные для подключения
проверенной конфигурации, а не утверждение о модели на любых задачах.

## Что выполнено

- #1247: current / LLM / Jev и heuristic сравнили на одном 20-case smoke; дополнительно
  проверили ceremony на 24 independently authored задачах и downstream model/effort на 12.
  Unsupported baseline, неизвестные цены и ошибки явно отражены, не заменены успехом/нулём.
- #1253: общий offline harness, held_out, confusion matrix, latency, token/context,
  cost per 1k (null при неизвестной цене), HCER, unsafe, fallback/abstain, source identity,
  машинные и человекочитаемые отчёты, тесты. Готово к review; закрытие через merge.
- #1249: исследовательский результат **park**. На новой ceremony выборке исходные правила
  20/20; raw Jev 15/20 с пятью unsafe, LLM 19/20 с одной unsafe. Policy floor исправляет
  ошибки, но действующий deterministic путь уже даёт верный результат.
- #1250: исследовательский результат **park**. После явно задокументированного protocol
  repair оба пути 7/7 исполняемых held_out ответов; Jev увеличил общий input на 7,7%,
  выигрыш latency не подтверждён. Первый диагностический прогон сохранён отдельно.

Источники: [ceremony verdict](VERDICT-2026-10-05.md),

Smoke выбора agent owner не покрывает skill selection, lazy injection или downstream quality.

## Следующий шаг — #1251, без новых тестов Jev

[Исходная граница уже проверена](CONTEXT-AUDIT-2026-10-05.md): sequential workflow передаёт
только выбранного агента; обнаружен отдельный пробел передачи uses_skills. Следующее полезное
изменение — проследить и обеспечить skills binding до конкретного runtime, а не добавлять
ещё один selector для уже детерминированного owner.

Проверить полезность lazy context injection, сравнив текущую загрузку с выбором 1–3
релевантных agent/skill. Сначала измерить действующий footprint и найти реальные задачи,
где загружается лишнее. Если избыточной загрузки нет, зафиксировать park без новой абстракции.

Если есть измеряемая проблема: сформировать новый корпус с заранее размеченными обязательными
ролями/skills; deterministic selection использовать первым, LLM candidate — только для
недетерминированных случаев. Измерять фактически отправленный контекст, токены и результаты
исполнения, а не сумму размеров markdown-файлов. Mandatory judge/gates добавляются policy
независимо от кандидата; неуверенный/невалидный выбор расширяет контекст. Платный Jev и новые
прогоны бесплатного Jev в следующий шаг не входят.

Критерий решения: меньше фактического контекста при сохранении downstream качества;
критичный reviewer/skill не исчезает, ошибка/таймаут закрываются безопасно. Малого smoke
недостаточно для production ship.
