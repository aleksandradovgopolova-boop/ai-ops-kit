# #1251 — исходная граница контекста без Jev

Проверен реальный `orchestrator.run_workflow` с recording mock provider в отдельных
временных child roots: 11 workflow, 93 вызова, 251 226 UTF-8 байт суммарного prompt.
Это фактически переданный аргумент провайдера, а не сумма размеров файлов. Сетевых/model
вызовов нет. Токенов tokenizer/usage нет; качество исполнения и экономия не измерены.

[Машинный capture](context-boundary-audit-2026-10-05.json) содержит source identity,
hash модуля, workflow/stage/owner, размер и hash каждого prompt, наличие полного тела
owner и полных посторонних agent/skill bodies. Синтетическая задача одинакова, предыдущие
артефакты — mock, gates не получают поддельных положительных evidence.

Результат: ни один из 93 prompt не содержит полного тела другого агента. Существующий
stage owner уже выбирается детерминированно, `build_role_prompt` инжектирует его одного.
Оптимизация «убрать весь каталог» на этой границе не имеет baseline проблемы. Порядок
стадий и обязательные reviewer/gates задаёт workflow; semantic selector для них не нужен.
Частичные упоминания агентов этим exact-body сравнением не измерены.

На 11 стадиях есть `uses_skills`; полный skill body не передан ни в одном из 93 вызовов.
Это конкретный пробел между объявлением и исполнением в sequential workflow API,
а не доказательство, что skills отсутствуют во всех native agent/runtime путях.
Часть skill ids может не иметь тела в пакете; молча объявлять их подключёнными нельзя.

Следующее полезное изменение кита: проследить разрешение uses_skills до конкретного runtime,
выбрать одного владельца этой ответственности, обеспечить передачу доступного skill перед
вызовом и безопасное поведение при отсутствии. Нельзя решать эту проблему добавлением
ещё одного probabilistic роутера. После этого измерить действительные model tokens и
качество на новых заданиях. #1251 остаётся открытой: downstream quality, token savings,
расширение контекста при неуверенности ещё не квалифицированы.

Проверенная процедура: загрузить registry/workflows и agents; для каждого workflow вызвать
run_workflow с пустым TemporaryDirectory, одной фиксированной задачей и provider callback,
сохраняющим входной prompt и возвращающим существующий mock_provider(prompt). Проверить
число вызовов == число стадий. Для каждого prompt сравнить полные тела agent_body и
skills/*/SKILL.md, записать UTF-8 размер и SHA256. Source identity фиксировать через
существующий decision_eval.source_identity. Не использовать mock результаты как evidence
качества или разрешения gates. Временные записи удаляются после каждого workflow.
