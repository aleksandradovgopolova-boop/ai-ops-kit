# Decision Plane: бесплатный Jev, LLM и обязательный уровень

**Решение по ceremony: park — оставляем существующий код, Jev в рабочий маршрут не добавляем.**
Свободное предложение Jev получает reject: есть понижения обязательного уровня.
Jev + deterministic floor технически проходит эту проверку, но результата лучше текущего кода не даёт.
По model/effort и agent/skill — continue experiment; маленький smoke не является квалификацией.

## Главный результат на новой выборке

24 новых кейса: 4 development / 20 held_out. Отдельная AI-сессия создала и вручную разметила
выборку без доступа к старому корпусу, промпту и результатам; знала действующие правила.
Это независимость автора примеров, не человеческая экспертная разметка.

| Вариант | Верно на held_out | Понижения обязательного уровня | Ошибки с уверенностью ≥0.9 | p50 / p95 wall latency |
|---|---:|---:|---:|---:|
| Текущий код | 20/20 | 0 | Не применимо | <0.01 / <0.01 мс |
| Бесплатный Jev | 15/20 | 5 | 0 | 1035 / 1184 мс |
| LLM baseline | 19/20 | 1 | 1 | 12130 / 15638 мс |
| Jev + floor | 20/20 | 0 итоговых; 5 исходных | 0 исходных | capture + измеренный policy overhead |
| LLM + floor | 20/20 | 0 итоговых; 1 исходное | 1 исходная | capture + измеренный policy overhead |

Guarded варианты получены из тех же ответов: повторных вызовов provider нет. Policy вычисляет
минимум из signals через действующую classify, а не читает expected / allowed_by_policy.
Итог не ниже `max(предложение, floor)`; при abstain выбирается deterministic fallback.
Исходные ответы/уверенность и ошибки сохраняются отдельно; override снимает confidence модели.
Policy сама не подтверждает качество предложения и не разрешает ship.

Jev пропустил пять обязательных L3 в held_out, уверенность 0.25–0.82. LLM пропустила один
обязательный L3 с уверенностью 0.98. HCER без отдельного safety-счётчика скрыл бы проблемы Jev.

## Доступ и границы измерений

Jev: только бесплатный anonymous classifier.dev, actual model `jev-1.13.0`.
Все 24 ответа получены без транспортных ошибок, реальные credentials прокси не передаются.
Цена для anonymous пользователя — 0; экономика оператора сервиса не исследуется.

LLM: установленный Codex CLI, requested model `gpt-5.6-sol`, low effort, schema output,
изолированный каталог, без tools. Все 20 held_out ответов получены; один development вызов
завершился ошибкой, она учитывается как abstain. Выборочно повторов не делали.
Actual revision alias и стоимость подписки неизвестны. Claude не использован: организация
отключила подписочный доступ; configured default Codex также был недоступен, поэтому доступная
модель явно зафиксирована в capture.

LLM wall latency включает запуск CLI и его системный контекст; Jev latency — полный HTTP-запрос
через прокси. Это сравнение измеренных маршрутов, не чистой скорости моделей. Средний input
на held_out: Jev 660.9 tokens, LLM 12938.4 tokens (включая системный контекст CLI).
Сравнения денег/production SLA по этим числам не делаем.

## Три точки на исходном smoke

20 авторских синтетических задач; [сравнение трёх providers](three-provider-smoke/report.md).
Held_out ceremony: current 6/6, Jev 5/6 с одним unsafe, LLM 5/6 без unsafe.
Model/effort и agent owner: Jev и LLM по 2/2 на каждой точке. Current model/effort — abstain,
а не измеренное проигрышное качество; текущий механизм generic effort не выбирает.
Один LLM development вызов завершился ошибкой и записан в отчёте. Skill selection и downstream
успешность выбранной модели не измерены; расширять обещания по двум примерам нельзя.

## Что решаем дальше

На ceremony всё уже детерминировано по тем signals, которые получены на входе. Обращение к
Jev добавляет сеть и контекст, а улучшения над кодом здесь нет: эту точку паркуем.
Следующий осмысленный эксперимент — выбор модели/effort или agent/skill там, где правила
не дают однозначного ответа; нужны независимые эталоны и проверка итогового качества работы.
Это отдельные #1250 / #1251, без production-проводки и без обязательной зависимости Jev.

Отсутствие итоговых unsafe с floor действует лишь при достоверных явных signals. Извлечение
риска из текста и потеря/подмена signals не проверены. Авторский корпус и знание разметчиком
правил не доказывают production safety. Решение о ship остаётся за владельцем после квалификации.
