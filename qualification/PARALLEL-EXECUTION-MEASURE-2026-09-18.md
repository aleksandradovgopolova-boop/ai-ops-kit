# Замер: «пакеты выполняются по-настоящему одновременно» (2026-09-18)

**Повод.** Владелец попросил взять из ROADMAP («Дальше») направление «пакеты выполняются
по-настоящему одновременно, а не по очереди». Метод кита — сначала ЗАМЕР, не постройка: проверить по
коду на текущем main, что из этого УЖЕ есть, а где реальный остаток.

## Что построено (проверено по коду)

- **Opt-in `ai-ops run --parallel`** проведён в контур. CLI (`ai_ops_kit/cli/ai_ops_cli_commands.py`,
  #542) при явном `--parallel` зовёт `engine/parallel_live_dispatch.run_parallel_live`. Дефолтное
  поведение `run` не меняется — конкурентность только по явному opt-in.
- **Настоящая конкурентность.** `engine/parallel_live.run_live_concurrent` →
  `engine/parallel_executor.execute_parallel` исполняет пакеты на
  `concurrent.futures.ThreadPoolExecutor(max_workers=max_parallel)` (bounded ≤2): независимые группы —
  конкурентно (`submit`/`as_completed`), зависимые — по topo-порядку, хвост группы >2 — сериализованно.
- **Изоляция.** Каждый пакет исполняется в СВОЁМ disposable-клоне (`git clone` на base_sha,
  `make_isolated_package_runner`) → нет гонок git-worktree одного репо; основной checkout не трогается.
  fan-in — в отдельный integration-SHA; fail-closed на clone/checkout/fetch/merge.
- **Проведён и не дормантен.** `engine/parallel_live` убран из дормант-инвентаря 2026-09-06 (#542,
  `tests/contracts/test_dormant_inventory.py`): у него есть живой вызыватель.
- **Покрыт тестами.** `tests/unit/test_parallel_live.py::TestRunLiveConcurrent`
  (`test_concurrent_execution_with_per_package_clone`, `test_concurrent_fan_in_green`, очистка
  temp-клонов) + `tests/unit/test_parallel_live_dispatch.py`.

Замок писателя (`providers.orchestrator_providers.writer_lock_busy`, `engine/writer_contention`) —
НЕблокирующая ПРОБА занятости (сигнал для координации), а не сериализатор конкурентного пути.

## Реальный остаток (не код — граница среды)

Оркестрация, git и клоны параллельны. Но шаг ПИСАТЕЛЯ — вложенный `claude -p` — без API-ключа
упирается в ОДИН локальный writer на машине (машинный замок сериализации: параллельные `claude -p`
на одном локальном Клоде деадлочат). Значит само НАПИСАНИЕ кода в пакетах сериализуется, даже когда
клоны и гейты идут параллельно.

Это ровно та же граница, что зафиксирована как стоящая (`standing_boundaries`, раздел ROADMAP
«Later» — «параллельные писатели»): настоящая параллельность писателей даётся API-ключом
(`--provider anthropic`, тогда движок параллелен), субагентным фан-аутом (отдельные инстансы Клода)
либо несколькими машинами — а НЕ дополнительной постройкой в ките.

## Вывод

Направление «пакеты выполняются по-настоящему одновременно» **как МЕХАНИЗМ достигнуто** (opt-in
`--parallel`, конкурентное исполнение, изоляция клонами, fan-in, тесты). Строить нечего — это был бы
дубль уже построенного (`dp-001`). Остаток — граница среды (локальный writer без ключа), а не рабочий
пункт: снимается ключом/фан-аутом/машинами. ROADMAP-пункт обновлён под этот замер.
