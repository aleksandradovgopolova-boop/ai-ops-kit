# #1183: реальная обратная связь native Codex и профили двух стеков

Исполнитель AI. Это контролируемые проверки на изолированных копиях реальных
репозиториев, не принятые владельцем продуктовые работы и не выборка #1243.
Результаты, версии, hashes, неудачная попытка и исходные native receipts — bundle.json;
точные драйверы и прозрачный observer — harness.source.txt.

## Наблюдаемый эффект

На ии-среде 9f36ae3bcdc194ab62683737015efcff90f7d186 Codex 0.163.0 реально
вызвал apply_patch: кириллическое имя вызвало автоматический PostToolUse и отказ
настоящего ESLint (local/latin-identifiers, exit2). Получив замечание, тот же native
turn исправил имя, следующий автоматический hook дал0. Typecheck и build прошли.
RunPlan до/после одинаков; это само по себе не доказывает потребление WorkItem.

Применён candidate hook этой ветки, а не неизменённый stable v4.10.1. Прозрачный
observer записывал stdin/выход canonical hook и передавал их обратно без замены.
Native trust подтверждён AI через обычный /hooks после просмотра точного определения.
В receipts сохранён permission_mode=bypassPermissions при запрошенном workspace-write;
это проверка доставки обратной связи, без утверждения об изоляции или security boundary.
PostToolUse срабатывает после записи и не отменяет сделанную правку. Bash не покрыт.

Первая попытка не изменила файл: отдельно скачанному бинарнику не хватало sibling
code-mode-host. После зарегистрированного ремонта использован полный официальный
пакет, повтор занял36.027s; неудачная попытка27.901s сохранена, стоимость USD неизвестна.
Cached input — часть input, не дополнительное число токенов. Глобальный Codex не обновлён.
В git worktree проектный hook не обнаружился; успешный опыт — standalone clone.
Причина различия не установлена, все setup-попытки сохранены.

только для этого опыта, не названа принятой архитектурной политикой проекта.

На чистой копии реального Python-репозитория 671a814491b7424aa2a66cecd6952597e2cc8726

проверки: код приложения/БД не запускался, исходная рабочая копия не изменялась.

## Ограничения приёмки

Ранее реальный child CI отказал на отрицательной пробе (поле05.10, PR#1235).
Сегодня реальная локальная команда CI с детектированным repository-profile тоже
отказала на новом кириллическом имени (exit1) и прошла после восстановления (exit0).
Она использовала готовые зависимости того же lockfile, без нового npm ci.
Это не подменяет новое исполнение GitHub Actions.
Production rollout профилей, live Claude и owner acceptance не объявлены.
