# Добровольный учёт проектов

Kit по умолчанию ничего не отправляет и не записывает активность для этого счётчика.
Владелец проекта явно включает локальный учёт. Команды ниже работают без сети.
В установленной дочке пакет находится в `.ai/managed`, поэтому команды явно задают
локальный путь импорта; установленный системный Python-пакет не требуется.
Существующая регистрация `reach register` — отдельный механизм; её согласие не переносится.

## В проекте

Создайте ID один раз и сохраните файл в истории проекта обычным процессом PR:

```bash
PYTHONPATH=.ai/managed python3 -m ai_ops_kit.cli.adoption identity .
# Включите .ai/project/adoption-id.json в обычный коммит/PR проекта.
```

Все клоны, ветки и worktree одного проекта должны сохранять этот UUID. Если вы создаёте
отдельный продукт из шаблона/форка, удалите файл и выполните `identity` для нового продукта,
затем сохраните его в git. UUID псевдонимен: он позволяет связать выгрузки друг с другом.
Файл не содержит согласия, учёт после его создания по-прежнему выключен.

Только владелец конкретного проекта включает учёт на этой копии:

```bash
PYTHONPATH=.ai/managed python3 -m ai_ops_kit.cli.adoption consent . --owner
./ai-ops reach adoption . --json
```

`--owner` подтверждает, что решение принимает владелец. Учёт хранится в git-common этой
копии, распространяется на её worktree, но не на новые клоны. После согласия pipeline
отмечает дату завершённого прогона с фактическими вызовами; mock и preview не учитываются.
Другие способы работы пока не наблюдаются. Пустой след активности означает «неизвестно».

Сначала просмотрите состав, затем подготовьте файл и передайте его получателю сами.
Без дат preview/export/report выбирают последние 30 календарных дней UTC, включая
текущий неполный день. Выбранные даты видны в результате. Для другого периода задайте
обе даты `--start` и `--end`; одна дата без второй отклоняется до записи:

```bash
PYTHONPATH=.ai/managed python3 -m ai_ops_kit.cli.adoption preview .
PYTHONPATH=.ai/managed python3 -m ai_ops_kit.cli.adoption preview . --start 2026-10-01 --end 2026-10-30
PYTHONPATH=.ai/managed python3 -m ai_ops_kit.cli.adoption export . \
  --start 2026-10-01 --end 2026-10-30 --output /tmp/adoption-october.json
```

В файле только ID проекта и согласия, состояния установки/активности, даты и контрольная
сумма. Имена и пути репозиториев, задачи, код, провайдеры и личные данные не включаются.
Команда не перезаписывает существующий файл. Kit не отправляет его; сервера сбора пока нет.

Отзыв очищает локальные даты и останавливает учёт:

```bash
PYTHONPATH=.ai/managed python3 -m ai_ops_kit.cli.adoption revoke . --owner
PYTHONPATH=.ai/managed python3 -m ai_ops_kit.cli.adoption export . \
  --start 2026-10-01 --end 2026-10-30 --output /tmp/adoption-revoked.json
```

Передайте отзыв каждому получателю прежнего файла: до этого он об отзыве не знает. Импорт
отзыва блокирует повторную доставку прежнего согласия. Автоматически удалить чужие копии
невозможно. Другие клоны отзываются отдельно. Повторное `consent` начинает новую историю.

## У владельца Kit

Импортируйте полученный файл в локальный git-common реестр; принадлежность выбирается по
известным оператору фактам, по умолчанию unknown:

```bash
PYTHONPATH=.ai/managed python3 -m ai_ops_kit.cli.adoption import . /tmp/adoption-october.json --relationship external
PYTHONPATH=.ai/managed python3 -m ai_ops_kit.cli.adoption report . \
  --start 2026-10-01 --end 2026-10-30 \
  --owned /path/to/owned-project --external /path/to/known-external-project
```

Локальные пути нужны только для чтения уже разрешённых владельцами наблюдений. Они не
попадают в экспорт или сводку. Согласия в этих проектах команда отчёта не включает.
`--project` обозначает неизвестную принадлежность. Повторы одного UUID не увеличивают счёт.

Сводка разделяет локально наблюдаемые данные и непроверенные сообщения извне. Контрольная
сумма не является подписью: импортированный файл не подтверждает подлинность активности.
Активность импортируется только для точно совпадающего периода. Установки — след на дату
снимка, а не утверждение об исправности или сегодняшнем состоянии внешнего проекта.
Ошибки дают код 1, отказ выполнения — 2. Мировое число всегда неизвестно, даже если
наблюдений нет. Главная продуктовая метрика этим счётчиком не заменяется.

Полная модель доверия и ограничения: [архитектурное решение](../architecture/adoption-opt-in.md).

## Локальная проверка свидетельств

После отдельного согласия владельца можно проверить уже существующие артефакты одного
явно указанного проекта. Команда ничего не пишет и не отправляет:

```bash
PYTHONPATH=.ai/managed python3 -m ai_ops_kit.cli.adoption evidence .
```

Период по умолчанию — те же 30 календарных дней UTC; другой задаётся парой `--start/--end`.
Без действующего согласия установка и отчёт не читаются, команда возвращает код 2.

`installation.state=locally_consistent` означает, что VERSION и provenance согласованы,
а полный checksum manifest совпал с файлами managed. Это не аутентификация происхождения:
владелец локальной FS способен подменить одновременно файлы и manifest. Приватные source URL,
пути, тексты заметок и поля отчёта в вывод не включаются. Повреждение, drift, небезопасный
путь или отсутствие артефакта дают `unknown`. Файлы ограничены по размеру, ссылки не читаются.

`update.state=local_report_consistent` означает согласованный локальный отчёт о переходе
версий с успешным непустым smoke. Отложенный PR, rollback, failure, пустой smoke и no-op
не засчитываются. Старый отчёт не датирован: ни сегодняшняя проверка, ни mtime файла
не доказывают дату перехода; `updated_in_window` остаётся `unknown`.

Даты активности в прежнем state не имеют привязки к продуктовому evidence. Вывод явно
называет их `unattributed_local_dates`, а `verified_product_active` оставляет `unknown`:
ручная дата, неподтверждённый отчёт и внешний receipt не становятся доказанной продуктовой
работой. Команда не меняет прежние агрегаты/receipt v1 и не мигрирует сохранённые данные.
