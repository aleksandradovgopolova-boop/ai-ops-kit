# Стоимость и качество compiled контекста

`context_compiler` собирает пакет ДО вызова исполнителя. Дочка может добавить к обычному
отбору точные пути файлов и запреты в `.ai-ops.yaml`:

```yaml
context:
  required: [docs/api.md]           # целиком; отсутствие/вытеснение блокирует исполнение
  optional: [docs/examples.md]      # кандидат, может не уместиться
  forbidden: [docs/archive/**]      # glob, путь файла или каталог, включая правила кита
context_budget:
  run_tokens: 20000                 # до резервов 25% output и 15% tool loop
  session_start_tokens: 5000        # прежняя отдельная оценка стоимости старта
```

`required`/`optional` — относительные пути без `..`, glob только в `forbidden`. Запрет применяется
до чтения источника в payload, включая реальный путь symlink; выход за репозиторий запрещён.
Конфликт required/forbidden и некорректная декларация останавливают даже QUICK до writer.
Запрет действует и на переданный готовый bundle. При непустом forbidden hybrid остаётся
в режиме v1-only: его retrieval пока не умеет исключать пути до чтения. Причина записана в
context_hybrid.reason. Storybook-навигация также не добавляется: её агрегат не даёт проверить
отдельные источники.
Это граница compiled payload. Самостоятельные чтения native runtime и итоговый prompt провайдера
эта политика не ограничивает; для них нужны существующие runtime-инструменты доступа.

Отсутствие `context` сохраняет обычный отбор. Required не обрезается до кэпа. Optional и обычные
источники могут сокращаться (поле `truncated`) или вытесняться с причиной. Бюджет проверяет весь
скомпилированный текст, включая заголовки, и окно выбранной модели. Токены оценивает
`context_cost` по символам с поправкой на кириллицу; это не фактический usage токенайзера.
Остальные части prompt и чтения tool loop в эту оценку не входят. Превышение, missing required
и ошибка политики дают `context_resource.ok: false` в preflight до исполнения.

## Измерения

В `features/<id>/context-payload.yaml` и `run-report.json → context_payload` сохраняются
`resource_check`, `compiled_text_tokens_estimate` и `metrics`. Время `time_to_context_ms` реально
измеряется `perf_counter` от начала сборки до готовности текста (область названа в `timing_scope`).
Оно зависит от машины/кеша и не является SLA или временем поиска человеком.

`precision`, `waste`, `miss` по умолчанию `null`, статус `unknown`. Политика доступа не является
разметкой релевантности. Для оценки конкретного прогона нужна явная разметка источников:

```json
{
  "relevant": ["task", "docs/api.md", "docs/expected-but-not-selected.md"],
  "irrelevant": ["docs/examples.md"],
  "evidence": "ссылка или описание заранее подготовленной разметки этой задачи"
}
```

Её можно передать как `signals.context_relevance` в программный `run` или через CLI:

```bash
python3 -m ai_ops_kit.devtools.context_compile_cli /path/to/child \
  --signals '{"task_text":"Проверь API", "task_type":"QUICK"}' \
  --payload --relevance /path/to/labels.json --json --strict
```

Source id берутся из `included_items[].source`; `task` — сам текст задачи. Precision — число
включённых релевантных источников / число включённых; waste — оценочные токены нерелевантных
источников / оценочные токены всех источников (обёртки в эту долю не входят); miss — число
ожидаемых релевантных источников, отсутствующих в пакете / число всех ожидаемых релевантных.
Пустой знаменатель даёт `null`. Обязателен evidence и непересекающиеся списки. Если хотя бы один
включённый источник не размечен, статус `incomplete_labels`, все три доли `null`.
Неожидаемые/неразмеченные пропуски невозможно измерить. Доли относятся к source-набору compiled
payload, а не к семантике отдельных фрагментов или полноте ответа модели; сокращённый источник
считается включённым, факт сокращения виден отдельно. У заблокированного прогона это измерения
собранного кандидата; подача writer не состоялась.

## Повторить локальное доказательство

Из checkout кита, stdlib + PyYAML, существующий интерпретатор окружения:

```bash
python3 -m qualification.context_resource.run --output /tmp/context-resource-new-run
```

Каталог должен быть новым. Скрипт создаёт два настоящих git-репозитория и вызывает штатный
`ai_ops_run.run`: локальный детерминированный proposer получает compiled context и через
настоящий tool loop записывает файл в изолированную рабочую копию. Он не вызывает модель/сеть.
Положительный сценарий доказывает запись и отсутствие forbidden в контексте; малый бюджет —
ноль вызовов writer и отсутствие результата. Разметка fixture объявлена ДО обоих прогонов.
Сохраняются исходные файлы, labels, lifecycle/preflight/payload/run-report и `evidence.json`.
Это функциональное доказательство локального пути, без обкатки Claude/Codex и продуктовой
калибровки релевантности. Записанное свидетельство — `qualification/context_resource/evidence.json`.
