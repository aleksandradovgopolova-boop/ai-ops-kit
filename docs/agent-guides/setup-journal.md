# Установка: время ожидания и журнал

`python3 /путь/к/kit/installer/ai_ops.py setup /путь/к/проекту` по умолчанию даёт
всем подпроцессам вместе 150 секунд. Следующий шаг получает только оставшееся время;
диагностика, установка и фиксация файлов не получают каждый новый отдельный лимит.
Внешний исполнитель должен ждать дольше этого бюджета, например 180 секунд.
Если этого недостаточно для конкретного репозитория, увеличьте **оба** бюджета:
`setup /путь/к/проекту --timeout-seconds 240` и ожидание исполнителя свыше 240 секунд.
Завершение процессов и запись итога могут потребовать небольшого дополнительного времени.

До первого шага команда печатает путь к `.ai/runtime/setup/<попытка>/events.jsonl`.
В журнале — время начала/конца, длительность, исход и код возврата каждого шага,
исходная ревизия проекта и общий бюджет. Стоимость, токены и активное время человека
остаются неизвестными (`null`): установка их не измеряет. Это технический журнал установки,
а не регистрация владельческого прогона в квалификационной выборке.

Вывод каждого шага сразу направляется в соседние `<шаг>.stdout.log` и `<шаг>.stderr.log`.
При превышении времени частичный вывод остаётся на диске, установка возвращает код 1,
а следующие шаги не запускаются. На POSIX останавливается вся группа процессов шага,
включая дочерние процессы и Git hooks; на Windows останавливается прямой процесс.
Прерывание Ctrl+C или SIGTERM также сохраняет исход и вывод. После принудительного
SIGKILL итоговая запись может отсутствовать: последний `step_started` без соответствующего
`step_finished` показывает незавершённый шаг; успешным такой журнал считать нельзя.

Повторите ту же команду для новой попытки. Предыдущие журналы остаются, установка
заново проверяет целостность и пересчитывает дальнейшие шаги. Успех старого шага не
переносится без проверки. Неполная установка останавливает цепочку на диагностике;
её вывод сохранён в `doctor.stdout.log`/`doctor.stderr.log`. Автоматическое восстановление
повреждённого managed-слоя этим изменением не добавлено.

Журналы локальные: новая установка добавляет правило игнорирования, а собственный
коммит установки явно исключает этот каталог и в проектах со старым `.gitignore`.
