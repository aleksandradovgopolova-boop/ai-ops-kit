Коротко, по существу. Если нужен полный путь установки — [QUICKSTART.md](QUICKSTART.md);
подробности установки и требований — [guides/installation.md](guides/installation.md);

## Установка

### Как поставить кит в мой репозиторий?
Два пути.

- **В Claude Code с плагином AI Ops** — скажите в репозитории **«установи AI Ops»**. Скилл сам
  проведёт `init → doctor → onboard`, вводить команды руками не нужно.
- **Вручную** (CI, офлайн, без плагина) — это же и есть источник истины:
  ```bash
  python3 <путь>/ai-ops-kit/installer/ai_ops.py init .
  python3 <путь>/ai-ops-kit/installer/ai_ops.py doctor
  ./ai-ops onboard
  ```

### Что нужно на машине?
`python3` (3.12+) и `pyyaml`. Node.js — только для опции OpenSpec (включена по умолчанию,
выключается `openspec.enabled: false` в `.ai-ops.yaml`). Ключей провайдеров при установке не нужно —
они подключаются через env-референсы позже.

### Что появится в репозитории после установки?
- `.ai/` — managed-слой: реестры и контракты кита. **Не редактируйте его руками.**
- `.ai-ops.yaml` — ваш конфиг: впишите `project.name` и провайдеров.
- `.github/workflows/ai-ops-update.yml` — ежедневный PR с обновлением кита.
- `ai-ops` — точка входа для команд (`./ai-ops …`).

### Как понять, что установилось правильно?
`doctor` не должен ругаться. Дальше `./ai-ops onboard` один раз определит ваш стек и команды,
а `./ai-ops model .` покажет, что кит про продукт знает, а чего — нет.

## Обновление

### Как кит обновляется?
Через Pull Request, не молча. Джоб `ai-ops-update.yml` раз в день открывает PR с новой версией —
вы его смотрите и мержите сами. Тихая перезапись запрещена по построению (`silent_update: forbidden`),
поэтому обновление никогда не перетрёт ваши изменения без ревью.

### А обновит ли он мой репозиторий, пока я сплю?
Нет. Он только **предложит** PR. Пока вы не смержили — ничего в вашем коде не меняется.

### Как обновить вручную?
```bash
python3 <путь>/ai-ops-kit/installer/ai_ops.py update .
```
Для мажорной версии (ломающие изменения) — `update --force`; перед этим прочитайте
`MIGRATION_GUIDE_*.md`.

### Как узнать, что моя копия отстала?
Команда с кодом возврата, а не отчёт:
```bash
./ai-ops check-update
```
`0` — копия соответствует своей версии; `2` — отстала (разошлись версии/содержимое или managed-слой
правили на месте); `1` — проверить не удалось. Она уже стоит в `ai-ops-validate.yml` и **падает** при
отставании — CI не даст «исправлено в ките» тихо не доехать до вас.

## Настройка

### Можно ли править то, что ставит кит?
Managed-слой (`.ai/managed/`) — нет: его перезапишет обновление. Свои правки кладите в **`.ai/custom/`**,
а политику — в `.ai-ops.yaml`. При обновлении ваши кастомизации сохраняются.

### Как включить кит в CI?
Готовый snippet — в [QUICKSTART.md](QUICKSTART.md) (§4) и [guides/ci.md](guides/ci.md). Ключевое:
child-джоб ловит расхождения до мержа, а `check-update` держит копию в актуальном состоянии.

### Как поменять «уровень общения» кита?
В `.ai-ops.yaml`, блок `communication.audience`: `product` (по умолчанию) → `technical` → `debug`.
Или попросите словами: «рассказывай подробнее техническую часть».

## Ежедневная работа

### Как поставить задачу?
Словами, одной командой — кит сам выберет маршрут:
```bash
./ai-ops run "описание задачи" --execute
```
Не помните команду — наберите просто `ai-ops`. Основные: `status`, `next`, `review`, `resume`,
`explain`, `model`.

### Почему кит говорит «не готово», хотя тесты зелёные?
Это принцип, а не сбой: **нет доказательства → нет утверждения**. Кит не выдаёт «готово», пока
проверки не доехали до установленной копии, а не только до чтения кода. Спорьте с находкой —
закройте её или отметьте `declined` с причиной.

### Кто проверяет работу?
Не тот, кто её сделал: **writer ≠ judge**. Ревью независимо, evidence привязан к ревизии.

## Про сам кит

### Это стабильная версия?
Текущий канал — **qualification**, не `stable`. Кит работает, но `stable` требует полевых
доказательств на живых дочках и выдаётся только машиной — не авансом.

### Мои данные и секреты?
Секретов в репозитории нет по построению; провайдеры подключаются через env-референсы.
Конфиденциальные задачи не уходят внешним провайдерам — правило в `registry/routing-policy.yaml`.
