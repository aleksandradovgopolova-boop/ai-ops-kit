# Каталог фич продукта

Один достоверный список всех фич продукта — чтобы разобраться во ВСЕХ фичах из ОДНОГО места,
а не собирать картину по коду и тикетам. По каждой фиче: **что** она делает, **для кого**,
**как проверить**, какими поверхностями наблюдаема в коде и в каком она статусе.

Каталог **выведен из реестра фич** при генерации (схема `registry/feature-registry/
feature-registry.schema.yaml`), а не написан руками, поэтому не расходится с реестром молча.
В продуктовом репозитории источник — собственный реестр фич дочки; здесь, в самом ките,
своего продуктового реестра нет, поэтому каталог собран из ОБРАЗЦА
`registry/feature-registry/feature-registry.example.yaml` и служит демонстрацией формы.

## active (живёт)

### Экспорт отчёта (`export-report`)

- **Что делает:** Пользователь выгружает отчёт в CSV командой CLI или кнопкой в интерфейсе.
- **Для кого:** Аналитик, которому нужен отчёт вне продукта.
- **Как проверить:** `app export report --format csv` создаёт непустой CSV; тот же файл доступен из UI по кнопке «Экспорт».
- **Владелец:** team-analytics

### Вход пользователя (`user-login`)

- **Что делает:** Пользователь входит по email и паролю и получает сессию.
- **Для кого:** Зарегистрированный пользователь продукта.
- **Как проверить:** POST /login с валидными кредами → 200 и cookie сессии; неверные креды → 401.
- **Владелец:** team-identity

## planned (объявлена, кода ещё нет)

### Совместные рабочие пространства (`shared-workspaces`)

- **Что делает:** Несколько пользователей работают в общем пространстве с ролями доступа.
- **Для кого:** Команды, которым нужна совместная работа над одними данными.
- **Как проверить:** После приглашения второй пользователь видит пространство и объекты согласно своей роли.
- **Владелец:** team-collaboration

_Поверхности не заявлены._ Для `planned`-фичи это законно (кода ещё нет); для `active` — сигнал, что фича не связана с кодом.
