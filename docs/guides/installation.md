# Установка в свой проект

**Русский · [English](../en/installation.md)** · [Короткий старт](../QUICKSTART.md)

## Что подготовить

Git, Python 3.12+ с модулем `venv`/`pip`, существующий Git-проект с первым коммитом
и настроенным автором Git. Сохраните текущие изменения проекта перед установкой.
Доступ к GitHub и индексу Python нужен для получения исходников и зависимости.
Сначала прочитайте [LICENSE](https://github.com/aleksandradovgopolova-boop/ai-ops-kit/blob/main/LICENSE); для коммерческого использования текущего
кода требуется отдельная лицензия. Зависимость движка — PyYAML 6.0.3+.

## Новый путь: 3 команды

Экспериментальный вход для macOS/Linux из проверенного checkout. Git и Python
3.12+ с `venv`/`ensurepip` должны быть установлены; требуется доступ к PyPI для
существующей зависимости PyYAML. Устанавливаются только готовые wheel, без сборки
нового ПО. Если для платформы нет подходящего wheel, подготовка остановится.
Локальная проверка проведена на macOS arm64/Python 3.14; Linux и другие версии
Python ещё ждут проверки. Это не установка Python/Git на чистую ОС.

Из каталога, рядом с которым можно разместить кит (замените путь к проекту):

```bash
git clone https://github.com/aleksandradovgopolova-boop/ai-ops-kit.git
python3 ai-ops-kit/installer/bootstrap.py /absolute/path/to/your/project
source ai-ops-kit/.ai/runtime/bootstrap/venv/bin/activate
```

После clone проверьте полученный commit и код перед запуском. Первые две команды
готовят установку, третья делает окружение доступным текущей терминальной сессии.
Это те же предпосылки Git/Python, что у прежнего пути из пяти команд ниже.

`bootstrap` не заменяет установщик: он создаёт собственное venv внутри игнорируемого
`.ai/runtime/bootstrap/` checkout кита, устанавливает единственную зависимость из
`requirements.txt`, проверяет её и вызывает существующий `setup`. Подготовка не пишет
в глобальный или пользовательский Python, не меняет системный PATH, credentials,
правила доверия или разрешения. Повтор проверяет зависимость и переиспользует готовое
окружение. Чужие PYTHONPATH/PYTHONHOME не передаются дочернему Python; окружение
родительской сессии сохраняется. Затем выполняется штатный setup. Чужой каталог
окружения, занятая подготовка или ошибка pip дают видимый отказ до вызова setup.
Повреждённую среду helper не удаляет.

Для пробы без собственного проекта вместо второго/третьего шагов достаточно:

```bash
python3 ai-ops-kit/installer/bootstrap.py --demo
```

Он готовит ту же среду и запускает существующий [offline-пример](../../examples/first-session/README.md)
на временном sample; модель не вызывается. Активация нужна позже, если вы вызываете CLI вручную.

Если есть доверенный локальный кеш wheel, добавьте `--wheelhouse /absolute/path/to/cache`:
пакеты берутся только из него, без индекса. Подготовка использует обычный pip с
изолированными настройками, поэтому пользовательские PIP_INDEX_URL и pip.conf не
подхватываются. Для организации со своим индексом используйте прежний управляемый
путь ниже. Новый вход не устанавливает сам кит из PyPI и не загружает удалённый shell-скрипт.

## Прежний ручной путь: 5 команд

Выполняйте из каталога, рядом с которым можно разместить checkout кита. Замените
`/absolute/path/to/your/project` реальным путём к продукту. Это установка из текущего
`main`, а не из релизного тега; проверьте полученный commit и код перед запуском.
После clone можно читать файлы и проверять источник без выполнения установщика.

```bash
git clone https://github.com/aleksandradovgopolova-boop/ai-ops-kit.git
python3 -m venv ai-ops-kit/.venv
source ai-ops-kit/.venv/bin/activate
python3 -m pip install -r ai-ops-kit/requirements.txt
python3 ai-ops-kit/installer/ai_ops.py setup /absolute/path/to/your/project
```

Для уже проверенного checkout и подготовленного окружения нужен только последний
вызов `setup`. Это не «одна команда с чистой машины»: получение кода, зависимости
и подключение модели остаются отдельными шагами. Быстрая проба после первых четырёх
команд этого ручного пути: вместо `setup` запустите `python3 ai-ops-kit/examples/first-session/demo.py`.
Она создаёт временный проект и не меняет ваш продукт.

Пример выше — для macOS/Linux и shell bash/zsh. В PowerShell активация отличается:
`ai-ops-kit\.venv\Scripts\Activate.ps1`; полная проверка Windows этим срезом не проведена.

## Что setup делает автоматически

- Устанавливает `.ai/managed/`, `.ai-ops.yaml` и вход `./ai-ops`.
- Доставляет проектный контекст, команды/скиллы Claude Code, сгенерированные
  Codex-промпты и CI-шаблоны; готовит политику общения в `CLAUDE.md`.
- Проверяет целостность, определяет стек, готовит черновики и собирает первый план,
  если хватает фактов. Иначе сохраняет вопросы владельцу.
- Коммитит собственные служебные файлы. Продуктовые правки не входят в этот коммит.

Если задан `CODEX_HOME`, установщик также размещает промпты в его `prompts/`;
иначе сохраняет их в `.ai/generated/codex/prompts/`. Проверьте это до установки:
это не активация native adapter. Пример `demo.py` задаёт временный `CODEX_HOME`.

`setup` не получает credentials и не вызывает модель. Код `0` означает завершение
автоматизируемой части, а не готовность всей команды к работе: прочитайте остаток
«от тебя» и журналы `.ai/runtime/setup/`. При ошибке остановитесь на конкретном
шаге; повторный `setup` допускается, но не исправляйте проблему удалением managed.

## Что настроить один раз после установки

Проверьте факты о продукте и ответы на вопросы, поддерживаемого исполнителя,
его авторизацию/лимиты и разрешения. В `.ai-ops.yaml` проверьте project/providers,
не помещая секреты в отслеживаемые файлы. Уточните правила публикации и включите
применимые [CI-проверки](ci.md). Сама установка не даёт разрешения на публикацию.

Node.js нужен только для OpenSpec: опция включена в шаблоне по умолчанию.
Если OpenSpec нужен, поставьте совместимый CLI по его инструкции; если не нужен,
явно задайте `openspec.enabled: false` в `.ai-ops.yaml`. Установщик не ставит его
за вас. Демо не использует OpenSpec и не требует Node.js.

Новая терминальная сессия должна использовать Python с установленным PyYAML:
активируйте то же окружение перед вызовами `./ai-ops`. После нового пути это
`ai-ops-kit/.ai/runtime/bootstrap/venv/`; после прежнего — `ai-ops-kit/.venv/`. Открывая Codex/Claude,
проверьте проектные инструкции по [короткому старту](../QUICKSTART.md).
Эксперимент командных hooks по умолчанию выключен; native Codex adapter пока
`readiness=false`. Файлы инструкций не подтверждают полную автономность.

## Проверить и обновить

Из корня продукта, с активированным окружением:

```bash
./ai-ops doctor
./ai-ops model --json
./ai-ops status
```

`doctor` проверяет локальную установку, а не доступ к аккаунту модели или готовность
релиза. `model` показывает известное и неизвестное, а не выполняет продуктовую задачу.
Обновление — отдельное решение: изучите [каналы](../release-channels.md) и
`./ai-ops diff`, затем применяйте штатный `./ai-ops update`. Прямые правки
`.ai/managed/` остановят обновление; собственные правила храните в `.ai/custom/`.

Для разработки самого кита — [CONTRIBUTING](https://github.com/aleksandradovgopolova-boop/ai-ops-kit/blob/main/CONTRIBUTING.md).
