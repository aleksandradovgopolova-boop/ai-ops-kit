## Что сравнивалось

- **regex** — прежний разбор проверки слоёв дочки (`planning/architecture_invariants._regex_imports`):
  регулярное выражение по каждой строке. Остаётся способом по умолчанию.
- **tree** — `ai_ops_kit/context/js_imports.py`: синтаксическое дерево tree-sitter 0.25.2,
  tree-sitter-javascript 0.25.0, tree-sitter-typescript 0.23.2.

Единица сравнения — пара (файл, импорт). Файлы, которые дерево не разобрало, из сравнения
исключены (их читает regex, и в отчёте названа причина). Эталона нет: это сравнение двух способов,
а не полнота против истины, поэтому расхождения разобраны по категориям вручную и скриптом.

Команда (нужны опциональные пакеты; без них — код 2 «НЕ ИСПОЛНЕНО»):

```bash
git clone --depth 1 https://github.com/excalidraw/excalidraw && git -C excalidraw checkout 701b901a0f1ba3d0b390d9cdf63d112e25abac4b
python3 -m ai_ops_kit.devtools.jsts_import_compare excalidraw --json
```

Время — три прогона подряд, разброс в пределах 5%; Apple M4, Python 3.12, чтение диска не входит.
Полные сводки с примерами — `compare-excalidraw.json`, `compare-typeorm.json`.

**Что нашло только дерево — пропуски regex.** Все 677 и 1 344 пары — настоящие импорты:
многострочные `import {\n a,\n} from '…'` (674 и 1 344) и многострочные динамические
`await import(\n '…'\n)` (3). Построчный regex не видит инструкцию, у которой источник стоит не в
строке с `import`. Доля пропущенных импортов — **14,6%** (excalidraw) и **9,8%** (typeorm).

**Что нашёл только regex — почти всё ложные рёбра.**
- В комментариях — 8 и 50: JSDoc-аннотации `/** @type {import('next').NextConfig} */`. Это ссылка
  на тип, а не импорт модуля; для проверки слоёв это не ребро исполнения. Дерево её не видит —
  это сознательная граница, а не пропуск (см. ниже).
- Внутри строк — 25 (typeorm): примеры кода в шаблонных строках документации
  (`docs/src/pages/index.tsx:101`) и имена модулей как данные в codemod
  (`packages/codemod/src/transforms/ast-helpers.ts`). Это ложные тревоги regex.

**Время.** Дерево примерно в 10 раз медленнее, но укладывается в 1 секунду на 3 600 файлов —
для advisory-отчёта governance, который строится раз на прогон, это незаметно.

## Что дерево не разобрало (fallback на regex с причиной)

7 файлов из 4 344, все — `syntax-error` из-за пробелов грамматики tree-sitter-typescript 0.23.2
(новее версии нет на 12.11.2026):
- `export type * from "./x"` (синтаксис TypeScript 5.0) — `typeorm/packages/typeorm/src/index.ts`,
  `…/data-source/index.ts`;
- `importOriginal<typeof import("x")>()` — тесты excalidraw (`setupTests.ts`, `*.test.tsx`).

Дерево с ошибкой не используется даже частично: восстановленное дерево не доказывает, что из него
не выпал код. Такие файлы читает regex, и отчёт называет их число и причину.

## Границы

- Алиасы сборщика (`@/…`), `paths` из tsconfig и `exports` пакетов не разрешает ни один способ —
  их по-прежнему объявляют в `aliases` (схема `architecture-invariants`).
- JSDoc-ссылки на типы и `import()` с вычисляемым аргументом рёбрами не считаются.
- `.vue` и `.svelte` грамматикой не покрыты — их читает regex.
- Подключён только разбор для проверки слоёв дочки (`parser: tree-sitter` в объявлении). Граф
  `ai_ops_kit/context/repo_graph.py` (выбор тестов, контекст) по-прежнему читает JS/TS регулярками — перевод
  его на `js_imports` — отдельный шаг.
- Способ по умолчанию не изменился: дерево включается объявлением и требует опционального пакета.
