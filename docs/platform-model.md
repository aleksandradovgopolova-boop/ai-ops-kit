# AI Ops — модель платформы на одном экране

AI Ops — не библиотека инструментов, а **AI-native операционная система разработки продуктов**:
одна дисциплинированная платформа над множеством продуктовых репозиториев. Цель — **большой по
возможностям, маленький по числу механизмов, которые надо держать в голове одновременно**.

## Два плана

```
                      AI OPS — CONTROL PLANE
        (как создаём продукты, что обязано существовать, какие правила)
        ┌───────────────┬───────────────────┬───────────────────┐
        │   Standards    │  Product Registry  │     Policies       │
        │ (реестр формы  │  (реестр флота:    │ (гейты, автономия, │
        │  артефактов +  │   какие продукты   │  governance)       │
        │  контуры)      │   ведём)           │                    │
        └───────────────┴───────────────────┴───────────────────┘
                                  │
                        Product Contract
                (единый объект: кто продукт, какому
                 стандарту следует, удовлетворяет ли ему)
                                  │
                      PRODUCT EXECUTION PLANE
        ┌──────────┬──────────┬──────────┬──────────┬──────────┐
        │ Продукт 1 │ Продукт 2 │ Продукт 3 │   ...    │ Продукт N │
        │   repo    │   repo    │   repo    │          │   repo    │
        └──────────┴──────────┴──────────┴──────────┴──────────┘
```

Кит знает **контракт** продукта, а не его внутренности: React/FastAPI/Supabase — вторичны. Поэтому
N продуктов — это масштабирование **одной модели**, а не N уникальных интеграций.

## Домены (архитектурная сложность — ограниченная)

Внутри может быть сколько угодно модулей, но модель в голове помещается на одном экране:

| Домен | Что держит | Пакеты кита |
|---|---|---|
| **Kernel** | пути, контракты, фундамент | `shared` |
| **Product** | паспорт, реестр флота, контракт, здоровье | `planning` (product_contract, product_registry, passport, contours), `lifecycle` |
| **Engineering** | архитектура, гейты, исполнение, доставка | `engops`, `gates`, `engine`, `delivery` |
| **Intelligence** | здоровье продукта/тех/delivery, риски, дрейф, статус команды | `intelligence` |
| **Governance** | политика автономии, журнал решений, переопределения | `governance` |
| **Artifacts** | шаблоны, схемы, проверяющая логика | `checks`, `validation`, `templates`, `schemas` |
| **Integrations** | git, GitHub, LLM | `integrations`, `providers` |

Границы доменов проверяются машиной (`packages/layering.yaml` + `validate_layering.py`): зависимость
вверх запрещена, взаимные связи заморожены ратчетом и вправе только сокращаться.

## Product Contract — центральный объект

Единый объект продукта агрегирует существующие вычислители (не заводит второй источник истины):

| Грань | Откуда | Команда |
|---|---|---|
| **identity** | Product Passport | `ai-ops contract` |
| **standard** | artifact-registry (версия контракта) | |
| **artifacts** | product_templates (Missing/Invalid/Outdated/Valid) | |
| **contours** | product-operating-model (источники истины) | |
| **health** | intelligence.health (product+tech+delivery) | |
| **risks** | intelligence.risk_register (из здоровья+дрейфа) | |

**Операции** над продуктом и флотом:

| Команда | Что делает |
|---|---|
| `ai-ops contract` | контракт текущего продукта + один вердикт (valid / not_ready с причинами) |
| `ai-ops products` | сводный вердикт по ВСЕМУ флоту разом |
| `ai-ops products register` | добавить текущий репозиторий в реестр флота |
| `ai-ops inspect <id>` | карточка одного продукта флота по id |
| `ai-ops team` | статус команды: здоровье, риски, блокеры, задачи, milestone |
| `ai-ops governance` | политика автономии, журнал решений AI, переопределения человека |

Вердикт **честный**: `valid` только когда все обязательные артефакты на месте, источники истины
контуров присутствуют и здоровье не красное; иначе `not_ready` **с названными причинами**.
Недоказанное называется недоказанным (`unknown` ≠ `ok`, `not_computed` ≠ зелёное).

## Три вида сложности

- **Capability** (что кит умеет) — большая, и это нормально: создать продукт, вести паспорт, проверять
  архитектуру, запускать тесты, ревью, quality gates, работать с git/GitHub/LLM, собирать evidence,
  вести флот.
- **Architectural** (модель в голове) — ограниченная: домены выше, границы проверяются машиной.
- **Operational** (что нужно сделать оператору) — минимальная: `register` продукт, `contract`/`inspect`
  один, `products` — все разом.

> N продуктов должны чувствовать AI Ops как одну простую систему, даже если внутри — большая платформа.
