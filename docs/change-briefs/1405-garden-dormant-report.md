# #1405 — неподключённые модули в отчёте уборки

Результат: единый отчёт уборки называет неподключённые модули с путями к исходникам и сохраняет причину намеренного карантина. Это кандидаты на разбор, а не разрешение удалить или подключить эксперимент.

Затрагиваемые пути: garden.collect → существующий capability_inventory.dormant_modules; JSON и текстовый вывод garden; контракт витрины возможностей и неизменный ратчет дормантного инвентаря.

Инварианты: только чтение; существующий детектор и его исключения сохраняются; тестовый импорт и самоимпорт не считаются проводкой; карантин не снимается; отчёт советует и при успешном сборе возвращает 0; ошибка детектора не превращается в «сад чист». Новых зависимостей, пакетов и обязательных проверок нет.

Основные failure modes: потеря кандидата при композиции; потеря причины карантина; тестовые/копийные импорты скрывают кандидат; ошибка выдаётся за пустой список; отчёт изменяет исследуемые файлы.

Доказательство: настоящие временные Python-файлы → обнаруженный кандидат; добавленный рабочий импорт действительно меняет результат; тестовый/самоимпорт и копия не скрывают модуль; побайтовый снимок до/после доказывает отсутствие записи; исключение детектора доходит до вызывающего; целевые контракты, core smoke, Ruff и независимое review всей delta.

Не входит: удаление модулей, изменение allowlist/потолка, новый детектор, перенос старых реализаций, полное закрытие #1405, тяжёлые замеры #1408/#1409 и настройки защиты GitHub.
