# Интерактивная сессия без вложенной модели — #1434

Результат: проектный run готовит существующий controller-план для открытого агента;
автономное исполнение требует явного выбора. Нет безграничного ожидания или дубля события.

Затрагиваемые пути: UserPromptSubmit → begin/active; run → Spec-First → controller либо
явный autonomous → claim → subprocess; resume, Stop/verify; managed team-session; init/update.

Инварианты: не удалять claim и не повторять неизвестный исход; одинаковый turn_id не
создаёт новую постановку; разные события не склеиваются по тексту; план не означает
accepted; обязательные gates, независимое review и CI не подменяются самоотчётом автора.

Failure modes: повтор hook; отсутствует turn_id; занятый writer lock; молчащий процесс
с потомками; подмена/дрейф подготовленных артефактов и checkout.

Доказательство: реальные FS/Git/процессные fixtures обоих runtime, включая controller без
моделей, resume со сменой исходников, turn replay, missing intake, timeout и descendants,
busy lock, сохранность claims и отказ при подмене. Целевые тесты, core smoke и lint.

Границы: конкретная точка зависания 0df05aef не установлена: runtime-лог исходной облачной
сессии недоступен. Локальная установленная 4.12.0 и текущий main имеют тот же безграничный
subprocess.run. Stop сам не создаёт запрос; begin создавал новый UUID на каждый submit.
Новая реализация не даёт controller-плану машинную приёмку: evidence/gates остаются
обязательными. Полная живая командная приёмка #1434 и изменение ИИ-среды сюда не входят.

## Блокер слияния

У текущего controller-пути нет завершения project-session с независимой проверкой
результата. После handoff задача остаётся running, Stop не принимает её, а новая
постановка при незавершённом claim отклоняется. Это **не готовый пользовательский
сценарий**. PR остаётся draft до реализации безопасного finalize/reconcile и проверки
нового следующего запроса. Ослаблять verify либо удалять claim для обхода нельзя.
