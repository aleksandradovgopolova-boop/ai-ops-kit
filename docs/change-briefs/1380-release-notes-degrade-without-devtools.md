# Change Brief — #1380: описание выпуска деградирует чисто, когда devtools нет

## Результат
При `ai-ops update` дочки печать человекочитаемого описания выпуска больше не выглядит отказом.
Генератор release-notes живёт в `ai_ops_kit/devtools/` — слое инструментов разработки, который в
дочку намеренно не поставляется, поэтому его импорт там закономерно не проходит. Теперь этот шаг
честно сообщает «описание выпусков здесь не формируется» и называет диапазон версий, без трейсбека,
без имени исключения и без слова «НЕ УДАЛОСЬ». Применённое обновление и managed-доставка от этого
шага не зависят.

## Затрагиваемые пути
`installer/update_ops.py::_whats_new` — единственный шов. Его читают три потребителя: коммит
отложенной ветки (`_deferred_update`), экран штатного `cmd_update` (печать `report["whats_new"]
["text"]`) и тело PR CI-шаблона `templates/ci/ai-ops-update.yml`. Контракт `-> {status, versions,
text}` сохранён; добавлен новый статус `unavailable`. Поставка (`delivery_ops.DEV_ONLY_PREFIXES`,
правило no-product-depends-on-devtools) не меняется — наоборот, фикс опирается на неё.

## Инварианты
Managed-доставка не зависит от описания выпуска (шаг косметический). Обёртка всегда возвращает
well-formed dict, а не бросает исключение. Ожидаемое отсутствие генератора (`ModuleNotFoundError`/
`ImportError`) не выдаётся за отказ; настоящий сбой генератора остаётся честным `failed` с «НЕ
УДАЛОСЬ». Имя исключения и трейсбек наружу не текут. devtools по-прежнему НЕ едет в дочку.

## Основные failure modes
Выдать ожидаемое отсутствие за сбой (регресс до фикса); спрятать настоящую поломку генератора под
«unavailable»; уронить применённое обновление трейсбеком; сломать контракт dict для трёх
потребителей; «починить» доставкой devtools в дочку (нарушение слоистости и раздувание поставки).

## Доказательство
Positive: с доступным devtools `_whats_new` даёт `status=ok` и реальный текст (прежний тест цел).
Fail-closed по смыслу: заблокированный импорт `ai_ops_kit.devtools` → `status=unavailable`,
`versions=[]`, в тексте назван диапазон `4.11.1 → 4.11.4`, нет «НЕ УДАЛОСЬ» и нет
`ModuleNotFoundError`, dict сериализуем. Настоящий сбой генератора (OSError) по-прежнему даёт
`failed` + «НЕ УДАЛОСЬ» (существующий тест). ruff на изменённых файлах, целевые `test_update_*`
зелёные.

## Не входит
Перенос ядра `whats_new` из devtools в поставляемый слой — это более крупный вариант; здесь только
мягкая деградация. Issue #1380 закрывает судья, не писатель.
