# #1417 — установка под стек и добавление готовых навыков

## Результат

При установке из исходного checkout команда выбирает именованный профиль.
Установщик доставляет в проект существующие навыки из манифеста. Команды
`capability add` и `bundle add` подключают один навык или набор. Состав должен
воспроизводиться при штатном обновлении.

## Границы реализации

Входы — `./ai-ops init <каталог> --preset <профиль>` из checkout кита и команды
добавления из этого же установщика в уже установленном проекте. Используем
действующие manifest.skills.shipped и sync_skills. Профили React, Python, AI,
дашборда и мобильного проекта задают подборку навыков; обязательные навыки
ядра выводятся из манифеста. Списки product-team, enterprise, startup и govtech
описывают состав наборов. Новых моделей, инструментов и политик доступа профиль
не включает. По умолчанию сохраняется штатная установка всего набора.

## Приёмка

Проверяем видимые навыки после чистой установки из соседнего каталога,
повтор команды и обновление, добавление одного навыка и набора. Неизвестный
идентификатор, некорректная конфигурация и конфликт с выбором владельца
выявляются до записи. У сторонней настройки, пользовательского навыка и прав
должны сохраниться исходные значения. Существующие skills не копируются в исходники
профилей. Тестируем через настоящий CLI на временном Git-репозитории.

Независимое ревью выявило риск частичной установки при конфликте навыка,
общем каталоге по ссылке и одновременном update. Проверяем назначение относительно
самого child до записи, сериализуем add и update и проверяем отсутствие изменений
соседних YAML-полей при anchors. Каталог наборов помещаем рядом с перечнем
поставляемых навыков в существующем манифесте.

После интеграции #1560 add сначала входит в штатный барьер миграции. В активном
окне prepared update и при незавершённом журнале команда отказывает до изменения
конфигурации и навыков. Блокировка каталога отдельно сериализует обычные установки.

Регрессия порядка обновления проверяет вход из cmd_update под блокировкой и оба расчёта списка файлов вокруг запуска миграции.

Штатная проверка самоприменения читает тело cmd_init. Сохраняем в нём шаги доставки и применяем блокировку к входу до первой записи.
Установленная в дочке обёртка направляет capability/bundle в штатный локальный установщик. Сквозной тест выполняет добавление, повтор и update из самой дочки.
