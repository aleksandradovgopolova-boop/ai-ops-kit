# #1409 — гейт скорости и памяти: время парой, память против принятой базы

Результат: ухудшение скорости или памяти кита относительно последнего выпуска делает ночной (или
ручной) прогон `performance-baseline` красным. Время сравнивается только парой на одной машине в
одном прогоне, память — с принятой базой в репозитории. Схема принята владельцем 18.11.2026.

Затрагиваемые пути: `ai_ops_kit/devtools/perf_gate.py` (новый), `bench_performance.validate_receipt`
(публичное имя существующей проверки), `.github/workflows/performance-baseline.yml` (ручной запуск
и ночной cron, база — последний тег `vX.Y.Z`), `qualification/evidence/performance-baseline-1409/accepted-memory-baseline.json`.

Инварианты: обязательные проверки PR не меняются; новых зависимостей нет; порог 1,2; «не смогли
сравнить» никогда не зелёное (код 2); без чистых исходников и снимка окна (`/proc`) не исполняется
ни одна команда.

Failure modes: база из выпуска, где набор команд не проходит, → `ERROR`; изменён `suite.json` →
память `INCOMPARABLE` до новой принятой базы; swap/перезагрузка/изменение исходников во время пары
→ `REJECTED_WINDOW`.

Доказательство: `tests/unit/test_perf_gate.py` (парное время, память по устойчивым полям, итог и
коды, реальный прогон пары на двух git-checkout, отказы до команд, повторный разбор трёх
CI-прогонов 13.11.2026), `tests/unit/test_performance_baseline_workflow.py` (триггеры, pinned
actions, выбор базы на репозитории с тегами, отказ на неполном/неизвестном SHA), actionlint,
`workflow_contexts`.

Не входит: обязательность на PR, чередование порядка A/B, оптимизация.
