# #1321: импорты валидаторов без повторного исполнения сценариев

Бриф написан до изменения теста. База: `2cda991a8df45b6fcbf3a31a628a659d671c74c9`.
Это один срез открытой задачи #1321, а не завершение оптимизации всего цикла.

## Результат

Проверка bootstrap загружает настоящий файл каждого валидатора в изолированном Python,
но не исполняет его main повторно. Полное исполнение main и предметные сценарии сохраняются
в существующих отдельных тестах. Любая ошибка импорта, отсутствие эффекта bootstrap или
загрузка другой копии пакета дают отказ.

Основание: прежний `test_validators_start_without_pythonpath` последовательно запускал
весь main каждого найденного файла. Для `validate_product_qualification.py` это все
`run_scenarios()`, уже проверяемые отдельно. В историческом диагностическом прогоне такой
subprocess превысил 180 с; отдельный контроль занял 83,672 с. Это разные условия и исходники,
а не сопоставимое before/after и не оценка экономии.

## Затрагиваемые пути

- `tests/unit/test_validator_bootstrap.py`: динамическое обнаружение, загрузка реального
  script через runpy с именем вне `__main__`, успешный checkpoint после проверок пути и копии.
- Используется прежний `ambient.run`: `-S`, PYTHONPATH только с разрешёнными зависимостями,
  чужой cwd и прежний timeout. В probe меняется только sys.path[0] на каталог validation,
  как при прямом запуске script. Корень пакета должен добавить настоящий bootstrap.
- До import-only пробы проверяется отдельный владелец main: STANDALONE / NEEDS_ARTIFACT
  из `test_validator_runtime_contract.py` либо FIXTURE_CHECKS из `test_example_fixtures.py`.
  На базе все 25 обнаруженных файлов имеют процессный вызов main. Для artifact CLI это
  сохранённый отказ без входа; он не объявляется успешной предметной валидацией.
- Настоящие script-запуски из изолированной копии, проверки повреждения реестров,
  product qualification и teeth-тесты не меняются. Общий `tests/ambient.py` не меняется.
- Кроме теста меняются только этот бриф, его индекс и newsfragment.

## Инварианты

Динамическое обнаружение сохраняется. Новый файл без отдельного процессного владельца main
краснит проверку до импортной пробы. Корень Kit не подставляется вручную; site/editable finder
не включается. Настоящий bootstrap обязан изменить путь; пакет и bootstrap должны принадлежать
выбранной копии. Ошибка другого импорта и завершение до checkpoint не считаются успехом.

Маркеры существующих тестов, selectors, skip/xfail, таймауты, floors и обязательные CI contexts
не меняются. «Импорты проверены» не означает «рабочие сценарии прошли».

## Основные failure modes

1. Probe подложил корень и скрыл отсутствие bootstrap.
2. Main исполняется внутри импортной пробы.
3. Исключение или отсутствие эффекта bootstrap не краснит пробу.
4. Загружена другая копия пакета.
5. У нового валидатора исчезло единственное процессное покрытие main.

## Доказательство

- Positive: все реальные файлы импортируются без окружающего Kit; rc0 и checkpoint.
  Отдельный script действительно пишет marker при прямом запуске main; импортная проба
  marker не создаёт. Это проверяет факт исполнения, а не только аргумент runpy.
- Fail-closed: удалён настоящий bootstrap выбранной копии; повреждён обычный импорт;
  в bootstrap добавлена runtime-ошибка; удалено его изменение пути. Сначала доказывается
  наличие повреждения, затем ненулевой результат и отказ положительного assertion.
- Side-effect proof: до импорта корня нет в путях, после bootstrap он есть. Проверяется
  реальное расположение ai_ops_kit и bootstrap. Предзагруженный чужой пакет даёт отказ.
- Контрпример полноты: новый реально обнаруженный файл без отдельного main owner отвергается.
- RED: три новые регрессии падают на прежнем runner: main реально вызван, пустой bootstrap
  и чужой пакет ошибочно имеют rc0. Затем тот же набор проходит на новой пробе.
- Целевые проверки: весь bootstrap-файл, существующие процессные случаи всех его владельцев,
  product qualification, teeth, ambient/path hygiene и короткий core; ruff/diff. Перед merge —
  независимый review и существующие применимые CI точного итогового head. Один дополнительный
  pr-current-python по изменению harness согласует интегратор после review; не дублируется.

Сырые результаты и карта process ownership сохраняются в рабочем пакете session05/
verification1321-implementation. Численное ускорение всего цикла и p95 не заявляются.
