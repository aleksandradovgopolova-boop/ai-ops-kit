# #1434 — продолжение через штатных агентов открытой сессии

## Результат

Открытая сессия Codex координирует работу своим штатным tool loop. Когда завершение
требует независимого review, кит выдаёт готовые машинные задания субагентам и
команду продолжения той же задачи. Пользователь не переносит запросы, JSON и
digest между сессиями и не настраивает второй Codex ради проверки результата.

## Затрагиваемые пути

current-session run/resume → исполнение RunPlan → finalize → scoped review requests
→ задания родным агентам → их независимые результаты → прежний finalize/gates.
Resume/compact перечитывает проверенный отчёт; смена ревизии, пользовательского
ввода либо артефактов требует нового review. Init/update доставляет код и общую
инструкцию team-session. Вложенный `--autonomous`/codex-app-server сохраняет guard.

## Решение и инварианты

В интерактивном Codex исполнителем является уже авторизованный runtime и его
субагенты. Запуск дополнительного CLI не является условием автономности сессии.
Не вводим собственный model/tool loop, новый login, API fallback или настройку
доверия. Машинное задание не означает, что агент запущен: dispatch делает host,
статус обозначает ожидающее действие. Если native tools отсутствуют, это реальный
блокер, а не повод объявить запуск или симулировать независимый verdict.

Writer ≠ judge; reviewer получает fresh context и опубликованные входы, не
рассуждения автора. Verdict/digest возвращаются через настоящий независимый tool
result; код лишь готовит задания. Гейты, approvals, CI и приёмка не ослабляются.
Старый text-only provider не переименовывается в исправленный native executor:
его несовместимый pre-turn handshake остаётся отдельным ограничением headless пути.

## Failure modes

1. Изменились HEAD/input/artifacts — старые задания не запускаются, нужен finalize.
2. Подменён request/report либо путь verdict выходит из checkout — отказ.
3. Повтор resume — стабильный job id, host проверяет уже запущенного агента.
4. Нет native tools или ответ агента потерян — нет ложного accepted/повторного CLI.
5. Собственный/stale/чужой verdict — прежняя проверка независимости блокирует.

## Доказательство

Positive: настоящий controller/finalize создаёт request, CLI возвращает готовый
native job, fixture независимого reviewer проходит прежние gates. Fail-closed:
tamper и stale scope не дают запустить старое задание или принять результат.
Side-effect proof: сначала создаются реальные request/изменение Git/артефакт,
затем проверяются обнаружение дрейфа и отсутствие нового provider/claim.
Отдельный живой review родным субагентом проверяет передачу без участия владельца;
это не подменяет требуемую командную приёмку двух аккаунтов в #1434.

## Не входит

Обход host permissions, снятие native guard, поднятие capability до полной
поддержки всех app/cloud/CLI сред, запуск после закрытия приложения, собственный
Codex fork и продуктовые изменения ИИ-среды. Доставка выполняется отдельно на
проверенной копии дочернего проекта с сохранением текущей работы владельца.
