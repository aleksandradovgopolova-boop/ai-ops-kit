# #1434 — завершать только свою заявку контроллера

При одновременной регистрации в двух рабочих копиях общий реестр выбирает одного владельца. На стороне завершения current-session после проверок выполнялся finish по одному workitem_id. Между подготовкой и завершением постановку мог принять другой владелец.

Регистрирующий контроллер записывает идентификатор попытки в заявку и свой run-report. Работник finalize сверяет отчёт с закреплённым при подготовке хэшем. Под общей блокировкой записи finish проверяет идентичность сессии, машины, рабочего дерева, ветки, состояния и поколения до первой записи. Старые отчёты допускают проверку по прежним полям только для заявок старого формата. Несогласованная пара старого и нового форматов блокирует завершение.

Проверки охватывают обычный finalize, смену владельца или поколения до завершения, отсутствие записи в реестр и проекции при отказе, старую пару без поколения и отказ при расхождении форматов. Операторское управление реестром, хранение заявок и права процесса сохраняются. Границу изоляции задаёт среда исполнения; проверка владельца координирует запись в общий реестр.

Штатный относительный путь команды register должен указывать на тот же общий реестр из каждой рабочей копии. Перед завершением проверяем существующие проекции, которые будут изменены или удалены. Проверка воспроизводит передачу через CLI из двух копий, расхождение прежних записей, повреждённую копию и восстановление после прерванного завершения того же владельца.

При обновлении ранее созданная операторская заявка может находиться только в локальном реестре. Штатный относительный finish переносит её под обеими блокировками, если рабочая копия и носители согласованы. Контроллер по-прежнему требует исходную общую заявку.
