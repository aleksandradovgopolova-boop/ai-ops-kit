# Точная граница CI после реконструкции истории

Что: исходный exclusive cutoff находится внутри version-stage. В 300-stage истории
он выделен отдельным checkpoint; конфигурация ссылается на него, а не на конец
смешанной группы. Даты исходного включения правила и архивные CI receipts сохранены.
Зачем: исчезнувший SHA не должен отключать или случайно сужать проверку формата.
Инварианты: PR проверяет base..HEAD; non-PR — exact cutoff..HEAD; missing/unrelated
cutoff отказывает до cz; код пустого диапазона 3 допускается; прочие ошибки не успех.
Проверка: исходный и представленный source scope совпадают без добавлений/потерь;
реальные Git/Bash positive/negative cases, конфиг, Commitizen 4.17.1; полный применимый
CI нового итогового SHA обязателен и не заменяется прежними receipts.
Границы: это новая служебная миграция current policy, не изменение старых tag trees,
исторических release evidence или подписей. GitHub protection не изменяется.


## Квалификация нового корня до замены main

Полная package-quality, smoke и docs запускаются событием push только в выделенной
ветке `ci/history-cutover-qualification`. Обычные pull_request triggers, условия jobs,
steps и permissions сохранены; полный дубль CI на push main не возвращён.
Это eligible событие GitHub для checks точного нового SHA, в отличие от manual dispatch.
Отсутствующий общий предок с прежней main не подменяется фиктивным bridge-коммитом.
Проверка структуры подтверждает неизменность jobs и прежних PR events, ограничение
нового push одной веткой, отказ обычным feature/main push для package-quality/smoke.
До переключения требуются фактические полные результаты нового SHA и независимый review.
После переноса открытые PR сохраняют штатные PR gates и требуют свежего CI/re-review.

Towncrier требует общего предка. Только на указанном push кандидата его сравнение
идёт с точным 300-stage снимком исходной main `448cfa77`; missing/unrelated база
останавливает шаг до Towncrier. Обычные PR и остальные события сохраняют `origin/main`.
Наличие нового фрагмента по-прежнему обязательно; обхода fragment gate нет.
