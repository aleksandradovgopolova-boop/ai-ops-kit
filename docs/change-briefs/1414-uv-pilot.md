# Change Brief — пилот uv + единый источник версий инструментов (#1414, #1402)

## Результат

Материнский репозиторий получает воспроизводимое окружение (`uv.lock`) и более быструю установку
зависимостей через `uv`, а версии инструментов (ruff, mypy, pytest, pytest-xdist, pytest-cov,
hypothesis, pyyaml) объявляются из ОДНОГО источника — `pyproject.toml`, и расхождение между
объявлениями краснеет проверкой. `uv` НЕ навязывается дочернему киту — это пилот материнского репо.

## Замер (spike) — по числам, как требует #1414

Clean-install набора CI (`pyyaml pytest pytest-xdist hypothesis ruff`), Python 3.12.16, два прогона:

| прогон | pip, холодный кэш | uv, холодный кэш | pip, тёплый кэш | uv, тёплый кэш |
|--------|------------------:|-----------------:|----------------:|---------------:|
| 1      | 55.99 c           | 24.54 c          | 12.71 c         | 0.46 c         |
| 2      | 64.46 c           | 29.60 c          | 4.78 c          | 0.12 c         |

- Холодная установка (каждая джоба CI сейчас платит именно её — pip-кэша в workflow'ах нет): uv
  примерно в 2.2–2.3 раза быстрее.
- Тёплая установка (uv с кэшем): доли секунды против единиц-десятков секунд у pip.
- `uv.lock`: 30 пакетов, резолв за ~7 c; повторный `uv lock` даёт идентичные байты; `uv lock
  --locked` зелёный — значит годится как сторож дрейфа (lock разошёлся с pyproject → красное).

**Решение: числа ОПРАВДЫВАЮТ закрепление.** `uv.lock` закоммичен; установка в CI переводится на uv
обкаткой (см. «Затрагиваемые пути»).

## Затрагиваемые пути

- `pyproject.toml` — единый источник версий (`[project].dependencies` + `[project.optional-dependencies]`).
- `requirements-dev.txt` — зеркало полов из pyproject.
- `.pre-commit-config.yaml` — rev хука ruff.
- `.github/workflows/*.yml` — пины установки; пилотная джоба `smoke-uv` в `pr-smoke.yml`.
- `uv.lock` — новый, воспроизводимое окружение; в дочку НЕ едет (не в `managed_set`, не в wheel).

## Инварианты

- Версия ruff и mypy (находко-чувствительные) — РОВНО одна во всех объявлениях.
- pytest/hypothesis/pyyaml/pytest-xdist/pytest-cov — согласованы по серии (мажор) с полом pyproject.
- uv — только материнский репо; дочерний кит продолжает ставиться штатным pip-путём.
- Обязательные 17 проверок CI пилот не трогает: `smoke-uv` — ADVISORY (как parallel-safety начинала).

## Основные failure modes

1. Дрейф версии между pyproject / CI / pre-commit / uv.lock — ловит `test_tool_versions_aligned.py`.
2. `uv.lock` устарел относительно pyproject — ловят и контракт-тест (по мажору/точной версии), и
   `uv sync --locked` в джобе `smoke-uv`.
3. uv.lock просочился в поставку дочки — исключён `managed_set` (проверено: ни один паттерн манифеста
   его не захватывает).

## Доказательство

- positive — `test_aligned_tool_versions_have_single_source`: реальное дерево согласовано.
- fail-closed — `test_drift_is_caught_fail_closed`: расхождение любого класса даёт находку (проверено
  и живьём: временный `pytest>=8.0` в requirements-dev покраснел, откат — зелёный).
- side-effect — `test_real_tree_declares_each_tool_somewhere`: сверка видит реальные объявления, а не
  пустоту; `smoke-uv` на реальном раннере собирает окружение из `uv.lock` и исполняет критический путь.

## Не входит

- Переключение 17 обязательных проверок на uv: отдельный шаг под присмотром владельца (переписывает
  установку во всех workflow'ах, смотреть зелёным). Пилот даёт основу: `uv.lock` + сторож дрейфа +
  advisory-джоба `smoke-uv`.
- Навязывание uv дочернему киту (граница #1414).
