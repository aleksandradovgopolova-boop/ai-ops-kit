# #1399 — негодный числовой замер не увеличивает долю результата

Результат: карта продукта отвергает NaN и бесконечность в outcome-readout; валидный отрицательный результат и неизвестный исход сохраняют прежний смысл.
Затрагиваемые пути: YAML outcome-readout → `_measured_readouts` → `outcome_coverage`, `evidence_backed_outcome_rate` и `learning_to_decision_rate`; целевые тесты и документационный индекс.
База: main `e070300e473f9f465cd5d493c60c1db6773c1fd9`. PR #1418 уже слит и не повторяется. Проверены GitHub PR/issues, общий active-work, worktrees и имена процессов; Claude #1402/#1425/#1426 не затрагиваются. Зарегистрирована отдельная работа, takeover не используется.
Инварианты: read-only; только stdlib + pyyaml; никакого импорта validation из intelligence; конечные int/float, включая отрицательные и ноль, сохраняются; `target_met: no` считается замером, `unknown` не считается; главная мера и её знаменатель не меняются.
Failure modes: `.nan`/`.inf` принимаются за настоящий замер; исправление отвергает валидный отрицательный результат; большой конечный int вызывает переполнение при проверке; один негодный файл скрывает остальные; чтение изменяет данные. Неверный тип verdict уже отвергается сравнением с tuple и отдельной правки не требует.
Доказательство: сначала красные регрессии на настоящих временных YAML-файлах для обоих числителей; затем positive/fail-closed/side-effect proof с побайтовым снимком; существующие scorecard/outcome-регрессии, короткий core smoke, Ruff, документация и независимое entire-delta review; обязательный CI точного итогового head/base до merge.
Не входит: новая метрика, изменение определения #1400, security/billing/credentials, настройки GitHub protection, работа Claude, релиз пакета, consumer rollout, performance-замеры. Полный issue закрывается только после проверки всех его исходных критериев и подтверждённого merge.
