# #1512 — защита от дублей кода доезжает до проектов

Результат: статья CODE-003 «без дублирования» исполняется в проекте, а не только у кита. Новая группа структурно-одинаковых функций сверх базы проекта видна с адресами; существующие замораживаются базой `.ai/project/code-duplication-baseline.yaml`, как в ките; проект без Python слышит «не проверяется». Шаг child-CI advisory — проект не краснеет в день обновления.

Что нашлось до кода: упрощённая копия детектора УЖЕ ехала в проект (`checks/constitution_conformance._duplicates`, онбординг и первый осмотр здоровья), но без базы заморозки и без «не проверяется» — а две копии одной проверки на дубли сами нарушали CODE-003. Поэтому срез — одно ядро, а не третья копия.

Затрагиваемые пути: `checks/code_duplication.py` (ядро) ← `devtools/code_duplication.py` (ратчет кита, база `packages/`) · `checks/constitution_conformance` (онбординг, отчёт конституции) · `cli/ai_ops_cli_first_health` (осмотр здоровья) · `validation/validate_code_duplication.py` ← шаг `templates/ci/ai-ops-validate.yml` (из клона кита) и команда владельца из `.ai/managed`; поставка — `RUNTIME_VALIDATORS`; статья — `ARCHITECTURE_CONSTITUTION.md` → `rules.yaml` → `gate-reconciliation.md`.

Инварианты: ключи групп и база кита не меняются (база кита пересобрана байт в байт); шаг child-CI не блокирует; перезаморозка базы проекта только с `--force`; пустой результат по непрочитанному коду — не «дублей нет».

Основные failure modes: проект без Python получает «дублей нет»; без базы — молчаливый зелёный или красный в день обновления; повторная заморозка «отмывает» новые дубли; тесты и `.ai/managed` в проекте дают ложные группы; ратчет кита ломается от смены ядра.

Доказательство: positive — новая группа сверх базы видна с адресом; fail-closed — без базы код 1 и перечень, без Python код 2 и «НЕ ПРОВЕРЯЕТСЯ», перезапись базы без `--force` отказывает и файл не меняется; side-effect — база реально пишется на диск и читается следующим прогоном. Замер на настоящем проекте — ниже.

**Замер на настоящем проекте** (сайт mooniq, коммит `6293915`, только чтение копии): Python — 87 файлов продукта (тесты, `.venv`, `.ai` не считаются), найдена 1 группа — `_connect` в `server/mooniq_orders/callbacks.py:139` и `server/mooniq_orders/club_earn.py:92`, одинаковый помощник подключения к SQLite. Шум — 0 из 1. JavaScript (47 файлов) назван непроверенным. Время — 0,4 с. На чисто TypeScript-репозитории (typeorm) — «НЕ ПРОВЕРЯЕТСЯ», код 2.

**Решение по пятому пункту — показывать ли агенту существующие помощники до написания нового.** Проверено: механизма нет. `context/repo_graph.py` строит `symbol_index`, но его не читает никто вне модуля; контекст агента получает только соседей по импортам, а явная подсказка «переиспользуй существующее» есть лишь для компонентов Storybook (#613). В этот срез не входит: это изменение контекста writer-а (что и сколько класть, как не раздуть бюджет контекста), и решать его по данным, а не заодно. Предложение — отдельная задача: перед writer-стадией класть в контекст имена и подписи функций затрагиваемых модулей и их соседей из `symbol_index`, с замером, снижает ли это число новых групп дублей по этой же проверке.

Сознательно унаследовано (независимое ревью назвало, решено не менять в этом срезе):
- каталоги `build`, `dist`, `tests`, `test` пропускаются на любой глубине — тот же список, что у прежней поставляемой копии в `constitution_conformance`;
- две одноимённые функции одной структуры в ОДНОМ файле считаются одним членом группы (ключ `путь::имя`, как у ратчета кита). Онбординг раньше сравнивал по `путь:строка:имя` и такую пару показывал — теперь не показывает; случай редкий (перегрузка под TYPE_CHECKING и т.п.).

Найдено ревью и исправлено: непрочитанный `.py` (кодировка, синтаксис Python 2) раньше считался проверенным — проект из таких файлов получал «дублей нет»; теперь проверенными считаются только прочитанные файлы, непрочитанные названы, ни одного прочитанного — «не проверяется». Битая база больше не падает трассировкой: «база не читается», код 2.

Найдено полной проверкой и исправлено: смена шаблона CI ломала перенос ожидающих запросов при обновлении проекта. Обновление освежает нетронутый владельцем `.github/workflows/ai-ops-validate.yml`, а миграция сессий (`ai_ops_kit/lifecycle/session_migration.py`) принимала это за независимую правку продукта и отказывала. Шаблон не менялся с версии, на которой стоит сквозной тест, поэтому дефект был скрыт; эта задача — первая, кто его тронул. Теперь файл в `.github/`, чьё содержимое совпадает с отпечатком кита из `.ai/runtime/ci-templates.json`, считается установкой, а не правкой; правка владельца по-прежнему останавливает миграцию (оба случая — в `tests/unit/test_session_migration.py`).

Не входит: JS/TS (детектор читает только Python; разбор JS/TS деревом из #1408 дал импорты, а не подписи функций), показ помощников агенту (см. выше), блокирующий режим в проекте.
