# #1446 — локальные настройки владельца при подготовке ветки обновления

В чистой копии dashboard-kit штатный update с политикой pr поменял два ключа merge-драйвера в общем Git config ещё до решения владельца. Вложенный installer работает в linked worktree и поэтому разделяет этот config с основной копией. При заданном CODEX_HOME в область записи и отката также попадают личные prompts.

При подготовке ветки вложенный installer доставляет версионируемые файлы проекта. С первого снимка до завершения rollback работа с host prompts и регистрация драйвера остаются за обычной установкой на месте. Отчёт обозначает отложенную регистрацию. Проектные команды и .gitattributes по-прежнему входят в обновление. Штатный init и явный update на месте сохраняют прежнее поведение, в том числе в linked worktree владельца.

Проверки: создать настоящую ветку на временной дочке и проверить содержимое Git, сохранить нестандартные значения обоих ключей и личный prompt, воспроизвести отказ вложенной поставки, проверить границу восстановления после снимка. Сверить отсутствие изменений у владельца и работу штатного in-place. Для полевой проверки использовать одноразовую копию закреплённого коммита dashboard-kit.

После принятия ветки установленная версия уже совпадает с целевой. Обычный явный update --in-place в этом состоянии завершался до установки личных команд. Проверяем полный переход от подготовки ветки до её принятия и установки в указанный CODEX_HOME. На месте используются только команды из актуального генератора и разрешённого набора проекта. Посторонний файл из .ai/generated не становится личной командой пользователя.
