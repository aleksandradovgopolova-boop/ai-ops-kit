# Установленный wheel работает вне клона — #1398

## Результат

После установки wheel команды `ai-ops plan` и `ai-ops next` используют поставленные
реестры и создают/читают артефакты в рабочем репозитории, без исходников кита рядом.
В поставку входят правила `rules/`: контекст плана сохраняет обязательную категорию `core`.

## Затрагиваемые пути

Сборка setuptools из checkout и через sdist → wheel → чистый venv → console_scripts →
разбор аргументов → RunPlan/ContextBundle и next_work. Корневые данные накладываются
на `build_lib/ai_ops_kit/`; `VERSION` позволяет существующим резолверам найти их.
Проверка чистой установки исполняет команды и проверяет артефакты, а не только импорты.
Editable-установка и installer сохраняют существующую раскладку.

## Инварианты

Один исходный экземпляр данных; нет записи в исходное дерево при сборке или в чужой
site-packages. Состав Python-пакетов, публичные команды, версия и зависимости не меняются.
Данные `planning/` и `context/` не затирают одноимённые Python-пакеты. Повреждённый
реестр не превращается в успешный пустой результат.

## Основные failure modes

1. В wheel есть код, но отсутствуют VERSION или один из каталогов данных.
2. Прямой wheel исправен, а сборка из sdist теряет ресурсы.
3. Успех обеспечен cwd/PYTHONPATH/editable-установкой или оставшимся клоном сборки.
4. Наложение данных повреждает код либо сборка загрязняет исходное дерево.
5. CLI теряет каталог/текст задачи при перестановке `--json`; отсутствие реестра даёт ложный успех.

## Доказательство

- Positive: help/plan/next из реально установленного wheel вне checkout, оба порядка `--json`.
- Fail-closed: удалённый обязательный реестр действительно отсутствует; команда завершается
  ненулевым кодом и не создаёт успешный план.
- Side-effect: JSON указывает на существующие RunPlan и ContextBundle с непустыми данными;
  `next` выбирает заданную работу из плана тестового продукта.
- Сверка состава/содержимого wheel, сборка через sdist, неизменность исходных ресурсов,
  целевые регрессии, core smoke, lint и применимый широкий профиль для изменения clean-install.

## Не входит

Массовая замена резолверов, реорганизация пакетов, поставка installer через pip, релиз,
изменение публичных схем и закрытие остального бэклога. Независимое review и CI точного
head требуются перед merge; локальные проверки их не заменяют.
