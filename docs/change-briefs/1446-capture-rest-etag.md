# Повторная сверка проверок при подготовке выпуска

При сборке плана GitHub повторно получает одинаковые запросы о прогонах проверок для каждого коммита.
Сохраняем в памяти одного сбора ответ страницы и выданный GitHub ETag. При повторе запрашиваем эту страницу заново.
Ответ 304 разрешает использовать прежние байты. Ответ 200 проходит действующие проверки на изменившиеся прогоны и попытки.
При отказе GitHub прежние данные не выдаём. Сверка перед публикацией начинается без сохранённых ответов.
Меняется только чтение списка прогонов pull request через штатный авторизованный gh в сборщике.
Проверяем границы страниц, независимость двух сборов, изменившийся ответ, отказ и отсутствие ETag.
Экономию основной квоты можно подтвердить для конкретного запуска только при полученных 304.
