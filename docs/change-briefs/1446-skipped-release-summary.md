# Восстановление пропущенного сообщения о выпуске

После публикации плана GitHub Actions отдельно записывает сообщение в сводку запуска. Если Pages успели опубликовать изменение, а этот шаг был пропущен, очередная сверка видит прежний состав и теряет сообщение. На дереве `999727ee` это воспроизведено локально с проверенными артефактами автоматических запусков 45197139134 и 45198882943. В реальной истории эти запуски завершились успешно.

Проверка должна сохранить доверенную проекцию и связать пропуск с единственным завершённым шагом сводки той же задачи и попытки Actions, в которой подтверждён deploy. Только явный `skipped` доказывает, что шаг не выполнился. При прежнем смысловом составе следующий автоматический запуск сохраняет исходный идентификатор уведомления. При новом изменении сообщение отражает новый состав. Повтор после успешной сводки молчит. Исход `cancelled` или `failure` у самого шага оставляет неопределённость: запись могла состояться.

Целевая проверка проходит через штатную сборку проекции и запись сводки в выделенный файл. Отдельно проверяются пропуск нескольких сводок, неверный источник, неоднозначный шаг, изменившийся состав и отсутствие записи при неизвестном исходе. Охват ограничен сообщением Actions. Публикация остальных показателей пульта продолжается обычным порядком. Факт получения человеком требует отдельного наблюдения.
