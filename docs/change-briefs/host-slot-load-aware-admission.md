# Допуск host-slot учитывает реальную нагрузку, а не только имя процесса (#1377)

Результат: локальный полный цикл (`check-full.sh` / host-slot) больше не блокируется процессом,
который лишь совпал по имени, но фактически простаивает. Совпавший процесс теперь дополнительно
проверяется по реальной загрузке CPU за короткое окно: простаивающий (≈0 %) не закрывает допуск,
а идущий под нагрузкой — закрывает по-прежнему. Это снимает ложную блокировку из baseline 21.10
§4, где локальный цикл не стартовал даже при совпавшем процессе на ~0 % CPU (постоянные
self-hosted раннеры и простаивающие тест-контейнеры). Защита от настоящей oversubscription
сохранена без ослабления. `devtools/` — только для разработки кита, дочкам не поставляется; #1377
остаётся открытым (судит ревью).

Затрагиваемые пути: только dev-слой —
`ai_ops_kit/devtools/host_resource_cli.py` (сэмплер CPU за окно + фильтр «реально нагруженных» +
подключение фильтра в `execute`), тест `tests/unit/test_host_resources.py`,
`docs/change-briefs/` (этот бриф и индекс), `newsfragments/`. Матчер имён (`_HEAVY`,
`heavy_processes`) и поведение flock/lease не меняются. Поставляемые слои и гейты не тронуты.

Инварианты: аддитивно для случая реальной нагрузки — совпавший и нагруженный процесс блокирует с
тем же смыслом сообщения («ps наблюдает…»). Меняется только случай ложной блокировки на
простаивающем процессе. Сэмплер вынесен за шов (`sampler` в `busy_heavy_processes`, `load_filter`
в `execute`), поэтому тесты подставляют «занято/простаивает» без реальных процессов. Порог —
`IDLE_CPU_PERCENT = 10.0` (% одного ядра за окно 0.3 с): отсекает блипы поллящих демонов, но любой
идущий pytest/vitest/build держится заметно выше. Неизмеримый процесс (sampler → None: исчез / ps
не прочитан) трактуется консервативно как занятый — защита не слабеет при сбое измерения.

Failure modes: `ps cputime` даёт накопленное CPU-время; мгновенная загрузка берётся как дельта двух
снимков за окно — короткий всплеск на границе окна возможен, но порог 10 % одного ядра выше шума
простоя. Если `ps` недоступен или процесс исчез между снимками — консервативно «занято» (прежнее
поведение блокировки). Окно 0.3 с добавляется к допуску только когда процесс реально совпал по
имени (иначе фильтр не вызывается для пустого списка).

Доказательство: `tests/unit/test_host_resources.py` — `test_matched_but_idle_heavy_process_admits_action`
(совпал + CPU≈0 ⇒ действие исполняется), `test_matched_and_busy_heavy_process_still_blocks_action`
(совпал + CPU 95 % ⇒ блок, действие не исполнено), `test_busy_filter_drops_idle_matched_process`,
`test_busy_filter_keeps_loaded_matched_process`,
`test_busy_filter_treats_unmeasurable_process_as_busy`,
`test_cpu_sampler_reads_delta_of_cputime_window`, `test_cpu_sampler_returns_none_when_process_gone`.
Прежние регрессии host-slot (контеншн между чекаутами, crash-recovery, наследование fd, symlink,
наблюдатель-обёртка) проходят без изменений — 17 passed. ruff чист на изменённых файлах.

Не входит: сквозной замер «доля ложных блокировок до/после» на живом хосте (чек-бокс baseline
измеряется отдельным прогоном направления #1321, не этим срезом); изменение `_HEAVY`, flock/lease,
порогов других гейтов; поведение в дочках; системный load average (взята точечная per-process
загрузка как более адресная к сценарию «раннер есть, CPU≈0»).
