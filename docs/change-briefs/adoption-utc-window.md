# Окно добровольного учёта: последние 30 календарных дней UTC

Источник: [#1451](https://github.com/aleksandradovgopolova-boop/ai-ops-kit/issues/1451).
Продолжение локального consent/exchange среза #1455, тот же владелец реализации.

Проблема: для каждого preview/export/report владелец должен вручную вводить две даты,
хотя приёмка #1451 задаёт первый default: 30 календарных дней UTC, включая текущий
неполный день. Без общего правила результаты легко сравнить за разные периоды.

Результат: при отсутствии обеих дат CLI выбирает текущую дату UTC и 29 предшествующих
дат. Явный период по-прежнему задаётся парой start/end. Одна дата без второй — отказ
до записи файла. Выбранный период виден в preview, export и report; получение
default не меняет согласие и не записывает активность. Формат receipt не меняется.

Затрагивает существующие engops/adoption.py, cli/adoption.py, их unit-тесты и руководство.
Новых пакетов, зависимостей, серверов или источников наблюдения нет. Согласие,
дедупликация, отзыв и уровни доверия сохраняются. Установка/обновление и verified_active
не объявляются доказанными; #1451 остаётся открытой. Реальные проекты не изменяются.

Проверки: positive — границы 30 дат, переход года и високосный февраль; явный диапазон;
fail-closed — неполная пара и недопустимый период; side-effect proof — default report
без согласия не создаёт реестр, неполный export не создаёт файл и не меняет согласие.
Наследуются сетевой запрет и тесты утечек основного среза. Целевые тесты и core smoke
через общий host gate последовательно после текущих запусков, lint и независимое
review до публикации. Локальная подготовка не меняет head/CI текущего #1455.
