# Один чистый checkout для корпуса выпущенных версий

Результат: сократить повторное разворачивание полного дерева старого кита в тестах обновления с реальных релизов. Вместо отдельного worktree на каждый тег — один временный worktree на модуль, который Git переключает на точный commit каждого тега.

Пути: tests/unit/test_upgrade_from_released_versions.py — получение корпуса из git, подготовка исходников релиза, отдельный child на каждый тег, настоящий init старым installer → update текущим installer → checksums/child validator/owner files/актуальная раскладка; teardown временного worktree.

Инварианты: весь фактический корпус тегов выполняется, без whitelist/выборки/skip; каждый тег ставится собственным выпущенным установщиком. Child-репозитории остаются отдельными. Перед переключением и после сценария исходный worktree чист (включая untracked/ignored), HEAD равен разрешённому commit тега. Нельзя скрывать порчу исходников reset/clean. Все прежние asserts/CLI-процессы, CI-группы, workers и таймауты сохраняются. Модульная фикстура локальна pytest worker, глобального кеша нет.

Failure modes: остались файлы предыдущего релиза; неверный HEAD; установщик изменил общий исходник; скрытое падение checkout/cleanup; потеря тега при сборе тестов.

Доказательство: реальные переключения между двумя тестовыми тегами с изменением/добавлением/удалением файлов; отказ без перезаписи грязного tracked/untracked/ignored состояния; исходный полный релизный корпус. Сопоставимый замер всего исходного модуля с одинаковыми тегами и исходами, стартом pytest и фикстурами, чередованием до/после. Core smoke, ruff, широкий PR-профиль по риску окружения, независимый review и все обязательные CI.

Не входит: изменение установщика или исторических тегов, кеширование установленных дочек, in-process подмена CLI, новое разбиение тестов по workers.

Диагностический профиль трёх версий (4.11.3/4.5.0/4.0.0): update 17,062 с; init 1,692 с; worktree add 0,951 с; worktree remove 0,384 с. Это ориентир масштаба, не доказательство экономии. Общая длительность этого диагностического pytest зависит также от очистки прежних tmp-каталогов; сравнительный замер использует отдельный одинаковый basetemp.
