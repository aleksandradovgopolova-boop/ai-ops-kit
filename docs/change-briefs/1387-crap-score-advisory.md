# #1387 — advisory CRAP-измеритель

Результат: отдельная команда измеряет цикломатическую сложность Python-функций и CRAP при наличии проверяемого покрытия, отличает новый долг CRAP ≥ 10 от измеренной заморозки. По dp-002 это advisory-пилот без обязательного CI-гейта.

Затрагиваемые пути: AST → квалифицированное имя/структурный ключ → покрытие строк тела → CRAP → сравнение с YAML baseline → текст/JSON и код возврата; явная запись baseline; проверка входов встроена в devtools-команду. Только новый devtools, baseline, unit-тесты, эта записка и newsfragment; индекс записок дополняется своей ссылкой в изолированной ветке; общий FILE_INDEX сводит родительская сессия.

Инварианты: stdlib + pyyaml; исходники не исполняются; обычный запуск только читает; имена типов AST вместо ast.dump и координат в ключе; путь и полное имя различают одноимённые методы; неизвестное/устаревшее/отсутствующее покрытие не становится 0%/100% или числом CRAP. Существующий baseline не повышается без явного обоснования.

Основные failure modes: вложенные функции засчитываются дважды; перенос строк меняет идентичность; устаревшее покрытие выглядит свежим; невалидный вход даёт пустой зелёный отчёт; запись baseline незаметно прощает новый долг.

Доказательство: реальные временные Python/JSON/YAML-файлы; positive формулы/AST/границ функций; fail-closed отсутствующих/изменённых evidence и baseline; side-effect proof изменения исходника/покрытия с новым долгом и побайтовая неизменность дерева в read-only режиме; точечные тесты, core smoke, применимая валидация и независимое review.

Не входит: обязательный/блокирующий гейт, Ruff pins, pyproject, общие workflows, garden/capability_inventory, платные модели, зависимости crapper, публикация и полное закрытие #1387. Полный coverage всего кита требует отдельного окна host-slot; без него глобальная заморозка остаётся NOT_RUN.

## Основание алгоритма (проверено до кода)

[Первоисточник Savoia/Evans](https://www.artima.com/weblogs/viewpost.jsp?thread=215899): `CC² × (1 − cov/100)³ + CC`; CC = 1 + решения. В оригинале basis-path coverage. Здесь явно используется **line-coverage approximation**, не эквивалент basis-path и не доказательство качества тестов.

[Референс crapper](https://github.com/unclebob/crapper#what-each-language-counts) учитывает Python decisions и LCOV; код/зависимости не переносятся. Наша политика отдельно измеряет вложенные функции, comprehension generators/filters, boolean operators и match без безусловного wildcard; определения/декораторы не создают покрытие тела.

[coverage.py JSON reporter](https://github.com/coveragepy/coveragepy/blob/master/coverage/jsonreport.py) даёт `executed_lines`, `missing_lines`, `excluded_lines`; берётся пересечение с диапазонами тела, без тела вложенных функций и docstrings. [RegionFinder](https://github.com/coveragepy/coveragepy/blob/master/coverage/regions.py) подтверждает исключение тел вложенных функций из родительского диапазона. Пустой знаменатель остаётся unknown.

Архитектурная проверка запретила отдельный импортёр validation → devtools: devtools не поставляется дочкам. Обёртка удалена до коммита; CLI остаётся штатным process-entrypoint из разрешённого devtools. Проводка в обязательный контур и отдельный production-валидатор отложены.

## Использование и границы evidence

Команда по умолчанию сканирует именованные `def`/`async def` в `ai_ops_kit/**`:

```bash
python3 -m ai_ops_kit.devtools.crap_score --json
python3 -m ai_ops_kit.devtools.crap_score --coverage coverage.json --coverage-binding coverage-binding.json
```

Коды: **0** — все функции измерены, нового/выросшего долга нет; **1** — новый/выросший долг или неполные измерения; **2** — входы невалидны/измерение не выполнено. Это локальные результаты необязательного devtools-пилота; required checks не добавляются. Для текста без чисел покрытия у неизвестных функций всегда указана причина; JSON сохраняет `null`.

При общей строке определения и тела line event не доказывает вызов: inline suite остаётся `unknown`. Исключённые из coverage тела, docstring-only и пустой знаменатель также `unknown`. Lambdas отдельно не измеряются. Декораторы/default arguments не засчитываются как покрытие тела. Одноимённые определения с одинаковой структурой получают порядковый суффикс; перестановка таких повторов не обещает сохранение индивидуальной идентичности.

Импортёр принимает coverage.py JSON format 2/3 с каноническими **относительными** путями (`ai_ops_kit/...`), без угадывания абсолютных путей. Считаются `executed_lines / (executed_lines ∪ missing_lines)` внутри диапазона тела; `excluded_lines` не превращаются в исполненные. coverage.py иногда перечисляет виртуальную строку EOF+1 в исключениях — она безопасно остаётся вне диапазона тела. Сводный процент файла и branch percentage не подменяют покрытие функции.

Привязку создаёт **доверенный runner измерения**, а не сам импортёр задним числом. Он сохраняет `measurement_inputs(root)` **до** запуска тестов и убеждается в равенстве снимка **после** тестов и генерации JSON. Снимок включает все Python-исходники, тесты и основные настройки, включая появление/удаление файлов. Формат `coverage-binding.json`:

```json
{
  "schema_version": 1,
  "outcome": "passed",
  "scope": "точное имя выполненного набора; targeted или full явно",
  "command": ["python3", "-m", "coverage", "run", "--source=ai_ops_kit", "-m", "pytest", "tests/..."],
  "python": "версия интерпретатора runner",
  "report_sha256": "sha256 точных байтов coverage.json",
  "inputs_sha256": {"ai_ops_kit/...py": "sha256", "tests/...py": "sha256"}
}
```

Изменение любого входа делает все значения `stale`, повреждение JSON/hash — ошибка. Хеши защищают привязку содержимого; они не удостоверяют честность производителя JSON или полноту тестов. Измеритель не запускает тесты, не устанавливает coverage и не объявляет ограниченный набор полным. Реальные coverage-прогоны выполняются через штатный `host_resource_cli`, последовательно с другими тяжёлыми задачами; MAX и ИИ-среда приоритетны.

`--write-baseline` требует измерения **всех** найденных функций, отказывается при unknown/stale/missing, пишет атомарно. Первое создание — явная заморозка; для нового или выросшего долга в существующем файле обязателен `--allow-raise 'обоснование'`, которое сохраняется в истории `raises`. Снижение не требует этого флага. Сравнение работает с неокруглёнными значениями; изменение структуры функции создаёт новый ключ. Снимок исходников и точный scope измерения сохраняются в baseline. Это не запрет ручного редактирования YAML: review изменения заморозки остаётся необходимым.

Непустой глобальный baseline пока не записан: короткий own-medicine охватывает только целевые тесты и core smoke; inline/excluded функции требуют другого evidence или отдельного согласованного решения. Пустой исходный baseline с `measurement: null` — явный bootstrap, а не утверждение отсутствия долга. Отдельный production-валидатор, CI-проводка и повышение обязательности остаются за пределами пилота; #1387 не закрывается целиком.

## Интеграционная проверка

Широкий PR-профиль нашёл отсутствующую запись нового baseline в `registry/enforcement-inventory.yaml`. Инвентарь дополнен существующим потребителем `ai_ops_kit/devtools/crap_score.py`; это регистрация необязательного CLI-пилота, а не объявление обязательного CI-контроля. Пустой bootstrap и незаполненная глобальная заморозка сохранены. Проверяются сам инвентарь и запуск его валидатора из скопированного runtime; прежний неуспешный прогон не считается PASS.
