# #1409 — ручные реальные CI RSS/repeat-серии

Результат: отдельный ручной workflow исполняет существующую bounded suite на точном проверенном SHA, сохраняет wall/CPU/max child RSS, все повторы и raw artifacts. Это подготовка измерений, не готовый baseline.
Затрагиваемые пути: workflow_dispatch/sourceSHA → checkout/toolchain → общий host_resource_cli → существующий bench_performance → base/repeat → swap/boot/source/hash guards → artifact. Обязательные17CI и их политика не меняются.
Инварианты: workflow не запускать и не сливать в этом срезе; нет автоматических PR/push/cron-триггеров, новых credentials/Python-зависимостей, оплаченных прогонов, повышения1.2 или OS-cold/aggregate-tree-RSS claims. Новый официальный pinned upload-artifact сохраняет только measurement output. Очередь1449→1455 завершена; опубликованный11754dec и описание1425 не изменяются.
Failure modes: отсутствующий suite/harness на выбранном SHA; dirty/wrongsource; busy/lostlease; command/repeatfailure; swap/reboot/source/base mutation.
Доказательство: positive — fixture реально создаёт оба output до проверки window; failclosed — swap/reboot/source/hash/exit/lease cases дают ненулевой исход; sideeffect — фактические файлы base/repeat и хэш неизменной базы. YAML/Bash/Python parsing + применимые workflow-регрессии/core smoke/ruff + независимое staticreview. Fixtures не являются Actions metrics.
Не входит: установка в defaultbranch/dispatch, merge, новые расходы, подтверждение бесплатной runner/artifactквоты, новый benchmarkframework, полныйPR-профиль или межверсионное сравнение. Для запуска нужен проверенный sourceSHA с command-suite harness (сейчас опубликован11754dec; текущая main его пока не содержит). При отсутствии capability workflow отказывает явно. Старые шумные данные сохранены отдельно и не назначены чистой базой.

**Исправление 13.11.2026.** Workflow не исполнялся ни разу: `${{ runner.temp }}` стоял в `env` уровня job, где контекст `runner` недоступен. GitHub отвергал файл целиком: ручной dispatch был невозможен, а каждый push в main показывал красный run `performance-baseline` длиной 0 с. `OUT` перенесён в env шага. `ai_ops_kit/devtools/workflow_contexts.py` (тест — `tests/unit/test_workflow_context_availability.py`) сверяет выражения уровня workflow/job (`env`, `runs-on`, `if`, `concurrency`) с таблицей доступности контекстов GitHub — во всех `.github/workflows` и `templates/ci`. На прежней версии файла тест красный; actionlint по всем workflow чист. Вручную: `python3 -m ai_ops_kit.devtools.workflow_contexts [ФАЙЛ.yml ...]`.
