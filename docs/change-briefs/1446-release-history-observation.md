# Почему пульт принял или отклонил историю выпуска

В запуске 45212923929 план 4.16.0 включил 25 изменений и сообщил `history=unknown`. Последняя подтверждённая на тот момент публикация 45212034688 включала 24. Более поздний запуск 45212693133 опубликовать свой артефакт не успел. По архиву Jobs и итоговому плану можно проверить эти факты. В журнале сборки отсутствуют идентификатор действительно прочитанной страницы и причина отказа. Выбрать между задержкой страницы, несовпадением попытки и ошибкой GitHub API задним числом нельзя.

В обычном publisher одна строка журнала свяжет проверку с текущим запуском. Для прочитанного плана нужны проверенные по формату идентификаторы и вычисленный локально digest. Для Actions нужны run, попытка и SHA проверяемого источника. Код результата должен различать недоступные Pages, повреждение проекции, ошибки чтения Actions, отсутствие подтверждённого deploy в просмотренном окне и несовпадение источников.

При любом отказе история останется неизвестной. Публичная проекция, сводка, права и список сетевых запросов сохраняют прежнее поведение. Текст ответа, содержимое плана, URL и исключения в журнал не попадают. Проверки охватывают правильную и устаревшую страницу, неверный digest, отказ API и отсутствие лишней записи в плане или сообщении. Историческая реконструкция не подставляется в приёмку старого запуска.

Если первая целая проекция указывает на более ранний запуск, а Actions уже подтверждает более новый deploy на той же основной ветке, publisher один раз перечитывает тот же официальный URL. Повтор должен совпасть с замеченными run, attempt и checkout, а затем заново пройти всю проверку последнего deploy. Ошибка origin, другой attempt, повторно старая страница или исчерпание бюджета оставляют историю неизвестной. Бюджет просмотра Jobs делится между попытками. Повтор не запускает пересборку, повторный deploy или отправку сообщения.
