# Повторное использование подготовки в тестах установки и обновления

Результат: сократить время проверок setup и update_policy за счёт одной реальной подготовки одинакового исходного состояния на модуль и отдельных файловых копий для тестов.

Затрагиваемые пути: только tests/unit/test_installer_setup.py и test_update_policy_enforcement.py: обычный setup, вывод/артефакты первого часа, остаток конфигурации, повторный setup; обычная подготовка update-ветки, её diff/отчёт, отказ при существующей ветке.

Инварианты: реальные CLI-подпроцессы выполняются в каждом pytest-прогоне; одинаковый результат подготовки переиспользуется только при одинаковых входах. Каждый потребитель получает независимую копию дерева вместе с .git. Все прежние именованные проверки и утверждения сохраняются. Специальные исходные условия (чужие файлы, повреждение, таймауты, отсутствующая/manual policy, --in-place) и все выпущенные теги проверяются отдельными реальными запусками. CI-селекторы, workers, маркеры, таймауты и продуктовый код не меняются.

Failure modes: запись через общий inode/симлинк; утечка .git/index/refs между копиями; кеширование неуспешной подготовки; подмена stdout/журнала путями копии; исчезновение проверяемого перехода (особенно повторной установки/отказа update).

Доказательство: исходные тесты; прямые проверки изоляции содержимого и Git между двумя копиями и шаблоном; ненулевой результат общей подготовки останавливает фикстуру. Сопоставимый замер полных двух модулей с запуском процесса и фикстурами, чередование A/B, одинаковые исходные test ids/outcomes. Итоговый selftests-m и обязательные PR CI; короткий core smoke и ruff. Прогон Git/FS без глобальной Git-идентичности. Независимый review итоговой delta.

Не входит: изменение installer, ограничение релизного корпуса, смена диспетчера pytest и снятие CI-проверок.

## Сопоставимый замер — 24 октября 2026

База: `da0471b1ff56c2c21cd77bb8191209764afdcff7`; CPython 3.14.7, macOS arm64.
В одном checkout менялись только два тестовых модуля. Продуктовый код, остальные исходники,
параметры pytest и окружение совпадали. Три измерения каждого условия, порядок ABBAAB;
других локальных тестовых прогонов одновременно не было. Каждый pytest-процесс последовательно
исполнял все 36 исходных тестов двух модулей (`-n 0`). Время включает запуск, collection,
setup/call/teardown; очистка одинакового временного каталога перед запуском вне замера.
Глобальная и системная Git-конфигурация отключены в обоих условиях.

Это локальный замер двух модулей на одном хосте, а не обещание сокращения всей группы selftests-m

runs.tar.gz (полные логи и JUnit всех шести прогонов). Воспроизведение: скопировать
benchmark.py.txt во внешний каталог, из checkout с этой правкой выполнить
