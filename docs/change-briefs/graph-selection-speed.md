# Убрать повторный разбор файловых импортов при выборе проверок

Результат: сократить время select_tests при неизменном результате выбора.
Пути: build_graph → known_file_spec_targets → dependency uncertainty → selector.
Инварианты: те же edges, uncertainties, affected tests, dependency bindings и fallback.
Failure modes: незамеченный alias; потерянный импорт; кеш пережил изменение входа.
Доказательство: существующие graph/selector регрессии; отсутствие binding-scan без loader;
сопоставимый ABBA замер на одном snapshot с побайтово равными JSON результатами.
Не входит: изменение состава CI, маркеров, risk floors или отключение тестов.
Никакого кеша между вызовами: сокращается только повторная работа внутри анализа одного AST.

## Сопоставимый замер 22.10.2026

Один snapshot `d84d772a081e5e9ce91dbb613ebfafd30d69ed41`, Python 3.14.7/macOS arm64,
одинаковый запрос draft для `ai_ops_kit/shared/secret_formats.py`. Условия отличаются только
исходником repo_graph, загруженным вне snapshot. Сборка всего графа включена, pytest не исполняется.
По одному warmup до/после, затем ABBA × 3: по 6 измерений каждого условия, без локального
тестового прогона во время измеряемой серии. Между вызовами граф собирается заново.

- медиана до: **7,2024 с**, диапазон 7,1351–7,9297 с;
- медиана после: **4,8752 с**, диапазон 4,8440–4,8969 с;
- экономия одного выбора: **2,3272 с (32,31%)**;
- полный JSON select_tests совпадает во всех 14 вызовах, выбранные 248 файлов прежние.

Это тёплая файловая система на одном хосте. Не измерены cold-start ОС, очередь CI и
время до принятия задачи; снижение длительности всей разработки этим процентом не заявляется.
Сырые значения wall/CPU, версии, хэши обоих исходников и snapshot:
`qualification/evidence/graph-selection-speed-20261022/report.json`.
Текст исполнявшегося harness сохранён рядом как `benchmark.py.txt`; его запускать из checkout
кандидата, скопировав в Python-файл вне репозитория. Пути out/snapshot в нём локальные;
они не участвуют в разнице условий. Snapshot строится через git archive фиксированной базы.
Локальные целевые проверки: 148 passed; новый performance guard сначала был RED.
