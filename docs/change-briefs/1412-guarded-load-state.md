# #1412: состояние защищённого чтения resume-артефакта

- **Результат:** реальный `load_guarded()` возвращает различимый по `state` union: absent без data/reason, corrupt с reason, ok с data. Потребитель обязан проверить состояние перед доступом к payload.
- **Пути:** shared.contracts (уже strict) → shared.lifecycle_store.load_guarded → resume/budget/ledger-потребители. Добавляются аннотации, compiler-пробы и регрессии существующего чтения; модуль lifecycle_store целиком strict не объявляется.
- **Инварианты:** те же словари/ключи/причины, существующие YAML/kind/required_keys проверки и побочные эффекты; неизвестные ключи и значения payload остаются dict[Any, Any]. Только ok разрешает data; absent не превращается в corrupt или наоборот.
- **Отказы:** результат откатывается к Any/dict; data доступна до проверки state; отсутствующий файл выдаёт payload; corrupt теряет причину; типизация обещает полную валидацию произвольного YAML.
- **Доказательство:** положительный strict-потребитель и отрицательные пробы фактических вызовов с доказанной мутацией; реальные файлы valid/corrupt/absent, нестандартные YAML-ключи, неизменность bytes/stat; сравнение возвращаемых записей с main; целевые регрессии, core smoke, mypy/Ruff и независимый read-only review.
- **Не входит:** runtime-алгоритм, JSON Schema/Pydantic, новые runtime-словари состояний/валидаторы/нормализация, адаптеры #1434/#1462, новые зависимости. Только локальный commit/diff и evidence: без push/PR/merge, provider/model calls, платных запусков, credentials и активаций. #1412 остаётся открытой.
