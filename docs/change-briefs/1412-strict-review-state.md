# #1412: строгая типизация сохранённого review-вердикта

- **Результат:** потребитель `build_record()` видит форму создаваемого состояния проверки: ревизию, время, boolean verified, три источника доверия и необязательный outcome. `shared.review_verdict` добавлен в существующий strict-ратчет.
- **Пути:** сборка записи → persist → YAML → чтение/Knowledge Graph; независимый review_branch остаётся писателем вердикта. Меняются только аннотации существующего модуля, ратчет, compiler-пробы, регрессии и документация.
- **Инварианты:** исходные значения/порядок/байты YAML при заданном времени неизменны; отсутствие проверки не создаёт запись; ошибка записи возвращает None; источники доверия не смешиваются. Чтение YAML по прежнему проверяет только dict/kind, поэтому не обещает полную типизацию содержимого.
- **Отказы:** Any вместо конкретного результата; неверный verified/ревизия/форма источника незаметны компилятору; непроверенный YAML ошибочно объявлен валидированной моделью; пустой вердикт пишет файл; аннотации меняют runtime-поведение.
- **Доказательство:** реальные положительные и отрицательные compiler-пробы с доказанной мутацией; штатные persist/empty/review-branch/graph сценарии; сравнение записей и YAML с main при фиксированном времени; core smoke, mypy и Ruff; независимый review.
- **Не входит:** Pydantic/JSON Schema повторно не исследуются; runtime-валидация, новые enum/модели истины, адаптеры #1434, область #1455, новые зависимости и версии не меняются. Merge не занимает выделенный #1455 main-slot; широкие локальные проверки только при необходимости через штатную очередь. #1412 не закрывается частичным срезом.
