# Добровольный учёт проектов и активного использования

Источник: [issue #1451](https://github.com/aleksandradovgopolova-boop/ai-ops-kit/issues/1451).

Результат: владелец проекта явно включает локальный учёт, видит минимальную выгрузку и может
отозвать согласие; владелец кита различает наблюдаемые установки, активность за период и
непроверенные сообщения извне. Мировое число неизвестно. Работа независима от состава 4.12.

Затрагиваемые пути: identity проекта → local consent → подписчик run_completed → локальные
даты наблюдения → export/import → дедупликация → отзыв → report; reach adoption; документация
экспериментальной поверхности. Старый reach register не считается согласием на новый учёт.

Инварианты: stdlib + PyYAML; сеть запрещена; UUID псевдонимен; в выгрузке нет имён, путей,
кода, task id, провайдера, секретов или персональных данных. Согласие хранится в git-common,
не наследуется клоном. UUID записывается в отслеживаемый файл и одинаков в клонах/ветках.
Внешний JSON не доказывает подлинность; checksum подтверждает только целостность.

Failure modes: дубли клонов; унаследованное согласие; поддельная выгрузка; replay после отзыва;
пустые/старые/повреждённые данные выглядят как отсутствие пользователей.

Доказательство: positive — событие действительного выполнения после согласия даёт локальную
активность; fail-closed — нет согласия/битая запись/подмена не увеличивают подтверждённый счёт;
side-effect — файл учёта записан и очищен отзывом. Реальные git clone/worktree, проверка
выгрузки на утечки, запрет socket и git remote вызовов. Целевые тесты + core smoke + ruff;
независимый review итогового diff, draft PR. Тяжёлые проверки через общий host-slot.

Не входит: сервер, ключи/аккаунты, отправка по сети, изменение главной метрики продукта,
утверждение мирового total, выпуск или merge. Нормативный запрет телеметрии не снимается.

Ограниченный первый срез #1451: локальное согласие/наблюдение/обмен. Не закрывает всю issue:
проверка provenance установки, updated и связь реального продуктового evidence остаются
отдельными результатами. local_observed не называется verified_active.

## Исправления полного ready-CI

Полный профиль обнаружил три сквозных шва, не покрытых первоначальными целевыми проверками:
CLI-печать в engops, недостижимые из docs/index документы и достижение строгого лимита файлов
поставки. Parser/вывод переносится в существующий роль-слой entrypoints (`cli/adoption.py`),
библиотека остаётся без print. Документы соединяются через текущий индекс и README briefs.
Два модуля работают в дочке: библиотека consent/events/exchange и её процессный CLI. Бюджет
файлов изменяется только штатной записью с реальными установками до/после, без запаса;
print-baseline, тесты и правила не ослабляются. Прямые регрессии: print discipline,
standalone validator, docs coverage, delivery budget и настоящий installed footprint.
Изменение требует нового независимого review итоговой delta и CI точного нового head.


Изолированная установка из archive текущей main ef548c9b и из рабочей ветки
(`PYTHONDONTWRITEBYTECODE=1`, без ambient PYTHONPATH): **689 → 691 файлов**, **6205593 →
6223737 байт** в `.ai/managed`, включая checksums/provenance. Оба новых модуля присутствуют,
доставленный `cli.adoption status` возвращает disabled. Предел числа файлов <690 → <692
записан в `quality/delivery-budget.yaml`; предел байтов не менялся. Замер выполнялся до
записи этого пояснения; docs и сам реестр бюджета в поставку не входят.
