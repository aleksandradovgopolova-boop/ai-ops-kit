# Ограниченное чтение проектных hooks (#1434)

- **Результат:** Python-вход SessionStart/UserPromptSubmit/Stop ограничивает свои read-only фазы 10 с внутри прежнего внешнего лимита 15 с; остаток нужен для cleanup и ответа.
- **Пути:** stdin → project/config/Git binding через существующий shared/gitio → session/migration journal → continuation/artifacts → Stop reconciliation/verification → существующая durable запись.
- **Инварианты:** один monotonic бюджет чтения, только read-only фазы прерываемы; state/claim не меняются при timeout до commit; неизвестный исход записи не повторяется.
- **Инварианты:** прежние binding/receipt/security checks, CLI resume worker, native host_actions и отказ Stop сохранены. Nested native provider не меняется.
- **Failure modes:** FIFO/зависший syscall; суммарное истечение бюджета; cancellation/Git cleanup; timeout после предварительной проверки, до записи; некорректные/изменённые binding или artifacts.
- **Доказательство:** positive hook/Stop; реальные FIFO reads с маркером входа; fail-closed timeout/cancel; сравнение state/claim bytes и повторное получение locks; targeted regressions/core smoke.
- **Поставка:** stock init/update в disposable копиях, delivery footprint/budget, независимое entire-delta review и все применимые CI точного head/base до merge.
- **Граница записи:** durable fsync/readback не прерываются таймером чтения; их ошибка остаётся неизвестным исходом, без очистки свидетельств и автоматического повтора.
- **Граница времени:** бюджет начинается после Python bootstrap. Предшествующий shell Git, загрузка интерпретатора и непрерываемые ожидания ядра не получают новой real-time гарантии; внешний timeout сам по себе не доказывает атомарность или завершение записи.
- **Не входит:** модели, Toast replay, production checkout/install, release, изменение gates, закрытие #1434 или утверждение о живой автономности. Нужна отдельная установленная приёмка под двумя аккаунтами.

CI первого кандидата обнаружил прямой Popen Git вне единого helper. Bounded raw-вызов с cleanup собственной группы переносится в существующий `shared/gitio`; timeout и точный stdout сохраняются. Структурный контракт и его allowlist не меняются.

CI следующего кандидата обнаружил новый silent-pass и недостаток обязательного 10% installed reserve. Cleanup подтверждает завершение ребёнка при отсутствующей группе, не глушит неожиданный живой процесс. Исторические пояснения shared/gitio перенесены сюда без удаления текста; runtime, installer, ратчеты и бюджеты не ослабляются. Проверка — настоящий installed tree с checksum/provenance metadata.

## История единого Git-входа (перенесена из docstrings)

Единый git-хелпер (v3.0.13, блок C самоаудита) — ОДИН источник вызова git для `ai_ops_kit/`.

Прежде идентичная функция `_git` (rc, stdout.strip(), stderr.strip()) была скопирована в 7 модулях,
и НИ ОДНА не задавала timeout: зависший git-субпроцесс (сеть/lock/hook) вешал весь прогон навсегда.
Здесь — один вызов с таймаутом по умолчанию; при таймауте возвращается rc=124 (соглашение GNU timeout)
и понятный stderr, а не блокировка.

Плоский слой `tools/` снят в 4.0 — единственный вход к git теперь пакет `ai_ops_kit/`, а инвариант
«ни одного неограниченного git-субпроцесса» держит структурный тест `tests/contracts/test_no_unbounded_git.py`.

`git(root, *args)` — форма `git -C <root> <args...>`; `run(args, cwd=…)` — остальные формы (clone,
команды с `cwd=` вместо `-C`), которым `-C <root>` не подходит. Обе стягивают stdout/stderr через
`.strip()`; где вывод нужен ДОСЛОВНО (`git show <ref>:<path>`) или значима ведущая колонка
(`git status --porcelain`), вызывай git raw с явным `timeout=` — так задумано, тест это допускает.

`-z` ОБЯЗАТЕЛЕН, а не украшение. При `core.quotePath` (включён по умолчанию) git отдаёт
не-ASCII имена в escape-кавычках: `"context/product/\320\236..."`. Такой путь не совпадает ни с
одним сигнальным паттерном, и гейт связности превращал `changed` в `not_changed` — утверждение
вместо признания. Для русскоязычного продукта это отменяло гейт целиком. `-z` отдаёт имена как
есть, разделённые NUL, и попутно снимает вторую дыру: путь с переводом строки или запятой больше
не распадается.
