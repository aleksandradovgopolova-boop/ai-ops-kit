# #1405 — уборка объявлений и жизненный цикл обязательных проверок

Результат: существующий garden называет структурные дубли skills/workflows и проверок, роли без статических потребителей, явно снятые/заменённые принципы и конфликтующие объявления со ссылками. Неподключённые capabilities остаются существующим dormant-инвентарём. Новая обязательная проверка без роли-владельца и условия вывода краснеет в существующем контракте реестра.
База: main `db656bb868029102498ca3348e3d25b61c693efa`; open PR/issues, общий active-work и ветки проверены. #1434 Codex autostart и Claude #1402/#1425/#1426 не затрагиваются. Собственная заявка `garden-completion-1405`, takeover не используется.
Сквозные пути: ограниченные исходники skills/workflows + registry/agents/workflows + quality/gates + rules/decisions/architecture → read-only `garden_inventory` → существующие garden.collect/render/CLI; registry owner/retirement_condition → существующий `test_gate_prevents.audit` → обязательная CI-группа contracts. Источники обязательных CI — существующие premerge-checks/required-contexts; дополнительные факты об их владельце/выводе хранятся в quality/gates.required_checks_lifecycle, состав сверяется без второго списка допуска. Матрицы и aliases разрешает существующий validate_required_contexts. Собственные unit-тесты, brief/index и fragment; новые пакеты и независимые гейты не появляются.
Инварианты: только stdlib + pyyaml; без сети/моделей/исполнения анализируемого кода; детекторы не меняют файлы; повреждённые/нечитаемые входы не становятся пустым зелёным отчётом; роль-владелец — существующий responsible_role, список MVP8 и применимость проверок сохраняются.
Смысл сигналов: точное нормализованное совпадение текста — кандидат на консолидацию, не разрешение удаления; отсутствие роли в известных структурных потребителях не доказывает отсутствие ручного вызова; retired/supersedes и одинаковый id с разными объявлениями — наблюдаемые факты. Произвольная смысловая эквивалентность/противоречие прозы не измеряется и явно названа пределом отчёта, а не «садом без противоречий».
Failure modes: свой реестр засчитывается как использование; одинаковая проверка разных областей ошибочно считается дублем; сломанный YAML выглядит отсутствием кандидатов; симлинк читает вне корня; обязательная проверка без владельца/условия незаметно проходит CI.
Доказательство до реализации: реальные временные файлы/реестры для positive, fail-closed и доказательства изменения входа с побайтовой неизменностью чтения; отрицательные пробы существующего gate-контракта; затем target/core, применимые линтеры/документация, широкий PR-профиль при изменении policy и независимый entire-delta review; все обязательные CI точного head/base до merge.
Не входит: автоматическое удаление/подключение модулей, новая семантическая модель, paid-evals, изменение protection/security/credentials/billing, Ruff/dependencies, релиз пакета/consumer rollout. Закрытие #1405 только после сверки первоначальных критериев на фактическом отчёте и подтверждённого merge.
