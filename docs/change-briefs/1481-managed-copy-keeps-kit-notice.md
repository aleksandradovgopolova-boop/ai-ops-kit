# #1481: установленная копия кита несёт его лицензию

Результат: после `init` и `update` в проекте рядом с кодом кита лежит текст его
условий — `.ai/managed/LICENSE`, побайтно равный `LICENSE` той версии, что стоит.
В нём адрес условий и строка `Required Notice:`. Лицензия самого продукта не
меняется и не подменяется.

Повод: замер 10.11.2026 на main `32fb285b`. Свежая установка кладёт в проект 699
файлов кита и ни одного файла условий: единственный `LICENSE` в проекте — собственный
файл продукта. С #1470 кит распространяется по PolyForm Noncommercial 1.0.0, а эти
условия требуют, чтобы каждый получатель копии получил их текст или адрес и строки
`Required Notice:`. Следующий выпуск станет первым под новыми условиями — и без
правки разошёлся бы по проектам без них. Это механическое расхождение поставки, а не
юридическое заключение.

Затрагиваемые пути:

- состав поставки — `manifest/ai-ops-manifest.yaml -> update_policy.managed_set`
  (один новый путь `LICENSE`), его читает `installer/delivery_ops.py:managed_set`;
- `init` — копирование и запись контрольных сумм;
- `diff`/`update` — старая установка без файла получает его как `add`, смена текста
  между версиями приходит как `replace`;
- `status`/повторный `init` — удалённый или изменённый файл виден как дрейф;
- откат неудачного обновления (#1486) — файл входит в общий снимок `.ai/managed`;
- выбор пакетов в `.ai-ops.yaml -> packages` — файл не закреплён ни за одним пакетом
  и потому едет при любом выборе;
- потолки поставки `quality/delivery-budget.yaml` — число файлов и объём.

Инварианты:

- Источник текста один — корневой `LICENSE` кита. Копия побайтная: второго текста,
  шаблона или строки в коде нет, расходиться нечему.
- Условия едут вместе со своей версией. Установка версии под MIT несёт MIT, версия
  под PolyForm — PolyForm. Опубликованные выпуски, теги и уже стоящие копии не
  переписываются: у копии 4.12.0 условия меняются только вместе с её кодом, при
  обновлении.
- Файлы владельца не трогаются: корневой `LICENSE` продукта, `.ai/project/**`,
  `.ai/custom/**`.
- Содержание `LICENSE`, контакт для коммерческих запросов (#1471) и сами условия не
  меняются. Раскладка `.ai/` не переезжает: новый файл — аддитивное изменение.

Основные failure modes:

1. Путь выпадает из состава поставки (правка манифеста, перенос в dev-only) — копии
   снова уходят без условий, а установка зелёная.
2. Файл попадает в пакет, и проект с выбранным подмножеством пакетов его не получает.
3. Текст в проекте изменён или удалён, а кит считает установку целой.
4. Обновление заменяет лицензию продукта вместо лицензии кита.
5. Сбой обновления оставляет новый файл условий при старом коде.

Доказательство — `tests/unit/test_kit_license_ships_to_child.py`:

1. positive — после настоящего `init` файл на месте, побайтно равен исходному,
   содержит адрес условий и `Required Notice:`, записан в контрольные суммы; старая
   установка без файла получает его обновлением, повторное сравнение пустое.
2. fail-closed — изменённый и удалённый файл дают дрейф и ненулевой `status`;
   повторный `init` поверх изменённого текста отказывает; состав поставки без
   `LICENSE` роняет проверку, в том числе при выборе одного пакета.
3. side-effect proof — лицензия продукта побайтно прежняя после `init` и `update`;
   смена текста в источнике приходит в сравнение как `replace` (условия идут за
   версией); после сбоя обновления дерево проекта побайтно прежнее.

Потолки: число файлов 700 -> 701 и объём под факт с прежней долей резерва 0.10 —
записями в ленте подъёмов с замерами двух настоящих установок.

Не входит: `NOTICE.md` (атрибуции источников идей, код не копировался — условия его
доставки не требуют); отдельная проверка лицензии в `doctor`; текст README и условий;
уведомление владельцев о смене условий при обновлении с 4.12.0 (это слой описания
выпуска); branch protection, выпуск и тег.
