# Прополка юнитов — фаза анализа

Замер 2026-08-25. Обосновывает работу `unit-weeding-is-mutation-proven`
(`planning/plan.yaml`, цель `green-means-checked`). Ярусы уже в main (PR #262, `f0abbcd`).

Цель работы — не «уменьшить набор», а сделать его **читаемым ярусами** и срезать **только
доказанно-избыточное**. Ниже — что показал замер перед резом.

## 1. Пирамида фактически не размечена

Перепись по AST всех тест-функций (`testpaths = tests`):

| | функций | доля |
|---|---:|---:|
| **Всего** | 2686 | 100% |
| С ярусным маркером (`unit`/`contract`/`integration`/`e2e`) | 421 | 15% |
| **Без ярусного маркера** | 2265 | **84%** |

По маркерам: `unit` 382, `contract` 39, `slow` 208 (ортогонален ярусу), `integration`/`e2e` — 0.
Даже верхние ярусы размечены не полностью: `tests/contracts` — 63 из 102 функций без маркера,
`tests/integration` — 4 из 4 без маркера.

Маркеры зарегистрированы в `pytest.ini` (`critical_path, unit, contract, integration, live,
regression, slow`) и `--strict-markers` включён — но strict ловит только *незарегистрированный*
маркер, не *отсутствующий*. Поэтому 84% тестов не относятся ни к какому ярусу, и **пирамиду нельзя
прочитать числом**. Резать по ярусу, пока это так, — вслепую.

→ Критерий готовности #1: каждая тест-функция несёт ярусный маркер, инвариант это держит.

## 2. Перекрытие новых ярусов с юнитами — частичное, не полное

Два верхних яруса (`tests/contracts/test_platform_e2e.py`, `test_product_contract_tier.py`)
покрывают ту же **площадь**, что юниты `test_product_contract.py` (9 функций) и
`test_product_registry.py` (11 функций), но проверяют **грубее**. Юниты держат инварианты, которых
у ярусов нет:

- агрегация-без-второй-правды: `contract.counts == product_templates.report` (ярус проверяет лишь
  `valid == len(artifacts)`);
- fail-soft: битый продукт даёт строку `error`, а не топит флот;
- честный `not_computed` по граням health/risks без впрыска.

**Вывод:** «удалить юнит, раз площадь закрыл ярус» — молча срежет защиту. Выхлоп прополки от
перекрытия с ярусом **мал**. Ярусы — страховочная сеть, а не разрешение резать. Это меняет ожидание
«срезать 350»: большого сокращения не будет.

## 3. Настоящий дубль — 24 монолитных `*_selftest`

У 26 модулей есть и `test_<модуль>.py`, и `test_<модуль>_selftest.py`. Селфтесты перенесены из
продакшн-модулей **дословно** (v3.30, чтобы убрать тестовый код из того, что едет в дочку). Форма —
одна мега-функция: весь файл = один `def test_..._selftest`, десятки логических проверок протянуты
через хелпер `expect()` в **один финальный `assert ok`**.

Крайние примеры:

| selftest | функций | строк | рядом гранулярный `test_<m>.py` |
|---|---:|---:|---|
| `test_execution_pipeline_selftest` | 1 | 1284 | 215 функций / 345 assert |
| `test_ai_ops_run_selftest` | 1 | 610 | 90 функций / 145 assert |
| `test_orchestrator_selftest` | 1 | 316 | 14 функций / 28 assert |
| `test_tool_broker_selftest` | 3 | 294 | 30 функций / 50 assert |

Из 26 пар **24 — монолиты** (1 функция); гранулярны только `test_research_tools` и
`test_tool_broker`. С точки зрения QA монолит — низкая диагностическая ценность (один красный на
1284 строки), маркер `slow`, и площадь, которую гранулярный сосед уже покрывает лучше.

AGENTS.md требует, чтобы селфтест **не жил в продакшн-модуле** — его дом `test_<module>_selftest.py`.
Он **не** требует, чтобы монолит существовал. Значит честный ход, где гранулярный файл уже покрывает
то же: перенести уникальные случаи монолита в гранулярный файл и снять монолит — в продакшн-модуле
тестового кода не остаётся, инвариант AGENTS.md соблюдён.

## 4. Метод — мутационный, не по догадке о перекрытии

Переиспользуем существующее: `ai_ops_kit/devtools/mutation_probe.py` + `quality/mutation-probes.yaml`
(это тот же механизм, что `pytest.ini` уже называет: мутационное ревью показало, как `--cov` скрывал
неисполняемые `contour_consistency_evidence`/`_topo_order`/`_admission` при 1678 зелёных тестах).

Правило реза: тест — кандидат на удаление **только если каждая мутация, которую он ловил, остаётся
красной у другого теста** (ярус или гранулярный юнит). Ничего, чья смерть оставляет пробу зелёной,
не режется.

## 5. Порядок работы (фаза реза, отдельно)

1. Разметить набор ярусами; добавить инвариант «новый тест без ярусного маркера краснеет».
2. По 24 монолитам, от крупных: измерить перекрытие с гранулярным соседом мутациями; перенести
   уникальные случаи; снять монолит; проверить, что ни одна проба не позеленела.
3. Число тестов «до/после» — в newsfragment как **следствие**, не цель.

## Чего делать нельзя

- Резать по площади/догадке о перекрытии (п. 2 показал: потеряем защиту).
- Удалять селфтесты оптом (AGENTS.md; и некоторые модули могут покрываться *только* монолитом —
  ловит мутационное правило).
- Делать «меньше тестов» самоцелью. Цель — `green-means-checked`, а не малое число.
