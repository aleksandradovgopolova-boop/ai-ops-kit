# Пульт состояния AI Ops Kit

Одностраничный дашборд состояния кита: паспорт продукта, здоровье, дочки и ближайшие
задачи — всё на один экран, тёмная тема. Числа читаются вживую из `data.json`.

## Файлы

| Файл            | Что это                                                                 |
|-----------------|------------------------------------------------------------------------|
| `index.html`    | Страница пульта. Тёмная, самодостаточная. При открытии подтягивает `data.json`. |
| `build_data.py` | Сборщик: читает реестр/гейты/конфиги + открытые задачи GitHub → `data.json`. |
| `data.json`     | Снимок показателей. Пересобирается сборщиком.                            |

## Как получить свежие числа

Из корня репозитория кита:

```bash
python3 dashboard/build_data.py
```

Сборщик перезапишет `dashboard/data.json` текущими значениями (версия, канал, гейты,
агенты, валидаторы, тесты/покрытие, дочки, обкатка в поле, открытые задачи). Зависимостей
нет — только стандартная библиотека Python. Задачи GitHub берутся через `gh` (должен быть
установлен и авторизован); без него секция задач останется пустой, а не выдуманной.

Ключи запуска: `--repo <путь>` (если запускаете не из корня кита), `--out <файл>` (куда
писать `data.json`).

## Как развернуть

`index.html` при открытии делает `fetch("data.json")` из своей же папки — поэтому
достаточно отдать оба файла как статику с одного адреса:

- любой статический хостинг (GitHub Pages, S3, nginx, `python3 -m http.server`);
- открывать через `http://…`, а не двойным кликом (`file://` — браузеры блокируют fetch
  локальных файлов).

Быстрый локальный просмотр:

```bash
python3 -m http.server -d dashboard 8080
# затем открыть http://localhost:8080/
```

Если `data.json` рядом не окажется или сеть закрыта, страница молча показывает встроенный
снимок и помечает источник как «снимок» вместо «живые данные». Этот встроенный снимок
`build_data.py` переписывает при каждой сборке (блок между маркерами `SNAPSHOT:BEGIN/END` в
`index.html`, руками не править) — так локально/статически открытая страница остаётся такой же
актуальной, как `data.json`, а не отстаёт.

## Автообновление (готовый рабочий процесс)

В комплекте есть `status-dashboard.yml` — рабочий процесс GitHub Actions, который сам
пересобирает `data.json` и публикует пульт на GitHub Pages: числа освежаются без ручных
шагов.

Установка (один раз):

1. Положите файл в `.github/workflows/status-dashboard.yml`, а папку `dashboard/` — в
   корень репозитория.
2. Settings → Pages → Source: **GitHub Actions**.
3. Готово. Дальше он запускается сам:
   - по расписанию — каждый день в 06:00 UTC (частота меняется в блоке `cron`);
   - при изменениях в `main` (VERSION, `registry/**`, гейты, сама папка);
   - по кнопке **Run workflow** во вкладке Actions.

Адрес пульта появится в логе шага публикации и в Settings → Pages. Токену нужны только
чтение задач и публикация Pages — прав на запись в репозиторий процесс не требует.

## Что честно, а что нет

Пульт держит принцип самого кита: **что не доказано из источника — помечено как
недоказанное.** Если сборщик не смог достать показатель, в `data.json` будет `null`, а на
странице — «—», без подстановки правдоподобного числа.

Три показателя (команды владельца, pre-commit-проверки, извлекатели поверхности) сегодня
живут только в прозе документации и заданы в `build_data.py` явными константами
(`PROSE_PINNED`) с пометкой источника — их правят вручную при изменении. Остальное
выводится из файлов и GitHub при каждом запуске.
