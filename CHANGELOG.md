## [4.0.0] — 2026-09-04 · снятие плоского слоя tools/ — точки входа только пакетные (BREAKING)

BREAKING: слой совместимости `tools/` (112 шимов-алиасов) снят физически. Точки входа зовутся пакетно (`python3 -m ai_ops_kit.<pkg>.<mod>`, PYTHONPATH=.ai/managed), импорт — `from ai_ops_kit.<pkg> import <mod>`. Обновление дочки штатное (`ai-ops update` перегенерирует управляемые команды); рукописные вызовы `.ai/managed/tools/<x>.py` правятся по MIGRATION_GUIDE_4.0.md. Первый шаг (3.40) предупреждал о сносе; этот — снимает.
## [3.40.0] — 2026-09-03 · warn-минор перед 4.0: снятие плоского слоя tools/ предупреждается заранее

Перед мажором 4.0, который физически снимет плоский слой совместимости `tools/` (≈112 тонких алиасов на пакеты `ai_ops_kit/*`), кит теперь ПРЕДУПРЕЖДАЕТ заранее: прямой запуск плоской точки входа `python3 .../tools/X.py` печатает в stderr DeprecationWarning с пакетной заменой (`python3 -m ai_ops_kit...`) и ссылкой на MIGRATION_GUIDE_4.0.md. Best-effort по sys.argv[0] из одного места (`tools/_bootstrap.py`); срабатывает только на прямой запуск скриптом, молчит на импорт и на валидаторы; код возврата не меняется. Полный снос — в 4.0.

## [3.39.1] — 2026-09-01 · Fix C для ревьюеров + parallel-safety не валит апдейт кита

### Исправлено
- **Рубер-штамп `code_review`/`architecture_review` переопределён через эталон** (Fix C для ревьюеров,
  #388). Страж валил `pass` без read-op судьи, но claude-cli read-op детерминированно не эмитит —
  каждое настоящее ревью штамповалось в fail, и ни один прогон не мог закрыть блокирующее ревью
  (полевой блокер, ii-sreda). Теперь вовлечённость определяется сверкой с ДОСТАВЛЕННЫМ файлом: кит
  сам знает состав правки, ревьюер обязан цитировать evidence на изменённый файл, и `pass` без
  read-op проходит только заземлившись на правку. Рубер-штамп без заземления по-прежнему падает.
  Подтверждено вживую: claude-cli закрыл оба ревью на ii-sreda `material-ready-notification`.
- **`parallel-safety` пропускает собственные install/update-PR кита** (#384). Апдейт сам мигрирует
  план/историю, а первый заезд на голый репозиторий вносит весь план-стор — гейт по построению не
  пропускал ни один апдейт с миграцией и ни один первый заезд на новую дочку. Распознаётся по правке
  `.ai/managed/VERSION`; смешанные фиче-PR по-прежнему краснеют.

## [3.39.0] — 2026-08-31 · Судья приёмки сверяет met с доставленным файлом (Fix C)

Точечный выпуск на пути к `stable`: снят последний технический барьер к автоматическому
DeliveryReceipt.

### Fixed
- **Приёмка больше не проваливается на корректном вердикте из диффа.** Замер (шесть живых прогонов
  `claude -p`) показал: независимый судья приёмки детерминированно выносит верный `met` с точными
  цитатами прямо из диффа, но чтение файла отдельным шагом (`{"op":"read"}`) не делает — и прежний
  страж обнулял такой вердикт как рубер-штамп. Из-за этого чистая авто-приёмка (а с ней и
  `DeliveryReceipt sha_verified`) была недостижима на практике, хотя судья судил верно.
- **Авторитетное чтение доставленного файла теперь делает сам кит.** Основание `file` (цитата
  подтверждена в доставленном файле на проверенном SHA) стоит перед `post-state` (диффом); рубер-штамп
  переопределён как «ни одного чтения судьёй И ни одна цитата не сверена по доставленному файлу».
- **Страж стал строже, а не слабее (усиление #364).** «Выполнено», чья цитата есть в диффе, но
  отсутствует в доставленном файле (устаревший или частичный дифф), больше не принимается. `writer≠judge`
  сохранён: смысловой вердикт выносит независимый судья, кит лишь подтверждает цитату по эталону.

## [3.38.0] — 2026-08-31 · Product Operating System замкнута (5/5)

Этот релиз закрывает пять целей продуктовой ОС и выпускает работу, накопившуюся на `main` после
тега 3.37.0. Заголовки версии:

### Капстоун: автономное перепланирование — `ai-ops replan`

Цикл сам сводит приоритеты плана к реальности **без человеческого `--replan`**, замыкая Фазу 5
(Observe → … → Replanning). Граница автономии — вариант B (решение владельца, перенос одобренной
4-классовой модели ночного обзора на план): переприоритизация (класс A) обратима, детерминированна,
**СОСТАВ РАБОТ НЕ МЕНЯЕТ**, каждый сдвиг подписан «почему» — применяется сама (`--apply` пишет
машинный артефакт `.ai/project/replan/latest.yaml` дочки, авторский `planning/plan.yaml` и main не
трогает); структурные изменения — только предложением. Автономное удаление работ невозможно по
механизму (`_check_same_work_set`) — прямой ответ полевому провалу ии-среды. Детерминизм, `budget=0`,
kill-switch, policy-гейт. Второй правды не заводит: сводит `next_work.compute` /
`delivery_plan.resolve`+`git_disagreements` / `risk_register` / `backlog_prioritize`.

### Approval-gated слияние дублей — `ai-ops backlog merge`

Вторая половина исхода `duplicates_detected_and_merged`. Детектор как и прежде ПРЕДЛАГАЕТ; кит СЛИВАЕТ
дубли только по явно одобренным человеком парам (`--approved` файл), никогда сам. GitHub не «сливает»
Issue — закрывает ДУБЛЬ с кросс-ссылкой на канонический (`state=closed`, `reason=not_planned`),
канонический оставляет открытым; обратимо. Без `--apply` — dry-run; провал комментария не закрывает
дубль; все мутации GitHub через единственный шов `GitHubClient._gh_mutate` (только `gh`).

### Product OS достигнута 5 из 5

`roadmap-and-delivery` · `ai-product-operations` · `product-operating-layer` ·
`autonomous-product-loop` · `backlog-intelligence`. Остался единственный барьер `stable` —
owner-led второй полевой прогон (`owner_reaches_verified_pr_without_patching_the_kit`).

Плюс накопленная с 3.37.0 работа: миграции шаблонов + POLICY.yaml v2, команда `ai-ops drift`,
периодический `ai-ops audit` по расписанию, честное закрытие ложно-закрытых работ, K6-расщепление
god-функций ядра и др. (полный список — `newsfragments/`).
