concurrency-preflight: детекция коллизий по открытым PR теперь пагинирует список файлов
каждого PR до конца (а не только первые 100), и не выдаёт усечение за факт. Раньше PR,
трогающий больше 100 файлов, отдавал лишь первую страницу — пересекающийся 101-й путь был
невидим, и preflight сообщал «пересечений нет» при реальной коллизии. Если полнота не
гарантирована (лимит или потолок страниц у REST, потолок 100 у gh), результат помечается
`partial`, а не `checked`. Дополнительно owner/repo, извлечённые из git-remote, валидируются
по `^[A-Za-z0-9._-]+$` (и прогоняются через `urllib.parse.quote`) перед подстановкой в URL
GitHub API — имя вида `x?foo` или `..` больше не подмешивает квери/сегмент, а даёт
fail-closed `unavailable`.
