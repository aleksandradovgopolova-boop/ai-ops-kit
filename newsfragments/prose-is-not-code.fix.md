Комментарии перестали флагаться как код. На замере 23.09 шесть флагов `react_dangerous_html` из восьми стояли не на коде, а один — на комментарии, утверждавшем ОБРАТНОЕ: «рендер React-элементами без dangerouslySetInnerHTML». Отсечение по расширению файла этого не ловило: `.ts` с комментарием расширением не отличается от `.ts` с кодом. Теперь содержимое комментариев заменяется пробелами перед разбором — номера строк в находках остаются прежними, код рядом с комментарием по-прежнему ловится, а `https://` внутри строки не принимается за комментарий. Разбор включается только на файлах, где что-то нашлось, поэтому скан не замедляется. Остаток назван честно: имя правила в ЗНАЧЕНИИ yaml по-прежнему поднимает флаг — молчание там требовало бы доказательства, что YAML не содержит рендерящихся шаблонов. (#1112)
