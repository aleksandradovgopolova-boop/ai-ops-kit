`run`/`do`, вызванные без текста задачи (только `--feature <wid>`), больше не отправляют писателю
пустую задачу. Раньше движок строил задачу писателю ТОЛЬКО из позиционного аргумента, а не из
спеки: `./ai-ops run --execute --feature <wid>` без текста давал писателю пустой блок «=== ЗАДАЧА
===», и он либо не писал ничего, либо авторил спеку про то, что «задача пуста» — при полностью
заполненном features/<wid>/spec.yaml. Теперь, когда текста нет, задача собирается из заполненных
(`status: complete`) разделов спеки (цель, объём, критерии приёмки и далее). Fail-closed: нет спеки
или заполненных разделов — задача остаётся пустой, поведение как раньше (кит честно заблокирует).

Заодно: когда author-фаза (Spec-First) не смогла разобрать YAML артефакта requirements/spec, в
run-report теперь виден ОБРЕЗАННЫЙ СЫРОЙ ответ модели (`author_output_tail`). Раньше было только
«author не вернул валидный YAML», а что именно вернула модель — пусто, проза, обрезано — терялось,
и причину невалидной спеки нельзя было увидеть из отчёта.
