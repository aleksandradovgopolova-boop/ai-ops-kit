Governance входит в путь исполнения (Фаза 4, находка аудита 24.08 «policy_engine/decision_log декоративны, не звались из рантайма»). Новый шов `ai_ops_kit/governance/enforcement.py` перед открытием PR считает решение политики о доставке, берёт одобрение ТОЛЬКО из human_override и пишет решение в decision_log — композируя три уже построенных, но не подключённых куска. По умолчанию режим **observe**: решение записывается, доставку НЕ останавливает (виден радиус до включения); режим **block** (`.ai-ops/POLICY.yaml`) реально блокирует `require_approval` без одобрения. Шов вставлен в транзакционный контроллер `ai_ops_run`. Fail-closed по политике (нет POLICY.yaml → require_approval), fail-open по журналу (недоступный decision_log не роняет доставку). ИЗВЕСТНЫЙ БЛОКЕР Фазы Б: шаблон POLICY.yaml объявляет уровни под `autonomy:`, а движок читает `default:`/`actions:` — схемы надо свести до включения block.
