Извлекатель поверхностей продукта теперь видит ОПЕРАЦИИ GraphQL из схемы (SDL) — первый вид
поверхности `api`. SDL разбирается детерминированно по тексту, без поднятия GraphQL-сервера,
интроспекции и сети: поля КОРНЕВЫХ типов `type Query { … }`, `type Mutation { … }`,
`type Subscription { … }` и их расширений `extend type Query { … }` считаются операциями API продукта
(имя операции = имя поля, ref = `file:line|<operation>`). Обычные `type`/`input`/`enum` — это модель
данных, их поля операциями НЕ становятся. Комментарии `#` и описания-строки
(`"""docstring"""`, `"…"`, дефолтные строковые значения аргументов) маскируются, чтобы текст в них не
дал ложных операций; незакрытый блок битого файла пропускается. Как текстовый (не полноценный
GraphQL-парсер) разбор он помечает операции `confidence: inferred` (видны в каталоге, но прогон не
блокируют). Осознанно НЕ выводятся: схемы, заданные SDL-строками в коде (gql`…`/graphql-tag),
code-first (Nexus/TypeGraphQL/Strawberry), интроспекция, переименование корневых типов через
`schema { query: MyQuery }`, директивы схемы и объединённая схема federation на уровне рантайма (видны
только per-file `extend type`).
