Сканер видит inline-код интерпретатору в скриптах оболочки и Python, а не только в JS. Флаг
ставится, когда `node`, `python3`, `bash`, `perl`, `php` и соседям передан код, СОБРАННЫЙ
ПОДСТАНОВКОЙ:

* флагом кода (`-e`, `-c`, `-r`, склейки `-Sc`/`-pe`, `--eval=…`) — в Python f-строка, склейка,
  `.format`, `%` или имя с данными, в оболочке `$VAR`, `${…}`, `$(…)` или обратные кавычки внутри
  слова кода;
* на вход — heredoc без кавычек у ограничителя с подстановкой в теле (`python3 - <<EOF`),
  here-string (`node <<< "$X"`) или конвейер через любое число ступеней (`echo "$X" | tr a b |
  bash`, `curl … | bash -s -- --yes`);
* позиционными формами Python — `asyncio.create_subprocess_exec`, `os.execlp`/`spawnlp`,
  звёздочка по литеральному списку.

Не флагуется код, который исполняет ровно написанное в файле: литерал (`node -e '<код>'` с данными
через окружение или stdin), код из констант этого же файла (имя, которому на уровне модуля один раз
присвоено литеральное значение и которое больше нигде не связывается; файл с `globals()`,
`setattr`, `vars()`, `__dict__` или `import *` констант не имеет), чистые обёртки литерала
(`textwrap.dedent`, `.strip()`). Аргументы после сценария (`bash "$SCRIPT" -c "$x"`) — аргументы
сценарию, а не флаги интерпретатору.

На реальном продукте боевых адресов по-прежнему 4: все четыре места с inline-кодом там литеральные
или собраны из констант файла.
