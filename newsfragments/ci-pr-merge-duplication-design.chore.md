Разобран дубль обязательного набора проверок между прогоном PR и прогоном на merge-коммите (#1376): по данным репозитория безопасного среза из PR писателя нет — отмена устаревших прогонов уже включена, а оставшийся дубль при squash-слиянии снимается только решением владельца о merge queue. Рекомендация и нужное решение записаны в `docs/change-briefs/ci-pr-merge-duplication-design.md`; workflow и branch protection не тронуты.
