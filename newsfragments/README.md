# newsfragments — записи для CHANGELOG, по одному файлу на изменение

Гейт `towncrier check` в CI требует, чтобы в ветке была ДОБАВЛЕНА хотя бы одна запись. Причина —
замер (EV-1112): 236 версий за 40 дней и ни одного механизма, проверяющего выпуск; `CHANGELOG.md`
правился 401 раз — в 4.5 раза чаще любого файла кода.

**Имя файла:** `<что-это>.<тип>.md`, например `provider-decision.fix.md`.
Типы: `feat` (новое), `fix` (исправлено), `quality` (механизмы и проверки), `limit` (известное
ограничение выпуска: что ещё не сделано или работает не везде), `chore` (служебное — план, история,
реестр решений).

**Внутри** — одна-две фразы на языке результата, а не изменения кода: что теперь верно для человека.
Простым языком: без внутренних терминов (глоссарий — `registry/communication-policy.yaml ->
product_glossary`), кодов правил линтера и имён_через_подчёркивание. Цель по длине — до 200 знаков
на запись (`release_notes.layer_a.max_item_chars`); замер очереди —
`python3 -m ai_ops_kit.validation.validate_release_notes --fragments`.

**`limit` — строже всех.** Такой фрагмент дословно попадает в раздел «Известные ограничения» слоя
владельца (со ссылкой на имя файла), а слой проверяется строго: длиннее предела или с жаргоном —
бамп версии откажет. Имя файла — латиница, цифры и дефисы (`lint-hook-python-only.limit.md`), оно же
служит ссылкой на источник. Вручную раздел «Честно: что ещё не сделано» в CHANGELOG больше не пишем.

`towncrier build` в CI не запускается, только `check`: очередь сливает в раздел версии
`release_bump` на бампе. Старые разделы `CHANGELOG.md` остаются как есть.
