Команда `ai-ops replan` — капстоун Фазы 5: цикл сам сводит приоритеты плана к реальности, БЕЗ
человеческого `--replan`. Замыкает продуктовую ОС (Observe → Understand → Prioritize → Execute →
Evaluate → Learn → **Replanning**): семь шагов уже поставлялись, не хватало замыкающего.

Граница автономии — перенос уже одобренной 4-классовой модели ночного обзора на план: ПЕРЕПРИОРИТИЗАЦИЯ
(класс A) — обратимая, детерминированная, СОСТАВ РАБОТ НЕ МЕНЯЕТ (ни одной не добавляет и не удаляет),
каждый сдвиг подписан «почему» — применяется САМ (`--apply` пишет машинный артефакт
`.ai/project/replan/latest.yaml` дочки, авторский `planning/plan.yaml` и main НЕ трогает, не коммитит).
СТРУКТУРНЫЕ изменения (закрыть работу в историю, пометить начатой) — только ПРЕДЛОЖЕНИЕМ на одобрение
человека, автоматически не применяются. Автономное удаление работ невозможно по механизму
(`_check_same_work_set`), а не по обещанию — это прямой ответ полевому провалу ии-среды (writer
удалил 27 из 57 работ и получил ложный green). Модуль детерминирован и НЕ ЗОВЁТ МОДЕЛЬ
(`Budget(max_model_calls=0)`), с kill-switch (`AI_OPS_REPLAN=off` / файл-сигнал) и policy-гейтом.

Второй правды не заводит (dp-001): порядок берётся из `next_work.compute` (той же ранжировки, что
советует `ai-ops next`), расхождение план↔реальность — из `delivery_plan.resolve` (drift) и
`git_disagreements`, бэклог — из `backlog_prioritize`, риски — контекстом. «Не проверено» (нет плана,
ствол не найден, бэклог недоступен) называется в `unverified`, а не сворачивается в «расхождений нет».
