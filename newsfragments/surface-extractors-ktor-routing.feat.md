Извлекатель поверхностей продукта научился видеть **серверные маршруты Ktor** (Kotlin, вид `route`): из `.kt` детерминированно и без исполнения читаются method-вызовы DSL `get("/p") { … }` / post / put / patch / delete / head / options со строковым путём-литералом, склеенные с литеральными префиксами объемлющих блоков `route("/prefix") { … }` — вложенность учитывается балансом скобок (`route("/a") { route("/b") { get { … } } }` → `GET /a/b`), а метод без пути (`get { … }`) сводится к самому префиксу. Разбор сужен к индикатору Ktor (импорт `io.ktor`, `routing {` либо `install(Routing)`), а member-вызовы `x.get { }` отсекаются, чтобы чужой метод объекта не сошёл за маршрут. Как у go-web / spring / rails / aspnet, это текстовый (не AST) разбор → `confidence: inferred` (в каталог попадает, прогон не блокирует). Осознанно НЕ выводятся: обёртки `authenticate { … }` и интерсепторы, `route`/метод через переменную или интерполяцию `$…`, тип-безопасный `resources`-плагин (`get<Article> { }`), регекс-роуты и рантайм-склейка путей сверх объявленных литералов.
