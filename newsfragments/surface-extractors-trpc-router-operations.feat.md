Извлекатель поверхностей продукта научился видеть операции **tRPC** (TypeScript, вид `api` — как
GraphQL и gRPC) — из объекта роутера, детерминированно и без исполнения (node не поднимается, типы не
проверяются, сети нет). Роутер объявляется вызовом `createTRPCRouter({ … })` / `t.router({ … })` /
`router({ … })`, а ключи верхнего уровня — процедуры: ключ, значение которого содержит вызов
`.query(` / `.mutation(` / `.subscription(`, есть операция API продукта (имя операции = ключ).
Обычное поле объекта (значение без такого вызова — метаданные/конфиг) операцией не считается.
Вложенный роутер как значение ключа (`orders: createTRPCRouter({ … })`) даёт namespace: его процедуры
получают префикс `orders.` (форма клиентского вызова tRPC `trpc.orders.getOrders`), а сам ключ
вложенного роутера операцией не становится. Разбор сужен к индикатору tRPC (`initTRPC` /
`createTRPCRouter` / `publicProcedure` / импорт из `@trpc/server`), чтобы чужой TS-объект с ключом
`query` или полем `router` в React-компоненте либо конфиге не дал ложных операций; берутся только
нединамические литеральные ключи (идентификатор или строковый литерал), вычисляемый ключ `[expr]:`
пропускается. Комментарии и строки (включая backtick) маскируются, так что текст `.query(` внутри них
и фигурные скобки строк не сбивают разбор. Как текстовый (не AST) разбор TypeScript, операции
помечаются `confidence: inferred` (видны в каталоге, но прогон не блокируют). ref =
`file:line|<namespace.operation>`. Осознанно НЕ выводятся: склейка `mergeRouters(a, b)` в рантайме;
процедуры через spread (`...otherRouter`) или из переменной/импорта, а не литеральным ключом;
middleware-цепочки как отдельные операции; глубокая вложенность роутеров, если объект собран не
литералом; code-first без явных ключей; edge-случаи backtick-интерполяции; файлы без индикатора tRPC
и `.tsx` (берётся только `.ts`).
