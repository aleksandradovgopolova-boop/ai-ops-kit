`code_review`/`architecture_review` (и прочие блокирующие ai-review гейты) больше не штампуют настоящий `pass` в рубер-штамп из-за 0 read-op судьи. claude-cli судит из диффа и ceremonial read-op детерминированно не эмитит — раньше это валило КАЖДОЕ ревью и ни один прогон не мог закрыть блокирующее ревью (полевой блокер, ii-sreda). Теперь, как и acceptance Fix C, вовлечённость определяется сверкой с ДОСТАВЛЕННЫМ файлом: кит сам знает состав правки (`git show`), и `pass` без read-op проходит, только если evidence ревьюера ссылается на файл из правки. Рубер-штампом остаётся `pass` с 0 reads И без заземлённых ссылок — страж не ослаблен.
