Product Contract, срез 3 — операции над флотом. `ai-ops products register` добавляет ТЕКУЩИЙ
репозиторий в реестр флота (upsert по id), так что `cd продукт && ai-ops products register` по
очереди накапливает все продукты в одном файле. Реестр флота — центральный операторский файл
(`$AI_OPS_PRODUCTS`), иначе `products.yaml` рядом; при записи кит помечает его managed-заголовком
(комментарии в блоке products при перезаписи не сохраняются — файл ведёт команда).

`product_registry.register(reg, path)` — upsert (created/added/updated) с немедленной обратной связью
(вердикт `product_contract.validate` сразу после записи, чтобы register не был «записал и молчит»).
`product_registry.inspect(reg, id)` — карточка одного продукта флота по id (полный контракт + вердикт;
неизвестный id честно возвращает список известных, а не выдумывает продукт). inspect пока доступен
программно и через `--json`-путь; подробную карточку из терминала даёт `ai-ops contract` в самом
репозитории продукта — модель CLI передаёт один токен задачи, поэтому inspect-по-id отдельной
командой появится с флагом позже.

Слой и достижимость прежние: модуль в `planning`, health впрыскивается сверху; интент `products`
(experimental) уже достижим. Объём поставки поднят записью (файлов не прибавилось; модуль вырос кодом).
