`ai-ops backlog merge` — approval-gated слияние дублей: вторая половина исхода
`duplicates_detected_and_merged`, построенная по решению владельца (вариант «одобряемое слияние»).
Детектор дублей (`backlog dedup`) как и прежде ПРЕДЛАГАЕТ; теперь кит может и СЛИТЬ — но **только по
явно одобренным человеком парам** (файл `--approved` с `{approved: [{duplicate, canonical}]}`), никогда
сам. GitHub не «сливает» Issue: конвенция — закрыть ДУБЛЬ с кросс-ссылкой на канонический (комментарий
+ `state=closed`, `reason=not_planned`), канонический оставить открытым; операция **обратима**
(переоткрытие).

Границы механизмом, не на словах: без `--approved` кит отказывается сливать; без `--apply` — dry-run
(что закроется, видно ДО того); канонический никогда не трогается; пустой/битый `approved`,
`duplicate==canonical`, не-int — отказ с причиной; при провале комментария дубль НЕ закрывается (нет
тихого закрытия). Пары НЕ выводятся из детектора — принцип «предлагать, не сливать» сохранён на уровне
выбора. Все мутации GitHub идут через единственный шов `GitHubClient._gh_mutate` (POST/PATCH через
`gh`); rest-путь для записи закрыт. 12 мутационных тестов (снятие fail-safe → дубль закрывается вопреки
провалу комментария → красит) + live dry-run на реальном backlog (нулевая мутация подтверждена).
