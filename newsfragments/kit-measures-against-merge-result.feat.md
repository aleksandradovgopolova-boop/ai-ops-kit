Кит теперь умеет мерить объём поставки против ИТОГА СЛИЯНИЯ, а не ветки PR — на чистом git, без
GitHub merge queue (работа `gate-measures-merge-result`). Прежде гейты объёма смотрели на ветку PR;
код, который параллельные ленты складывают в main, дрейфовал выше порога незаметно и всплывал
падением на СЛЕДУЮЩЕМ PR, а не на том, кто дрейф создал. Новый модуль `ai_ops_kit/gates/merge_preview.py`
считает ДЕРЕВО СЛИЯНИЯ base+head без коммита через `git merge-tree --write-tree` (git 2.38+),
материализует его и сравнивает объём итога с потолком `volume_bytes`. Механизм фордж-нейтрален
(работает и там, где merge queue недоступна) и fail-closed: конфликт слияния, ошибка git или старый
git не выдаются за «в пределах» — посчитать итог не смогли, значит не зелёный. На пути PR это пока
advisory-джоба CI (`merge-footprint`), не блокирующая и не в обязательных проверках, — промоутнёт
владелец отдельным решением, как это было с parallel-safety.
