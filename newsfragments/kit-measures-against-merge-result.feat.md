Кит получил фордж-нейтральный ПРИМИТИВ для измерения против ИТОГА СЛИЯНИЯ, а не ветки PR — на чистом git, без GitHub merge queue (работа `gate-measures-merge-result`). Прежде гейты объёма смотрели на ветку PR; код, который параллельные ленты складывают в main, дрейфовал выше порога незаметно и всплывал падением на СЛЕДУЮЩЕМ PR, а не на том, кто дрейф создал. Новый модуль `ai_ops_kit/gates/merge_preview.py` считает ДЕРЕВО СЛИЯНИЯ base+head без коммита через `git merge-tree --write-tree` (git 2.38+), материализует его и умеет мерить объём итога — fail-closed на конфликте/ошибке/старом git (посчитать не смогли → не зелёный). Механизм фордж-нейтрален (GitHub/GitLab/голый git) и не зависит от типа репо. Пока это именно ПРИМИТИВ: блокирующий CI-гейт «доставляемый footprint итога слияния» отложен отдельной работой, потому что доставляемое подмножество считает `installer.managed_set` (globs + is_runtime_asset + package-фильтр), а тянуть installer вверх из `gates/` нельзя — гейт будет жить в слое, который видит managed_set, и переиспользует этот примитив. Advisory-джоба, мерившая ВСЁ дерево (надмножество доставки, всегда пробивает потолок), снята как ложный сигнал.
