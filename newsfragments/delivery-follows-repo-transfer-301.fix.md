Доставка переживает перенос/переименование репозитория на GitHub. Раньше при org-transfer старый
адрес отдавал 301-редирект: `git push` его следовал, но создание PR и API-вызовы били по СТАРОМУ
слагу, распарсенному из origin-URL, — PR уходил не туда либо доставка зависала в `outcome_unknown`.
Теперь перед PR кит резолвит ТЕКУЩИЙ канонический слаг через GitHub API (`GET /repos/{owner}/{name}`
следует редиректу и отдаёт актуальный `full_name`) и ведёт по нему все последующие вызовы —
определение дефолт-ветки, проверку идемпотентности и сам POST создания PR, а также сверку
(reconciliation). Резолв — улучшение, а не новая точка отказа: если он не удался (репо не найден или
API недоступен), доставка идёт по исходному слагу ровно как раньше, слаг не выдумывается.
