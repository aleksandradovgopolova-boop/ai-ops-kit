AI Ops Kit теперь устанавливается как плагин Claude Code: репозиторий кита сам является маркетплейсом
из одного плагина (`.claude-plugin/marketplace.json` + `plugin.json`), а интерфейс владельца 4+1 —
`status` / `inbox` / `next` / `explain` / `do` (плюс `run` / `model` / `review`) — выставлен наружу
нативными слэш-командами (`/ai-ops:next` и т.п.). Команды работают через точку входа репозитория
`./ai-ops` (её создаёт установка кита); если её нет — кит не подключён к репозиторию, и команда
предлагает установку вместо выдуманного статуса. Скилл `ai-ops` в составе плагина делает сценарий
«Установи AI Ops» first-class: подключение, диагностику и первичное изучение репозитория он ведёт
сам из состава плагина и объясняет результат человеческим языком — ручной запуск установщика
владельцу больше не нужен. Плагин — тонкий адаптер: источник истины остаётся рантайм-агностичным
движком, плагин лишь рендерит его в слэш-команды.

Дополнительно объявлен консольный вход `ai-ops` (`pyproject.toml -> [project.scripts]`): после
установки пакета (`pip`/`pipx`) интенты состояния — `ai-ops status` / `inbox` / `explain` — доступны
командой в PATH. Полные продуктовые интенты (`next`, `run`, `review` и др.) читают реестры кита и
работают из его исходного дерева — из репозитория с установленным китом (`./ai-ops`) или из состава
плагина, — а не из «голого» пакета; это осознанная граница, а не пробел.
