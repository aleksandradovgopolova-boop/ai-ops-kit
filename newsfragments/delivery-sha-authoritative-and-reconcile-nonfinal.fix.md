Доставка: ложный `sha_verified: false` на успешном PR устранён в корне. После push
авторитетом стал локально запушенный commit-sha (git-факт), а не ответ GitHub API про head
PR — тот обновляется с задержкой и на пути `updated` отдавал старый sha (#399). Плюс
реконсиляция теперь перепроверяет не только доставки без receipt, но и receipt с
неподтверждённым `sha_verified` — ложный false больше не залипает навсегда и лечится сверкой
с remote, без ручного удаления файла леджера (#400).
